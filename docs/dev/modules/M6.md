## 8. 人工门验收修复轮（2026-09-05，人工 GUI 实测 3 项反馈 → 已修复）

> 人工原话：① 空校验完成 ✓；② 真实只读 Key 保存后：立即同步 → 记录「新增 0 · 未解析跳过 120」（真实原因被吞）；

### 8.1 问题 ②：逐 symbol 失败原因被并入「未解析跳过」（120 全失败）
- 根因：`fetchSafely` 把任意 `ExchangeApiException`（含密钥失效/限流/时间戳/网络等**关键级**错误）都计入 `unresolved++` 并继续打满 120 次预算——
  真实原因（如密钥权限/限流/时间戳）被掩盖，用户只看到「未解析跳过 120」。
- 修复：
  1. `SyncTally` 拆分「请求失败 fetchFailed + 首因 firstError」与「未解析跳过 unresolved」两个计数；
  2. 关键级错误（InvalidKey/SignatureInvalid/RateLimited/TimestampSkew/Network）→ **立即中止整轮**（不再打满预算触发重复限流），
     原因经 `ExchangeFailureCopy.failureMessage` 上浮到 sync_logs 与 API 管理页（`同步中止：<真实原因> · 已导入 N · 请求失败 F（首因：…）`）；
  3. 非关键级（HTTP 400 单 symbol 下架等）→ 计 fetchFailed 继续下轮。
- 回归：新增「key level fetch error aborts run」测试（限流 → FAILED + 立即中止 myTradesCalls=1 + message 含真实原因 + sync_logs 含「限流」）。

### 8.2 问题 ③：编辑等同新增（不回显 + 保存走 addAndSync）
- 根因：编辑弹窗打开即密钥留空（安全口径，不回显属预期），但 `VM.save` 无条件调 `addAndSync` → 撞别名唯一约束/重复建号。
- 修复：
  1. domain `ExchangeSyncService.updateKey(apiKeyId, input)`：别名必填；密钥均留空 = 仅更新别名（不触发网络）；均提供 = 测试请求验证后以账户 DEK 重包覆盖原行（row id 不变、AAD 稳定）；只填其一拒绝（`ERR_UPDATE_CREDS_PAIR`）；
  2. 仓库 `updateAlias` / `updateCredentials`（保留 last_sync_time）；VM `save` 按 `editingKey` 路由 add vs update；
  3. UI 编辑态 placeholder「留空 = 保持不变」+ `KEY_UPDATED_TOAST`。
- 回归：仓库「update alias keeps ciphertext / update credentials re-encrypts in place」；UI「edit modal keeps secret blank and alias-only save routes to update not add」+「edit with only one credential rejected」。

### 8.3 问题 ④：移除报数据库错误（外键约束）
- 根因：`sync_logs.api_key_id` → `api_keys(id)` 外键；已产生同步记录的密钥直接删除违反 FK（`SQLITE_CONSTRAINT_FOREIGNKEY`）。
- 修复：`ApiKeyRepository.removeWithLogs`——**同一写事务内**先删该 key 的 sync_logs 再删密钥（同步日志随 key 生命周期清除，审计口径登记 §6-7）。
- 回归：仓库「remove key with existing sync logs succeeds and clears both (M8 FK)」。
- **「移除」完整口径（三轮后人工问询固化，2026-09-07）**：
  1. 删除 api_keys 行 + 该 key 的 sync_logs（同事务，见上）；
  2. **已导入的成交（transactions）不删除**——成交属账户账本数据（无 api_key 外键归属），持仓/重放/备份不受影响；
  3. 重新添加同一 Binance 账户的新 Key 再同步时，fromId 游标从本地最大成交 id+1 继续，且成交 id 去重兜底
     （此场景即「去重跳过」计数的典型出现处，见 §8.7）——不会重复导入；
  4. 如需「连导入成交一起删」语义属新需求（C1），待人工拍板，MVP 不做（静默删账本数据有审计风险）。

### 8.7 口径澄清（2026-09-07 人工问询）：重复同步「新增 0」无「去重跳过」= 正确

- 人工问询：重复同步显示「新增 0」但没有「去重跳过 120」。
- 口径：**「去重跳过」仅在交易所返回了已同步过的成交时计数**；增量游标（fromId = 已同步最大成交 id + 1）
  让全量追平后的重复同步**根本拉不到旧行**（Binance 返回空列表），因此显示「新增 0」即幂等证明。

  （message 含「增量无新成交」+ 行数不变）。
