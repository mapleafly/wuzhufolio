### 1.4 T13.2 打包与签名公证

- **产物格式按平台配置**（`app/build.gradle.kts`）：Windows `msi`+`exe` · macOS `dmg`+`pkg` ·
  Linux `deb`+`rpm`（`AppImage` 由脚本在 app-image 上追加，ADR-006 §1 既定口径）。
- **运行期镜像模块集修正（本模块发现的发布阻断缺陷）**：Compose 插件默认建议集只有 6 个模块
  （`java.desktop` 等），**缺 `java.sql`** —— 打包版冒烟实测「启动即 `NoClassDefFoundError:
  java/sql/SQLException`」（此前 P3/T0.2 只验 uber jar 可产出，未验打包版可运行）。
  修复 = 显式 `modules(...)`（`jdeps --multi-release 17 --print-module-deps` 实测集 + `jdk.unsupported`/
  `jdk.localedata`/`jdk.charsets` 等反射与本地化补充），实测运行期镜像 19 模块、打包版 bootstrap ok。
  进一步裁剪留 P7（ADR-006 风险表既定）。
- **打包元数据**：Linux 包名 `wuzhufolio`（合法 Debian 名）/ 分类 `Office` / 维护者邮箱 /
  rpm 许可证标签 `AGPL-3.0-only`；macOS `bundleID=com.wuzhufolio.app`、分类 finance；
  Windows 固定 `upgradeUuid`（后续 MSI 走升级而非并存安装）、菜单/快捷方式/按用户安装。
- **签名/公证流水线（可执行、凭据门控）**：
  - Gradle 侧：`macOS { signing {...} notarization {...} }`，凭据经 Gradle 属性 `wuzhufolio.macos.*` 或
    环境变量 `WUZHUFOLIO_MACOS_*` 注入；**未注入 = 不签名**（`sign.set(false)`）。
  - CI 侧（`package` job）：macOS 先由 Secrets 导入证书到临时钥匙串，再由 Compose 插件完成
    `codesign` + `notarytool` + `stapler`；Windows 由 `signtool`（SHA-256 + 时间戳）对 msi/exe 事后签名；
    **所有签名步骤均以 `env.X != ''` 门控**，未配置 Secrets 时自动跳过并产出未签名产物（内部验收口径）。
  - 凭据清单与证书采购（金额/周期）落 `ADR-006 §2.1`；Linux 包 GPG 签名留 P7。
- **AppImage 追加**：新增 `scripts/package-appimage.sh`（组装 AppDir：AppRun 包装脚本 + `.desktop` +
  图标 + jpackage app-image 载荷 → appimagetool `--no-appstream` 打包；无 FUSE 环境用
  `APPIMAGE_EXTRACT_AND_RUN=1`；appimagetool 下载带重试并缓存到用户缓存目录，规避 `clean` 与网络抖动）。
- **CI 增强（`ci.yml`）**：拆 `build` / `package` 两个 job；action 升版（checkout v5 / setup-java v5 /

  只能间接判断」的登记改进项）；新增 `workflow_dispatch`（分支可手动验打包）；`package` job 在建

## 5. 规格落档（请人工走读）

1. **三平台产物由 CI 产出，本地只出本平台**：jpackage 不能交叉出包（win/mac 安装器需在对应 OS 上生成，
   Windows 还需 WiX、macOS 需 codesign/notarytool）。M13 在本机（Linux/WSL2）验证 Linux 三产物与
   「打包版可运行」；**win/mac 产物以 CI 三平台 `package` job 为产出与实证点**（`workflow_dispatch` 可手动触发）。
2. **签名/公证合规留 P7 闭环**：无证书则无法产出「签名合规」的发布产物。本轮交付**可执行流水线 + Secrets 清单 +
   证书采购口径**；未配 Secrets 时步骤自动跳过（未签名产物用于内部验收，ADR-006 §2 原口径）。P7 需先完成采购
   与实名核验（周期 1–3 周，金额见 ADR-006 §2.1）后，同一流水线产出签名/公证产物并做合规实证（`codesign -dv` /
   `spctl -a` / `signtool verify` / `notarytool log`）。**Linux 包 GPG 签名同样留 P7**。
3. **运行期镜像裁剪留 P7**：本轮优先「打包版可运行」（显式模块集 19 个，产物 ~130–145MB）；
   进一步 jlink 裁剪与字体子集化按 ADR-006 / P3 登记在 P7 做体积优化（需回归三平台运行）。
4. **权限口径**：数据/日志/backups 目录 0700；密钥文件、DB（WAL/SHM）、`.cpro`、CSV、日志与诊断导出、活动日志文件
   0600；Windows NTFS 无 POSIX 权限模型 → 静默跳过（依赖用户目录 ACL，与 M1 既有口径一致）。
5. **脱敏漏斗口径**：所有 appender 的 `%msg` 统一经 `LogRedactor`（调用点显式脱敏保留，幂等）；
   `LogRedactor` 裸值规则不含 `/`（避免长路径误伤；带 `/` 的 base64 由键值规则兜底）。
6. **CI 触发口径**：`build` job 在 push main 与 PR 跑；`package` job 仅在 push main / 手动触发跑（避免 PR 消耗
   三平台打包时间）。action 版本采用 v5 系（最新为 checkout v7 / setup-java v6 / upload-artifact v7 /
   gradle-actions v6，如需再升可在 P7 一并处理）。
7. **版本号口径**：`app/build.gradle.kts` 的 `val appVersion` 是唯一真源（jpackage packageVersion、
   `.cpro` 头部、关于页、诊断报告同源）；M13 维持 `0.1.0`，正式发布号由 P7 决定（改一处即可）。
8. **安装器元数据 = ASCII**：Windows 侧 jpackage 读取参数文件（`@args.txt`）按 UTF-8 解码，中文
   `description`/全角点 `copyright` 在 Windows 默认代码页下写盘即触发 `Input length = 1`（CI 实证）→
   安装器元数据统一 ASCII（中文表述由应用内「关于」页与 README 承载）。
9. **macOS bundle 版本与应用版本解耦**：Apple 规定 `CFBundleVersion` 首段不得为 0（jpackage 报
   `The first number in an app-version cannot be zero or negative`）→ macOS `packageVersion = "1.0.0"`、
   `packageBuildVersion = "1"`，内部 `appVersion` 仍 `0.1.0`（`.cpro` 头部/关于页）；**P7 定稿发布号后两者对齐**。
10. **WiX 口径**：Windows 安装器打包需 WiX；CI 显式 `-Pcompose.desktop.application.downloadWix=true`
    （插件自动下载 WiX 3.11 到构建目录），不依赖 runner 预装版本。

## 8. CI 迭代记录（M13 打包链路，四轮）

## 7. 勘误（C0，无独立决策档）

1. **`LogRedactor` 裸值规则误伤文件路径**：字符类含 `/` 时，长度 ≥32 的路径段被判为密钥
   （实测 `db=/tmp/wzf-appimage-smoke/wuzhufolio.db` → `db=/****.db`），削弱诊断可读性。
   修正 = 字符类去掉 `/`（密钥形态为 hex/base64url，不含 `/`；带 `/` 的 base64 由键值规则兜底），
   新增回归 `long file paths are not mistaken for bare secrets`。
2. **logback `converterClass` 属性弃用告警**（logback 1.6）：改用 `class` 属性，启动日志不再有
   `[converterClass] attribute is deprecated` 警告。
3. **`dependency-licenses.md` 失真**：dorkbox SystemTray 标注为「M11 备选」但被列入「运行时随产品分发」表 →
   更正为「未采用，未进构建」（M13 安全自查 F8）。
