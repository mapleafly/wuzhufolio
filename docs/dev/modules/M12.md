  palette，取自原型且在明暗两档各有对应；不与文本底色直接相邻，不参与文本对比度判定）。
- **读屏（NVDA/JAWS）实测**仍受 ADR-001 风险约束（Compose Desktop 读屏支持弱于 Web），
  留 P6 系统测试登记执行——见 §5-2。

### 1.5 T12.4 全量 i18n（zh/en）

- **资源层**：`ui/i18n/` 新增 10 个文案目录（Common/Shell/Market/Ledger/Auth/Settings/Backup/Exchange/
  Gallery/Portfolio）+ `I18n`（语言持有器）+ `WzFormat`（数值/时间格式化），共 ~3700 行。
- **既有 `*Copy` 门面保持调用点零改动**：全部 `const val` 改写为**动态取值属性**
  （`val X: String get() = xxxStrings.x`），成员名与签名逐一保留——这是本模块能不动 700+ 调用点
  完成全量 i18n 的关键（约定见 `CommonStrings.kt` 头注 4 条规则）。
- **语言切换即时生效**：`WuzhuTheme(language = …)` 同步持有器 + `key(language.code, precision)` 强制
  整棵子树重建（文案是普通属性而非 Compose State，这是唯一可靠的重组触发点，函数头注已写明）。
- **语言入口**：设置 → 通用 → 「界面语言」（中文 / English，语言名用本语言书写），
  与主题/盈亏配色同路（`ShellViewModel` → `settings` 全局行 **`locale`**），持久化并在下次启动生效。
  对应 C1 决策档 **D25**（含影响面扫描与下游回写清单）。
- **精度消费**：`WzFormat.precision`（8/2/2 与 2/2/2 两档）由设置驱动，主题按精度档重组；
  **微小价格自适应**（有效数字不足时自动增加有效数字位，避免显示为 0，PRD「数据精度」）。
- **小额阈值消费**：仪表盘环形图「其他」归并（阈值 0 = 不启用）。
- **多法币/时间**：金额前缀随基础法币（USD → `$`，其余 ISO 前缀）；时间**时区恒为系统本地**、
  **格式随语言**（zh `2026-09-10 15:24` / en `Sep 10, 2026 15:24`）。
- **守护测试**：`I18nCatalogTest` 三查——双档非空、en 档零 CJK、**`ui/src/main` 除 i18n 目录外
  不得再出现中文字符串字面量**（注释先剥离；KDoc 按项目约定仍为中文）。此后新增页面若漏抽文案，
  测试直接红灯。

### 1.7 勘误（C0，无独立决策档）

- **`CoinResolutionException` 增类型化 `kind`**：UI 原以 `reason.contains("歧义")` 判分支——
  界面逻辑绑在数据层中文正文上，且 en 档无法独立成句。新增 `CoinResolutionKind`
  （AMBIGUOUS/NOT_FOUND/FIAT_UNSUPPORTED/CANDIDATE_GONE/UNKNOWN，默认 UNKNOWN 兼容既有构造），
  data 层 9 处抛出点带上类型；zh 档文案**逐字不变**（仍用 `reason` 正文，含候选数），
  en 档按 `kind` 成句。属实现偏差纠正，不改产品语义 → C0。
- **`MarketCopy.WATCH_EMPTY` 文案订正**：原为「自选为空 · 用上方搜索添加币种」，
  与 interaction.md §2.7 及原型「暂无自选，搜索添加币种」不一致 → 以文档/原型为准订正（C0）。
- **detekt 配置补齐测试目录排除**：为 i18n 目录加 `MaxLineLength`/`TooManyFunctions` 例外时，
  显式 `excludes` 会**覆盖** detekt 默认的 `**/test/**` 排除，导致测试类被误判（每用例一函数
  ≥11 即触发）。已在配置中显式带回默认测试排除并加注说明。

## 5. 规格落档（待人工认可）

1. **币种详情入口形态 = 页面（非弹窗）**：P1 原型把币种详情实现为弹窗（`openCoin`），而 ia.md §2.6
   定义为页面且 T12.1 明确「聚合页——…币种详情（三重筛选/校准入口）」。本模块按 **ia.md** 实现为页面
   （弹窗无法并排承载交易列表 + 校准历史），并保留「返回资产列表」入口；差异属**按设计基准文档取舍**，
   登记于此待人工认可。

2. **i18n 的资源组织**：采用「模块级接口 + zh/en 两实现 + 全局持有器 + 动态取值门面」，
   **不做 Compose CompositionLocal 参数化**（文案消费点有一半在 ViewModel/纯函数里，拿不到
   CompositionLocal）；语言切换靠主题层 `key()` 强制重组。取舍与理由见 `I18n.kt` / `Theme.kt` 头注。

3. **`WzFormat` 为全局精度持有器**（与语言同构）：精度档非 Compose State，同样依赖主题层重组键。
   代价 = 格式化必须经 `WzFormat`（既有页面里零散的 `toPlainString()` 保留原样，未强制改写，避免动
   已通过模块的展示口径）。

4. **状态栏「同步状态」合并了最近一次的同步结果与同步中指示**（同一格），未拆两格：
   interaction.md §1.1 只要求「同步中指示 + 同步失败提示」，合并后信息更紧凑；如需拆分请人工指示。

5. **语言设置复用既有 `locale` 键**：M002 迁移在 P3 期已种下 `locale=zh-CN` 但一直无消费方；
   M12 直接以它为界面语言键（值 `zh-CN`/`en-US`，解析兼容 `zh`/`en`），**不新增 `ui.language`**，
   避免同一语义两个键（决策档 D25 §5）。

6. **`shellStatus` 轮询间隔 30s**：状态栏为弱实时指示，避免高频查库；手动刷新/手动同步/同步结束
   会立即触发重算（不等轮询）。
