## 1. 本次改了什么（实现摘要）

### T9.1 CproCodec（domain/backup，纯计算无 IO）
- **文件布局 v1**（ADR-005 §1「明文头部 + 分隔符 + 加密载荷」）：`headerJson(UTF-8 单行) + '\n' +
  nonce(12B) + ciphertext‖tag`；头部为明文 JSON（恢复前仅解析此段展示摘要，PRD 5.2-5）；
  **AAD = 头部完整字节**（防头部替换/篡改——篡改头部即 GCM 认证失败，单测覆盖）。
- **加密语义**（ADR-005 §2）：备份密钥 = Argon2id(备份密码, 随机 16B salt, 参数入头部 kdf)，
  AES-256-GCM（96-bit 随机 nonce）；kdf 参数复用 [KdfParams] 契约（KDoc「M9 .cpro 内同样承载」口径），
  导出固定 KdfParams.DEFAULT（64MiB/t3/p1）；派生密钥用后即擦（Zeroization）。
- **头部字段**（与 ADR-005 §1 逐字对齐，kotlinx @SerialName snake_case）：format_version /
  app_version / exported_at / counts{7 表} / range{min_time,max_time} / kdf{alg,salt,m,t,p} / cipher。
- **载荷**：meta{exported_at, base_fiat} + records{7 表 DTO}；金额十进制原串透传（勘误链同
  M006/M009/M010/M011）；时间 UTC ISO 文本；**币种引用统一 cg_id**（CoinGecko 稳定 id，跨设备键；
  本地 coins.id 自增主键不可跨库移植——导入经本地目录解析回行主键）。
- **内容范围**（ADR-005 §3）：transactions / capital_flows / reconciliation_records / fee_rules /
  api_keys（凭证先解密入载荷，PRD 5.2-9）/ 账户级 settings / 本账户涉及币种快照（交易两腿+资金/
  校准币种，全部法币维度）；**不含 accounts 任何字段、全局设置、coins/exchange_coin_map；
  行情 Key（CG/CMC）为设备级秘密（ADR-002 §2.1 方案甲）不随备份导出**。
- **错误语义**（flows §7）：CproDecodeException 三态——MALFORMED_FILE（不是 .cpro/截断/JSON 损坏）/
  UNSUPPORTED_FORMAT（format_version 更高、cipher/KDF 不识别 → 提示升级应用）/ 
  WRONG_PASSWORD_OR_CORRUPTED（GCM 认证失败——**PRD 有意不区分密码错误与文件损坏**，
  避免向攻击者泄露「密码正确但文件坏」的旁路信息）。format_version 导入只接受 ≤1。
- **导出保真**（BackupLedgerReadStore 全列直读，不动 M6/M7/M8 仓库）：交易/资金/校准行回填
  uuid / created_at / source / price_status（去重键与审计口径跨设备稳定）；api_keys 凭证解密
  （FieldCipher AAD 与 M6 同口径）；原子写文件（临时文件 + rename，进程中断不留半文件）。

### T9.2 增量合并 / 全量覆盖（BackupMergePlanner 纯规则 + BackupRestoreStore 应用器）
- **增量合并去重**（PRD 5.2-6）：业务记录 uuid → 交易所+订单号 →（v1 载荷 uuid 非空约束下
  「无标识记录」**无输入面**，模糊级去重无触发路径——留档见 §5-2）；api_keys 按 (exchange_name+别名)
  命中跳过（不覆盖本地）；fee_rules 按 (交易所) **备份优先覆盖**（upsert）；账户级 settings 按 key
  **备份优先覆盖**；price_snapshots 按 币种+法币+小时桶 幂等合并——**本地已有同桶行保留本地**
  （不回退本地较新快照，幂等性不受影响：同文件重导结果不变）。
- **全量覆盖**（ADR-005 §4）：单写事务内先清当前账户业务表（FK 序：sync_logs → api_keys →
  fee_rules → capital_flows → reconciliation_records → transactions → 账户级 settings）再全量插入；
  **全局公共表（coins/exchange_coin_map/price_snapshots）与全局设置不动**；清空与导入同事务，
  任一步失败整体回滚。
- **币种可解析门**：载荷 cg_id 先经本地目录解析（resolvableCoinIds）；引用缺失币种的行跳过并计数
  （missingCoinIds 明细随摘要返回——用户刷新币种目录后可重导，不破坏其余数据导入）。
- **api_keys 重加密**（PRD 5.2-9）：先插空列拿行 id → 以**目标账户 DEK** FieldCipher 加密回写
  （AAD = account_id|api_key_id|column）——跨设备/跨账户恢复只依赖备份密码（单测：恢复后可解回
  原明文）。
- **应用器事务边界**：applyWithinTx / deleteAccountBusinessRowsWithinTx 必须在单个 DbGate.write
  回调内执行（直接表访问，不再入闸门——写 Mutex 不可重入）；规划（读）→ 应用（单写事务）两段。

### T9.3 恢复流程 + CSV 明文导出（DefaultBackupService 编排）
- **流程**（flows §6 全路径）：previewBackup（仅解析明文头部，无需密码）→ prepareRestore（密码验证
  + 解密 + 合并规划预览[新增/跳过/缺失币种]，不落库）→ restoreBackup（模式选择 → 单写事务应用 →
  恢复后**全量重放（LENIENT）**出「持仓异常」币种清单[导入路径例外，PRD 全局说明]）。
  「导入完成触发全量重放重算并刷新」= 指标/持仓均读时重算（data-model §3 派生口径），恢复后页面
  reload 即得新结果——无缓存表需要失效。
- **全量覆盖临时备份**（PRD 5.2-6）：覆盖前自动将当前账户数据导出为
  `~/.wuzhufolio/backups/pre-restore-<UTC 时间>.cpro`，**以用户刚输入的备份密码加密**（用户已持有
  该密码、可直接恢复），路径随恢复摘要返回（不写入 backup.last_at 元数据——不冒充用户主动备份）。
- **CSV 明文导出**（PRD §9.9 数据主权）：交易记录（与导入模板同列 + source/uuid，可直接回导）/
  资金流水（增资/撤资/校准混合，时间升序）/ 持仓汇总（重放期末持仓：数量/平均成本/成本/已实现/
  估算/异常标记）；**不含任何 API 密钥**（单测断言凭证明文不出现在三类 CSV）；RFC 4180 转义
  （逗号/引号/换行）；UTF-8 原子写。
- **元数据**：账户级 settings 记录 backup.last_at / restore.last_at（数据管理区「上次备份/恢复」展示）。

## 5. 规格落档（待人工走读/认可）

1. **「导出默认填当前账户密码」不可实现（PRD 5.2-3 偏差）**：密码永不落盘/不留存（PRD 5.1-4、
   ADR-002），会话仅持 DEK，无密码可回填。落地：备份密码由用户设置（弹窗内说明该口径 + 独立密码
   建议），恢复语义不受影响（任何设备只依赖备份密码）。如需严格回填，须会话内存驻留账户密码
   （与擦除纪律冲突）——不建议，待人工裁决。
2. **模糊级去重无触发路径**：PRD 5.2-6 第三级「无标识记录模糊匹配并逐条确认」——v1 载荷由本应用
   导出，transactions/capital_flows/reconciliation_records 的 uuid 均为 NOT NULL（M009/M011/M012），
   「无标识记录」不存在；模糊匹配逐条确认 UI 不做假交互。若未来支持外部 .cpro（移动端互换）且
   出现无 uuid 行，随格式版本演进补第 2 版解析分支（ADR-005 §5）。
3. **快照幂等 = 本地优先**：同 (币种,法币,小时桶) 已有行保留本地（不回退本地较新快照）；PRD 仅要求
   「幂等合并」，本口径同时满足幂等与数据新鲜度。同库跨账户恢复时快照天然命中跳过（全局表已含

5. **临时备份密码 = 用户刚输入的备份密码**（PRD 要求「自动生成临时备份」未规定加密方式）：复用

## 7. 人工走查反馈修复轮（2026-09-10，2 项反馈 + 1 项裁决，全部闭环）

1. **保存文件无 .cpro 后缀**（人工反馈①：只输文件名生成的文件无后缀，恢复可正常读取）——
   根因 = 原生 FileDialog 不强制扩展名；修复 = `BackupFileNames.withExtension`（已带后缀原样返回、
   否则补全）接入保存路径（备份 `.cpro` / CSV `.csv` 一并覆盖）；**恢复侧维持不校验扩展名**
   （.cpro 由明文头部识别，格式真源 = 头部 JSON，任何文件名形态可导入——口径落 BackupFileNames KDoc）。
   回归测试 4 断言（含大小写幂等）。
2. **同账户增量回导结果页出现「持仓异常：fdusd,one,pepe,usdc」**（人工反馈②）——根因 = 这些币种的
   负持仓是**账户既存状态**（历史 API 同步/导入形成的账本形态，恢复后重放如实报告），并非本次导入
   造成；原实现把恢复后全部异常币种记入摘要，同账户回导场景易误读。修复 = RestoreSummary 拆分
   **anomalousCoins（本次导入新产生 = 恢复后重放异常集 − 恢复前异常集）**与
   **preExistingAnomalousCoins（既存 = 交集，灰字披露 + 说明非本次导入造成）**；同账户回导新产生
   恒为空。回归测试：同账户 MERGE（既存异常 → new 空 / preExisting 命中）+ UI 结果页两行渲染。
   *补充说明：fdusd/one/pepe/usdc 的既存负持仓属账本事实（如历史同步的卖出先于本地买入记录），
   消除路径 = 补录增资或持仓校准（PRD「持仓异常」既有口径，M7/M8 已支持）；P6 系统测试将把
   「既存异常币种」列入账户健康检查项。*
