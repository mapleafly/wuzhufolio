## 1. 本次改了什么（实现摘要）

### T5.1 MarketDataClient（CG 主源 / CMC 兜底，真实 API）
- **domain/market 契约**：`MarketDataClient`（fetchCurrent/fetchCmcCurrent/fetchHistory/fetchDirectory/fetchCmcMap/fetchMarketRanking，
  非所属平台端点默认抛 UnsupportedOperationException——CMC 无免费历史，历史回填不做兜底）+ 模型（MarketQuote/CmcQuote/MarketCandle/
  CmcMapCoin/MarketRank/PriceSource）+ 类型化错误 `MarketRefreshError`（Network/RateLimited(keylessHint)/InvalidKey/QuotaExceeded/
  Http/Untracked）与 `MarketApiException`。
- **CoingeckoMarketClient / CmcMarketClient（data/market）**：Ktor client + **OkHttp 引擎**（ProxySelector，ADR-001/003）；
  端点/头/参数逐项对齐 ADR-003 与 api-contracts §1（CG /simple/price、/coins/list include_platform、/market_chart/range、
  /coins/markets；CMC /quotes/latest ≤100/批、/cryptocurrency/map 分页）；个人 Key 仅每次请求入参（无 Key = 公共 API）；
  载荷以 JsonElement 手工导航解析（不建逐端点 DTO）；错误映射 429/401/402/404/网络。
- **编排（DefaultMarketRefreshService）**：两级模式——CG 分批主源 → 失败/缺席 → 已配 CMC Key 且有 cmc_id 时兜底（
  落快照 source=COINMARKETCAP）；主源成功自动回落（无持久状态）；全部失败 → error 置位（保持上次价格 + 时间戳语义）；
  **单飞（Mutex）**；目录每日一次维护（/coins/list → refreshDirectory + /coins/markets 4×250 → 市值榜缓存 +
  CMC map 分页 → **CmcIdAligner**（symbol→name 消歧）→ refreshCmcIds，M3 遗留 3/4 落地）；币不在目录 → untracked 不入 IO。

### T5.2 价格快照（M006 表 + 仓库 + 降采样）
- **M006 price_snapshots（schema 5→6，全局公共表）**：coin_id FK + fiat + price + price_source + recorded_at；

  recorded_at 经 `SqlUtc` 固定三位毫秒 UTC 文本（`Instant.toString()` 有/无纳秒形态混存会导致文本序错位——测试有专例）。
- **PriceSnapshotRepository**：同小时末条 upsert（单写队列 + 先查后写，评审 N1 口径）、批量 upsert、latest/atBucket/
  nearestBefore（M7 折算「最近可得价」估算用）/range、`compactPreservingDaily`（90 天界前仅留整点日线行，幂等）。
- domain `PriceResolution` 纯规则：小时桶/整点行/90 天界/24h 配对时刻（单测覆盖边界）。

## 5. 规格落档（裁决与勘误登记，后续模块引用）

1. **price_snapshots.price 存 TEXT（勘误，待人工认可后回写 data-model §2.11）**：SQLite NUMERIC 对非整小数落 REAL
   （IEEE 双精度，15–17 位有效数字），账本级价格精度（8 位小数 + 24h/折算推导）不允许浮点截断——M006 落 TEXT
   （十进制字符串，BigDecimal 精确读写）。迁移注记与 data-model 勘误登记同源。
2. **recorded_at 规范化（SqlUtc）**：本表时间统一「yyyy-MM-dd'T'HH:mm:ss.SSS'Z'」三位毫秒固定宽度文本——
   `Instant.toString()` 纳秒形态有无混存会让文本比较错序（"…00.5Z" < "…00Z"），SQL 范围/排序会错；测试专例守护。
   后续建时间序表的模块（M7/M8）建议复用本口径（登记 M7 注意项）。
3. **快照读取口径**：90 天内解析 = 目标小时桶行（同小时去重保证至多一条）；24h 配对 = t−24h 所在桶行，缺桶 = 该币计入
   「缺 24h 前价」（覆盖 N/M），**回填后消除**；更早 = 目标日整点行（日线）。「最近可得价」估算（nearestBefore）供 M7
   事件构造折算解析（PENDING 语义），不作为 24h 配对兜底。
4. **CMC map 分页与对齐**：/cryptocurrency/map 按 limit=5000 分页（≤4 页截断）；对齐 = symbol 精确 → 同名按 name 唯一；
   仍歧义/缺失跳过（cmc_id 空缺 = 该币无兜底价，不影响主源）。cmc_id/市值榜每日随目录刷新（M3 遗留 3/4 关闭）。
5. **调度宿主拆分（T5.4 验收面）**：窗口可见性/托盘降频的**循环宿主接入归 M11 桌面集成**（托盘与窗口生命周期句柄），
   M12 状态栏展示「数据源/上次价格/额度提示」；M5 交付：全部节奏/降档/退避纯规则 + 额度账本 + 单次刷新编排（单飞/目录 TTL/
   429 退避重试）——「调度时序」验收由规则单测 + 编排集成实证。
6. **UI 偏差登记（对照原型，均按建议简化）**：① 设置行 Key 状态按钮不展示尾号（安全优先——明文/部分明文不驻留 UI，
   原型为演示数据）；② 行情刷新频率用分段按钮（●/○ 标记）暂代原型下拉（M10 设置页统一组件化时换下拉）；③ 注册链接以
   平台官方文档页为准（原型为演示文本）；④ 行情分组现置于独立设置占位宿主，标注「M10 将并入完整设置页」。
7. **额度计数口径**：仅配置个人 CG Key 后计数（无 Key 模式无月度专属额度）；按「请求发起」计数（失败/重试也计）；
   CMC map 每页计数一次 DIRECTORY；跨月自动归零。80% 降档由 cadence 消费（quotaPercentUsed 暴露给 UI 提示）。
8. **缺目录币与缺席币**：币不在 coins 目录 → 不发起请求直接 untracked（无行情）；主源返回子集（未收录）→ 兜底尝试 →
   仍无 → untracked；「无行情」不计入净值/24h 的口径沿用（引擎/计算器已有语义）。

### 8.1 问题 1：弹窗输入框键盘不可用（M2 同根）→ 修复 + 共性约束固化

- 根因：`WzModal` 实现用 `Popup(focusable=false)`——桌面端 Popup（无论 focusable）无法可靠接收键盘输入
  （M2 已有同根记录并造 InPlaceModal 绕行；本模块 Key 弹窗复现）。
- 修复：**`WzModal` 统一改为就地叠加层**（同窗口 Box 覆盖：遮罩/卡片/Esc/关闭按钮语义不变，无 Popup）——
  与主场景同一焦点体系，键盘/IME 正常；auth 模块 InPlaceModal 保留（同一模式，待 M10 收编）。
- 自动聚焦：`WzModal` 新增 `initialFocusRequester` 参数（含输入框弹窗打开即聚焦首输入框，无需先点按）；
  `WzTextField` 新增 `fieldFocusRequester` 参数接入内部输入控件；KeyModal 已按示例接线。
- **共性约束固化（人工指令）**：`AGENTS.md §7.3 GUI 共性约束`（弹窗禁 Popup/就地叠加、含输入框弹窗聚焦
  首输入框、模块验收必须含 UI 测试 performTextInput+assertIsFocused 与人工键盘录入复验、修复模式登记）；
  已决策事项 20 落档。

### 8.2 问题 2/3：刷新误报「暂无行情」+ 数据源指示不随 Key 配置更新

- 根因一（误报）：首次刷新时目录维护失败（真实环境限流/网络）→ coins 目录为空 → 币集不可解析走了
  untracked 路径且错误被吞 → UI 只能报「tether 暂无行情数据」；实为「刷新链路未触达」（无 IO）。
- 根因二（显示）：数据源指示以「上次结果的 cgConfigured」为基准，保存 Key 后（尚无刷新）仍按旧结果显示
  无 Key 公共 API。
- 修复：
  1. 编排把**目录失败原因上浮**：`refresh()` 捕获目录维护异常（类型化或兜底 Network），币集不可解析时
     `result.error` 置位（此前为 null）——UI 将显示限流/网络/Key 失效真实文案而非「暂无行情」；
     目录成功但币仍不在目录（真无行情）保持 untracked 语义。
  2. 数据源指示改以**当前 Key 配置**为基准（保存即生效展示），未刷新注「（尚无刷新）」、已刷新失败注
     「（尚无成功刷新）」；刷新成功后注空。
  3. 补充回归：编排测试「目录失败 + 币集不可解析 → 上浮 RateLimited(keylessHint)」；UI 测试
     「弹窗打开即聚焦输入框（assertIsFocused）」+「已配置 Key 未刷新 → 专属额度（尚无刷新）」。
- 提示：真实免费 Demo Key 注册后可能有分钟级激活延迟（其间 401 属预期，激活后重试即成功）。

### 8.4 第二轮修复（2026-09-04，人工复验反馈：「网络不可达 CoinGecko」误报；真实 Key 已提供并实证）

- 现象：未配置与配置真实 Demo Key 后点「立即刷新行情」均 toast「网络不可达 CoinGecko，已保持上次价格」；
  真实 Key 在本机 curl 直连 200（bitcoin/tether 报价正常）→ 应用内错误非网络问题。
- **根因（日志实证）**：`directory refresh failed: Value can't be stored to database column because exceeds length
  (38 > 32)`——CG /coins/list 存在 symbol 超 32 字符的币；Exposed 的 `varchar(32)` 有**客户端长度校验**（SQLite
  本身不限长），整批 2 万行目录写库单事务回滚 → 目录为空 → 币集不可解析；且 `refresh()` 泛化 catch 把该本地
  DB 异常误标为 `Network`（第二轮 ①：错误分类不实）。
- 修复：
  1. `CoinsTable.symbol` 由 `varchar(32)` 改 `text`（对齐 M004 DDL 的 TEXT 列，消除客户端长度校验）；
  2. 目录维护异常分类修正：`MarketApiException`（平台/网络/限流）透传 kind；其余本地/DB 异常归
     `MarketRefreshError.Internal`（detail 仅入日志，UI 文案「行情目录初始化失败，请稍后重试（详情见日志）」），
     不再误报「网络不可达」；
  3. 回归：目录超长 symbol 入库测试 + 内部异常分类测试。
- **真实端到端实证（本机，用户真实 Demo Key，一次性冒烟后已删）**：真实 /coins/list（>10,000 行）落库、
  真实 current 报价（bitcoin/tether 均命中）、经 DefaultMarketRefreshService 全链路 refresh error=null 且
  快照落库（snapshots.count ≥ 2）——目录/落库/报价/快照链路真实网络全通。
- 影响：258 测试 0 失败（domain 149/data 85/ui 24）+ detekt 0 + 警告 0。
