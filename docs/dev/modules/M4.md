## 1. 本次改了什么（实现摘要）

> M4 = 纯领域模块（domain/engine，无 IO 可单测）；不建表、不动 UI/应用/数据层。引擎数值基准 = **黄金用例 1–9、12 全部通过**（里程碑门槛，task-breakdown §4）。

### T4.1 ReplayEngine（三类事件全量重放 + 校验）
- **事件模型**（LedgerModels.kt）：`LedgerEvent`（id/at/seq/estimated）三态——`TradeEvent`（base/quote/side/price/quantity/fee/feeCoin + **legFiat/feeFiat** 解析折算值 + source）、`FundEvent`（DEPOSIT/WITHDRAWAL + fiatValue=base_amount）、`AnchorEvent`（锚点：exchangeQuantity/delta/deltaFiat）；结果模型 `CoinHolding`（数量/成本/均价/已实现/来源/估算/负边界标记）、`ReplayOutcome`（累计增资/撤资/已实现/违例清单）、`MutationVerdict`。
- **重放**：按 (时间, seq) 稳定升序逐事件应用（同刻同 seq 以输入序决胜）；买入/卖出按共享规范 §2 成本公式联动 base/quote/手续费币三侧；卖出逐笔累计已实现盈亏；校准锚点**强制对齐**持仓（校准前历史记录编辑/删除不回滚校准效果）。
- **校验两策略**（PRD「重放校验规则」）：STRICT（手动路径：任一币种任一时刻持仓 < 0 即抛 `NegativePositionException`，携带币/事件/短缺额）；LENIENT（CSV/API/恢复导入：记录违例 + 持仓标记异常 `anomalous`）。
- **`validateMutation`**（手动新增/编辑/删除专用，两遍宽松重放比对负边界位点）：仅拦截**本操作新制造**的负持仓边界——既有导入负边界不阻塞后续补录增资等修复（黄金用例 6 语义），同一位点既存负值放行（宽松异常位点的编辑，宽松口径，见 §5-5）。
- 成本/均价除法统一 12 位 HALF_UP（LedgerMath.COST_SCALE）；数量移出按比例移出成本（均价不变）；宽松负区段不推导已实现盈亏。

### T4.2 PortfolioCalculator（净值/现金/本金/收益/ROI/已实现）
- `compute(ReplayOutcome, 现价表)`：净值（缺价币不计、「无行情」语义）、可用现金（稳定币白名单持仓市值，默认 USDT/USDC/DAI/TUSD 四个 cg id，可注入）、投入本金（净）、累计增资/撤资、总收益与 ROI（**累计增资 = 0 → 双 null 供 UI 显 "--"**，故事 6.4）、已实现盈亏合计、未实现盈亏、币种级明细（市值/浮盈金额与百分比/异常/估算）。
- 恒等式「总收益 = 净值 + 累计撤资 − 累计增资」由引擎累加量直接成立；黄金用例 8 以**校准前后总收益不变**实证「校准不制造凭空盈亏」。

### T4.3 FeeCalculator（费率优先级 + 三币种基数）
- `FeeRule`（exchange 空 = 全局，买卖百分比）→ `FeeRateResolver`：**交易所 > 全局**优先级、匹配大小写不敏感、无规则 null（自动计算不可用）。
- `FeeCalculator.feeFor`：三态基数（quote = 费率×总价；base = 费率×数量；**第三币种 = 总价基数按记录时行情价折算为该币种数量**，`ConversionPx` 提供折算价）；必需价缺失返回 null（调用层转 PENDING/不可计算提示）。
- 金额公式与买卖方向无关（方向差异只体现于所选费率）；数值与引擎成本口径闭环（feeFiat = feeQty×px(fee) 直接进事件）。

### T4.4 ReconciliationService（单一来源门 + 校准差额规划）
- `classifySources`：仅统计**交易事件**来源（Manual/CSV/Exchange），NoRecords / **SingleExchange（可校准）** / Multi（多来源 → 入口隐藏并提示，PRD 故事 4.1-5）。
- `plan`：delta = 交易所余额 − 本地持仓；deltaFiat = |delta|×校准时市价；方向分派（正→系统增资、负→系统撤资）；delta≠0 且市价不可得 → `CalibrationPriceUnavailableException`（执行前提，PRD 全局说明）。
- 规划产物可直接构造 AnchorEvent 参与重放；差额账务恒等式数值实证见黄金用例 8 + 本模块测试（正负差额校准前后总收益均不变）。

## 5. 规格落档（裁决与勘误登记，后续模块引用）

1. **引擎币键 = CoinGecko id（cg_id）**：PRD 内部唯一标识；DB 记录冻结的是 coins 行 FK id（data-model §2.5–2.7），**事件构造层（M7/M8）负责 FK → cg_id 解析**（读侧本就 join 目录展示 pair/名称，无额外成本；备份恢复跨实例引用安全）。
2. **记账单位 = 基础法币；折算值随事件传入（引擎无价格 IO）**：legFiat/feeFiat/fiatValue/deltaFiat 由上层「记录时行情价解析层」（快照 → 行情 API → 最近可得估算，PRD「折算价格解析」）构造；引擎纯确定性重放——黄金用例 9 的「回填重算」= 上层以回填价重建事件后重放，引擎侧保证标记清除与数值一致；估算态经事件 `estimated` 传播至币种与结果级（「估算中」UI 标注在 M12）。
3. **第三币种手续费「联动扣减持仓」裁决（勘误）**：PRD 故事 7.1 验收文案「手续费币种为第三币种时仅影响持仓成本计算，不联动该币种持仓（MVP 简化）」与 **黄金用例 5「BNB 持仓联动扣减」冲突**——按验收基准（黄金用例）裁决为**联动扣减**（交易所真实语义：BNB 抵扣从 BNB 余额扣费）；故事正文旧口径待需求基线下次修订时同步（登记）。
4. **base 手续费方向口径（字面公式）**：买入「实际到账数量减少」→ 到账 = 数量 − 手续费、成本 = 总价 + 折算手续费；卖出「从转出数量中扣除」→ 持仓 −= 数量（含费）、净收入 = 总价 − 折算手续费、已实现 = 净收入 − 数量×当时均价（与 quote 手续费公式同构）。
5. **负持仓校验相对语义**：手动操作校验 =「操作**新制造**负边界才拦截」（validateMutation 两遍比对）；宽松导入既存负边界不阻塞无关操作与补录增资（黄金 6）；同一位点既存负值编辑（如把导入负卖单改得更大）放行——宽松口径登记，M8 真实 UX 走查如暴露误导（用户在异常币上编辑后仍需校准修复）再收紧为同点比较短缺额。
6. **单一数据来源判定仅统计交易事件**：手动增资/撤资与校准锚点不计入（校准对照交易所余额，为交易所内未同步到账转入补录增资属常态路径——否则该功能几乎不可用）；多来源提示文案（「该币种存在多来源记录…」）映射落 M8。
7. **锚点成本边界口径**：重放到锚点时刻将持仓强制对齐交易所余额；差额账务（增/撤资方向与 deltaFiat）按记录值固定——校准前记录被编辑造成 q0 与记录时 local_quantity 显著背离时，成本调整仍按记录的 delta 语义执行（可能产生偏置均价），由「锚点前编辑不回滚校准效果」语义承载（黄金 8 实测路径覆盖）。
8. **宽松负区段不推导已实现盈亏**：无成本基数的卖出（异常区段）不累计已实现，由 anomalous/负边界标记承载；修复后从新基点继续。
9. **排序契约**：引擎按 (at, seq) 稳定升序；同刻同 seq 以输入序决胜——调用方须保证输入序确定（建议按 uuid/行 id 排）。
10. **数值精度约定**：除法统一 12 位 HALF_UP（LedgerMath.COST_SCALE）；加减乘全精度；展示舍入（市值/盈亏 2 位等）属 UI 层。
11. **边界登记（非 M4 面）**：黄金用例 11（24h 部分缺价口径）按 T5.3 归 M5；黄金用例 10（备份合并幂等）归 M9。
