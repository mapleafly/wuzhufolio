## 1. 本次改了什么（实现摘要）

### T11.3 系统代理（检测 → 请求经代理 → 状态栏指示）

- **domain/proxy/SystemProxy.kt**：`ProxyKind`/`ProxyEndpoint`（仅 host:port，**不含凭据**）、
  `ProxyMode`（DIRECT/SYSTEM）、`ProxyStatus`（`indicator` = interaction.md §1.1 逐字文案
  「代理：系统代理」/「直连」＋ `tooltip` 悬停提示）、`ProxyEnvironment`（环境变量解析纯规则）。
- **data/proxy/SystemProxyDetector.kt**：
  - `JdkSystemProxy.enable()` —— 置 `java.net.useSystemProxies=true`。**这是 PRD §7.2-6.2
    「自动检测并使用系统代理」在 JVM 上真正生效的前提**：JDK 的 `sun.net.spi.DefaultProxySelector`
    仅在该属性为 true 时才读操作系统代理（Windows Internet 选项注册表 / macOS SystemConfiguration /
    Linux GNOME gsettings），否则只认 `http.proxyHost` 一类 JVM 属性（本应用不使用）。该属性在
    `DefaultProxySelector` **类初始化时读取一次**，故调用点 = `Main.main` 首行，
    并由 `app/build.gradle.kts` 的 `jvmArgs` 为打包版兜底。
  - `SystemProxyDetector`：JDK 系统代理**优先**（用户真正在系统设置里配的），环境变量
    （`https_proxy`/`all_proxy`/`http_proxy`，大小写两式）**兜底**——后者覆盖 Linux 命令行/容器惯例，
    即 M10 走查答复中的「Linux 环境变量或桌面设置」。不触网（`select()` 只解析本机配置）。
  - `ToggleableProxySelector`：开关感知 selector，**每次请求读当前开关**——开则委派系统 selector、
    关则一律 DIRECT。两个 HTTP 客户端共用同一实例（PRD「所有对外请求均经代理」由共用保证，
    不各自判定）。
  - `ProxyRuntime`：开关易变副本（网络线程不查库）+ 检测状态 `StateFlow`（状态栏数据源）。
- **两个 HTTP 客户端接线**：`newOkHttpMarketClient(proxySelector)` /
  `newOkHttpExchangeClient(proxySelector)` —— 经 Ktor `engine { config { proxySelector(...) } }`
  注入（Ktor 3.5 `OkHttpConfig.config`），不破坏既有超时/UA 配置；参数可空（既有测试不受影响）。
- **状态栏**：`WzStatusBar(proxyStatus = ...)` 由布尔位升级为领域状态，文字指示 + 悬停提示；
  `MainShell`/`AuthGate`/`MainWindowContent` 逐层透传（默认值保持既有测试可编译）。
- **开关即时生效**：`GeneralSettingsViewModel.setProxyEnabled` 落盘后回调
  `onProxyEnabledChange` → `ProxyRuntime.setEnabled`，**无需重启**；调度 tick 亦会复检（用户可能在
  应用运行期间改动系统代理）。

### 调度循环宿主（M11 · M5 §5-5 + M10 §5-5 遗留闭环 · PRD §7.2 模块 9.2）

- **domain/schedule/BackgroundSchedule.kt**：`ScheduleJitter`（±20% 抖动，sample 注入保持纯函数）、
  `BackupReminder`（30 天规则 + 基线口径）、`LogRotationCadence`（运行期轮转 6 小时复查）。
- **data/schedule/BackgroundScheduler.kt**：三条循环 + 一个唤醒通道：
  1. **行情刷新**：间隔 = `RefreshCadence`（窗口可见按 5/15/30；托盘驻留按 API 同步间隔降频；
     额度 80% 自动降一档）+ 抖动；
  2. **交易同步**：间隔 = API 同步间隔（15/30/60），前台后台一致（PRD 9.2）；
  3. **运行期日志轮转**：6 小时（**M10 §5-5「运行中实时轮转未做」遗留闭环**），同 tick 复查备份提醒；
  4. **唤醒通道**：窗口从托盘恢复可见 → **立即刷新一次行情**（PRD 9.2）；
     429 退避窗口内忽略唤醒（`RateBackoff`，避免恢复可见即撞限流）。
- **窄接口 `SchedulerSources`**（8 项事实）+ `DefaultSchedulerSources` 生产适配器：
  宿主不依赖两个用例服务的完整面（22 个方法），测试用单个假实现即可覆盖全部循环逻辑。
- **错误隔离**：每 tick `runCatching` 包住，异常只记日志不终止循环——长驻托盘进程不得因单次网络异常而死。
- **事件出口** `events: SharedFlow<SchedulerEvent>`（市场/同步/备份提醒/轮转/429 频发）：
  宿主不产文案，展示口径在 app 层，保持本层可测。无 API 密钥时不发同步事件（不产生空通知）。

### T11.1 托盘与通知

- **app/tray/TrayIcon.kt**：**程序化绘制的托盘图标**（accent 圆角底 + 纸色衬线 W 折线，
  自带底色使明暗两套系统托盘下均可见）。品牌在原型中是纯文字字标（`WuZhuFolio` 衬线 wordmark，
  无图形标识资产），故此处为**占位资产**——见 §5-1（待人工认可）。
- **app/tray/TraySupport.kt**：`SystemTray.isSupported()` 探测（无头/不支持 → false，不抛）。
- **app/AppHost.kt**：托盘（菜单 = 打开主界面 / 立即同步 / 退出；单击 = 恢复主界面）+
  主窗口可见性 + 调度宿主 + 通知派发四者合一——它们共享**同一个可见性真源**
  `windowVisible && !windowState.isMinimized`，该值同时是「关窗最小化」的结果与调度降频的输入，
  分散会导致托盘驻留与降频判定不一致。
- **app/tray/DesktopBehavior.kt**：`WindowCloseBehavior.decide` 与 `NoticePolicy.noticeFor` 抽为纯函数
  （见 §5-3：当前环境托盘不可用，决策必须能被单测钉死）。
- **通知文案 app/tray/DesktopNoticeText.kt**：同步完成（新增/去重/待解析计数）/ 部分失败（占比）/
  同步失败（首个原因）/ 备份提醒；正文截断 120 字符、只含域层已脱敏短消息。
  **行情刷新与日志轮转发通知？→ 不发**（默认 5 分钟一轮会成噪音，PRD 只要求同步通知）。
- **降级口径**：托盘不可用（本机 WSLg 即如此）→ **不注册托盘、关窗即退出**，
  绝不把窗口藏进不存在的托盘（用户会以为已退出、进程却仍在后台且无入口唤回）；
  设置页「最小化到托盘」行同步置灰并说明原因。

### T11.2 开机自启（默认关，平台注册）

- **domain/autostart/Autostart.kt**（子代理交付）：`AutostartPlatform` + `AutostartRules`
  （平台探测 / 注册文件相对路径 / Windows Run 键 / macOS plist / Linux XDG .desktop / 引号规则）+
  `AutostartStatus` + `AutostartService` + `AutostartCommand`。
- **data/autostart/PlatformAutostartService.kt**：三平台注册与注销（Windows `reg add|delete|query`
  HKCU；macOS `~/Library/LaunchAgents/*.plist`；Linux `~/.config/autostart/*.desktop`），
  全参数可注入（测试用临时 HOME + 假命令执行器，**不触碰真实注册表/家目录**）；
  `enable/disable` **永不抛异常**，失败一律 `Result.failure(IllegalStateException("<中文原因>"))`。
- **接线口径（重要，见 §5-2）**：AppBootstrap 只在 `jpackage.app-path` 存在时注册
  （= 打包版）。开发态该属性为空，显式传 `commandLine = null` → `supported=false`，
  设置页如实置灰——**不注册坏注册项**（裸 java 无 `-cp`，自启即退）。
- **启动自愈** `reconcileAutostart()`：设置键 = 开但注册缺失（重装/移动安装目录后）→ 按当前路径补注册；
  键 = 关但注册残留 → 清理。失败只记日志、不阻断启动。

### 托盘与后台设置分组（M10 §5-1 遗留闭环）

- **domain/settings/DesktopSettings.kt** + **data/settings/DefaultDesktopSettingsService.kt**：
  四项设备级偏好 `tray.minimize_on_close`（默认 on）/ `autostart.enabled`（默认 off）/
  `tray.sync_notification`（默认 on）/ `backup.reminder`（默认 on）。
- **data/settings/DesktopPreferences.kt**：运行期镜像（关窗/通知判定发生在 EDT，逐次查库会卡 UI）。
- **ui/settings/DesktopSettingsViewModel.kt + SettingsPage「托盘与后台」分组**：
  四行开关；自启失败不改视图、回读真实注册态并提示原因（不出现「界面已开启、系统未注册」假象）。
  **该分组的 VM 有意不再用「busy 中 return」防重入**（M10 GeneralSettingsViewModel 的写法）——
  那会静默吞掉用户连续拨动的第二个开关，改为 `Mutex` 排队串行（见 §5-4）。

## 5. 规格落档（待人工走读/认可）

> **人工拍板（2026-09-10）**：人工就本模块提报的三项环境/范围事项逐条拍板——
> ① **托盘留待真实桌面再验证**（= 第 3 条延期，认可）；
> ② **开机自启延期**（= 第 2 条延期至 P7 打包版，认可）；
> ③ **按建议办理**（= 第 4 条：M11 新分组用 Mutex 串行、M10 通用组/网络组维持旧写法并登记 M12 统一；
> 以及第 6 条 toast 遮挡登记 M12 打磨）。
> **M11 模块本身仍为「待审核」**——本次拍板只关闭上述三项提报，不等于模块走查通过。

1. **托盘图标 = 程序化占位资产**：原型中品牌是纯文字字标（`.brand .logo` 的 `WuZhuFolio` 衬线
   wordmark），P1 未定义图形标识。本模块以「accent 圆角底 + 纸色 W 折线」程序化绘制（自带底色，
   明暗托盘下均可见），**不向仓库引入未经设计评审的位图**。正式图标资产建议随 P1 补或 P7 打包图标
   一并定稿；`nativeDistributions` 的 `iconFile` 亦仍未设置（P7 事项）。

2. **开机自启仅在打包版可用（有意为之）**〔✅ 人工拍板「延期」2026-09-10〕：`jpackage.app-path` 为空 = 开发态，
   此时命令行首 token 是裸 `java`（无 `-cp`），注册项自启即退。故接线处显式传
   `commandLine = null` → `supported=false` → 设置页如实置灰。
   **影响**：T11.2 的「开启后自启驻留托盘」端到端**在开发态不可验**，延期至 **P7 打包版**验证
   （到期检查点 = P7 发布前；DoD = 打包产物开启自启后重启系统，应用驻留托盘）。
   本模块已验证 = 三平台注册内容与幂等/失败语义（11 用例）+ 设置页诚实置灰。

3. **托盘 GUI 走查在本机不可执行**〔✅ 人工拍板「留待真实桌面再验证」2026-09-10〕：`SystemTray.isSupported() = false`（WSLg 无系统托盘宿主）。
   故把托盘行为的**全部逻辑**抽为纯函数 `WindowCloseBehavior.decide` / `NoticePolicy.noticeFor`
   并以单测钉死（`DesktopBehaviorTest` 6 用例）；机械动作（`Tray` 组合、`sendNotification`）留待
   **真实 Windows/macOS/Linux 桌面**验证（到期检查点 = M12 走查或 P6 系统测试；DoD = §4 步骤 4 之 ⑤）。
   **降级路径本机已实证**：`tray support supported=false` 且 rc=124（窗口正常驻留未崩）。

4. **托盘与后台 VM 不用「busy 中 return」防重入**〔✅ 人工拍板「按建议办理」2026-09-10〕（与 M10 `GeneralSettingsViewModel` 写法不同）：
   该写法会**静默丢弃**用户在写入未完成时的第二次开关拨动（连续拨两个开关即复现），
   属可见缺陷；本模块改为 `Mutex` 排队串行。**M10 的通用组/网络组仍是旧写法**，
   已登记 §6 转 M12 统一（不属 M11 范围，避免动已通过模块）。

5. **备份提醒基线口径**：优先账户级 `backup.last_at`（M9 落盘）；**从未备份过则退化为账户创建时刻**
   ——新装用户满 30 天前不打扰；两者皆不可得 → 不提醒（宁缺勿扰）。
   PRD 6.1 只写「距上次备份超过 30 天」，该补充口径待人工认可。

6. **通知范围**：只发「同步完成/失败」（PRD §9.4）与「备份提醒」（PRD 6.1）；
   **行情刷新成功/失败均不发桌面通知**——默认 5 分钟一轮，失败通知会形成噪音
   （行情异常态由行情页/状态栏承载）。429 频发事件已由调度宿主发出，
   但其 UI 展示（PRD 6.1「429 频发时提示」）登记 §6 转 M12 状态栏。
