## 1. 本次改了什么（实现摘要）

### T1.1 SQLCipher(JDBC) 整库加密（锁版）
- **驱动锁版实证**：io.github.willena:sqlite-jdbc:3.53.4.0（org.sqlite.mc fork，Multiple Ciphers 构建；SQL_CIPHER = SQLCipher 4 兼容实现）。实测 API：SQLiteMCSqlCipherConfig.getDefault()（SQLCipher 4 参数：kdf_iter 256000 / HMAC-SHA512 / 页 4096）+ withRawUnsaltedKey(32B) → build() → toProperties() 注入连接。**raw-key 模式**（x'hex'，跳过 SQLCipher 自带 KDF，ADR-002 备注）；密钥随**连接属性**注入、每新连接自动携带（评审 N4 口径）；驱动连接期执行 select 1 from sqlite_schema 即时校验密钥。
- **WzDatabase 重构**（data/…/db/WzDatabase.kt）：构造签名 (dbPath, masterKey: ByteArray, migrations)；共享写连接（迁移执行器）+ Exposed 新连接工厂均带密钥；WAL / busy_timeout(5000) / foreign_keys=ON 注入。错钥/旧明文库/损坏头 → 类型化 DatabaseKeyMismatchException（SQLITE_NOTADB 映射），另有 DatabaseOpenException。
- **三平台验证**：SqlCipherDatabaseTest（数据层测试，6 项守护：文件头非明文 / 重启同钥解锁 / 错钥类型化拒绝 / WAL·busy_timeout·foreign_keys 每连接生效 / Exposed 新连接带钥读写）随 CI 三平台矩阵执行 = 驱动三平台可用性验证；本地 Linux 已绿。
- **主密钥存取**（data/…/security/MasterKeyStore.kt）：KeychainMasterKeyStore（java-keyring 1.0.4：Windows 凭据管理器 / macOS Keychain / Linux Secret Service）——「无条目 vs 后端不可用」经**探针写-读-删往返**区分（跨后端无统一缺失语义，不做消息嗅探）；FileMasterKeyStore（降级 0600 hex 文件，损坏不静默覆盖）；MasterKeyResolver.obtainMasterKey（钥匙串优先 → 无条目则首建 → 写失败转降级 → 文件取用/首建，零静默降级）；KeyStorageReport(backend) 如实上报后端。
- **降级提示**：AppBootstrap 按 FILE_FALLBACK 生成提示文案；MainShell 新增 startupNotice 安全提示模态（WzModal，UI 测试 2 项）；启动致命错误（错钥 / 密钥文件损坏 / 打开失败）渲染 FatalWindow（含数据目录指引；正式 B1「从 .cpro 恢复」页面随 M2/M9 落地）。

### T1.2 CryptoService（领域层纯 Kotlin，无 IO）
- 新包 domain/…/security：
  - KdfParams：Argon2id 参数 + 稳定存储串 {"alg":"argon2id","m":65536,"t":3,"p":1}（accounts.kdf_params 契约，M9 .cpro 载荷同用；解析非法抛错不静默降级）；OWASP_MINIMUM 19MiB/t2 兜底。
  - Argon2Kdf：**BouncyCastle Argon2BytesGenerator 纯 JVM**（argon2-jvm/JNA 原生绑定未采用——免三平台原生库分发风险，速度实测见 §4）；输出 32B、salt 16B、密码内部拷贝 finally 清零。
  - AesGcm（internal）：JDK AES/GCM/NoPadding，96-bit 随机 nonce，AAD 支持。
  - KeyWrap：DEK/KEK 包解包，AAD = account_id + "wrapped_dek"，存储形态 v1 + base64(nonce‖ct‖tag)；解包认证失败 → AuthenticationFailedException（= M2 密码错误语义，ADR-002 §3）。
  - FieldCipher：api_keys 凭证列字段级加密，AAD = account_id + "|" + api_key_id + "|" + column（账户/条目/列三重隔离），形态 v1 + base64(version(1B)‖nonce‖ct‖tag)。
  - CryptoService 门面（M2/M6/M9 消费）+ Zeroization 擦除 + AuthenticationFailedException。

### T1.3 KDF 基准校准（实测 → 冻结）
- 夹具：./gradlew :domain:kdfBenchmark（JavaExec，非 CI 断言）；参照机 = 本开发机（Ryzen 9 5900HX 16 线程，JDK 17.0.20.1，BouncyCastle 纯 JVM）。
- **实测（3 次取最优）**：64MiB/t3/p1 = **169ms**；64MiB/t2 = 130ms；48MiB/t3 = 146ms；32MiB/t3 = 95ms；32MiB/t2 = 75ms；19MiB/t2（OWASP 下限）= 42ms。
- **冻结**：KdfParams.DEFAULT = m=64MiB / t=3 / p=1（维持 ADR-002 初值）。估算低配双核目标机约 3–6× 慢 → 0.5–1.1s，留 ≤2s 余量；**4GB 双核目标机复核列入 M2 人工门遗留**（不达标降 OWASP_MINIMUM，预案已备）。

### T1.4 单写队列（读写连接分离）

- SettingsRepository 改经 DbGate（写 = 队列内 upsert，保持 COALESCE 唯一索引语义）；HelloChain 链路不变。
- 测试：DbGateTest（6 写者 × 12 次交错 upsert 无锁冲突逐笔落库 / 单键 60 任务读改写精确计数 / 读写并行无错）。

## 4. 关键实测记录（证据）

- Argon2id（BC 纯 JVM）候选参数耗时：见 §1 T1.3；参照机 Ryzen 9 5900HX / 16 线程 / JDK 17.0.20.1 / Linux。
- SQLCipher 独立探针实证：错钥 → [SQLITE_NOTADB] File opened that is not a database file；新建库文件头 16B 非明文 SQLite 头（加密生效）；journal_mode=wal / busy_timeout=5000 / foreign_keys=1 在共享连接与新连接均生效。
- GUI 冒烟（WSLg + SOFTWARE_FAST）：日志两行——hello-chain ok | schema_version=2 | … market_api_key=**** 与 bootstrap ok | key_backend=****（脱敏生效）；二启复用降级密钥成功。**2026-09-03 修复轮后：主窗口与降级提示模态驻留至手动关闭（rc=124 实证）**——此前冒烟误判「窗口常驻」，实为 Outcome 类型推断缺陷导致成功路径静默退出（见下）。
- **2026-09-03 修复轮**：main() 引导结果 runCatching.getOrElse 被推断为 Any（Runtime 与 Outcome.Fatal 的 LUB），when(is Outcome.Ready) 永不命中 → 成功路径不组合窗口、进程约 2s 静默退出（12:34 FatalWindow 可见而主壳不可见的原因）。修复 = 显式收敛密封 Outcome（try/catch 包 Outcome.Ready）；本地两连启窗口驻留实证，63 测试 + detekt 绿。
- java-keyring 无 dbus Secret Service 环境（本机 / CI Linux）读写失败 → KeychainUnavailable → 文件降级（真实后端往返仅 win/mac CI 验证）。
