## 1. 本次改了什么（实现摘要）

### T3.1 coins 目录（M004 迁移 + SqlCoinCatalog 检索/缓存）
- 迁移 M004 coins（schema v3→v4，data-model §2.9 + **contracts 勘误列**，见 §5）：UNIQUE(cg_id)（验收项）+ symbol/name 索引 + status（ACTIVE/DELISTED/UNTRACKED，默认 ACTIVE）+ display_precision（默认 8）+ cmc_id（可空）+ contracts（平台→合约地址 JSON，消歧规则②用）。
- 迁移 M005 exchange_coin_map（v4→v5，data-model §2.10）：UNIQUE(exchange, exchange_asset) + coin_id FK + source（AUTO/MANUAL）。
- domain CoinCatalog 契约（接口 domain/catalog，实现在 data/catalog）+ CatalogCoin/CoinDirectoryEntry/DirectoryRefreshSummary 模型。
- refreshDirectory(entries)：/coins/list 全量目录幂等 upsert（同批 cg_id 去重后写；新增/变更计数；contracts JSON 编解码经 kotlinx-serialization——data 模块新增该依赖，许可证已在册）。
- refreshCmcIds(map)：cmc_id 每日缓存落库（/cryptocurrency/map 对齐产物由 M5 按 symbol 对齐后喂入；未知 cg_id 跳过）。
- search/getBySymbol/getByCgId/getById：大小写归一检索（symbol 精确 > 前缀 > 名称包含，symbol 内含命中殿后），输入归一化「usdt → USDT」落地。

### T3.2 CoinResolver 消歧归一（domain 纯规则 + 数据编排 + 映射冻结）
- CoinResolver（domain/catalog，无 IO 可单测）：共享规范 §6 四级规则链——① 交易对上下文（quote 侧同币种排除；退化对 NotFound）→ ② 合约地址精确匹配（chain 过滤、无命中不猜测降级 → NotFound）→ ③ 市值排名唯一最小（MarketRankProvider 边界接口 + Noop 默认；前 1000 预缓存归 M5 注入）→ ④ Ambiguous 候选（排名靠前排序，UI 用户选择）。
- SqlCoinCatalog.resolve(exchange, asset, context)：先复用 exchange_coin_map 既有映射（FROZEN_MAP，AUTO/MANUAL 均自动复用）；自动消歧唯一结果且带交易所上下文时固化 source=AUTO（后续复用）；歧义返回候选不固化。
- freezeMapping(exchange, asset, coinId)：用户选择固化 MANUAL（已存在映射时改绑 + MANUAL 覆盖）；目标币不存在 → UnknownCoinException（类型化）。
- 键归一：cg_id 小写 slug、symbol/exchange/asset 大写——映射键与检索键一致（Kraken XBT 等别名归一由映射表承担，不做字符串猜测）。

### T3.3 FiatNormalizer（法币孪生映射 + 计价腿分诊）
- FiatNormalizer（domain 纯规则）：默认孪生表 USD→USDT、EUR→EURC（共享规范 §3，1:1 联动）；已知法币代码集（交易常用 ISO 4217 子集，无孪生者按第三币种语义——仅计基础币种，不联动计价侧）；twinMap 可注入（M10 设置覆盖/扩展预留）。
- CoinCatalog.fiatQuoteLeg(quoteSymbol)：TwinStable（USD→USDT 币/EUR→EURC 币，BTC/USD→quote=USDT 验收口径）| ThirdCurrency（GBP/CNY 等；孪生稳定币不在目录的极端场景安全退化不抛错）| null（普通币种走目录解析）。

## 5. 规格落档（勘误与契约登记，后续模块引用）

1. **coins 表增列 contracts（桌面端勘误）**：data-model §2.9 未列 contracts，但 PRD §10-10 注「含各链合约地址缓存」+ 消歧规则②（合约地址精确匹配）需要该数据；移动端 SRD §14 coins.contracts 同源。故 M004 落 contracts TEXT NOT NULL DEFAULT '{}'（平台→合约 JSON）。data-model 修订建议随 M3 评审后回写（或在 P2 文档勘误登记，口径同 M2 §4-6）。
2. **api-contracts §3 契约补录**：新增 CoinCatalog（10 动作：search/getBySymbol/getByCgId/getById/refreshDirectory/refreshCmcIds/resolve/freezeMapping/mappingFor/fiatQuoteLeg）+ 结果类型（Resolution/FiatLeg/ResolveContext）；M2 restoreSession 补录先例。Koin/AppBootstrap 装配待首个消费模块（M5/M6/M7）接入（本模块无 UI 消费方）。
3. **键与映射口径**：cg_id 存小写 slug；symbol/name/exchange/asset 存大写（exchange_coin_map UNIQUE 以归一化键维护）；交易/资金记录冻结 coin_id 的语义归 M7/M8（保存时写入、不回溯改写——映射冻结原则）。
4. **resolve 语义注**：孤儿映射行（coins 行缺失）视同未解析 → NotFound；exchange 为空（手动录入路径）不固化 AUTO。
5. **FiatNormalizer 口径**：已知法币 = 常用 ISO 4217 子集（48 码）；未覆盖法币代码会按普通币种走目录（NotFound）——集合扩展/设置化随 M10。twinMap 与增资默认映射表（USD→USDT、其余→USDC 建议）分开：本模块管计价/费用侧归一；增资默认映射属资金模块语义。
6. **契约登记延续**：M2 §4-6 勘误口径不变；本模块 DDL 严格按 data-model + 上述 1 执行。
