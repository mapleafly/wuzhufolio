### T8.2 校准记录入列 + 校准执行流（CalibrationUseCase + DefaultCalibrationService）
- **执行链**（PRD 全局说明「持仓校准规则」/ 故事 4.1-5）：币种解析 → 全量重放取本地持仓与**交易事件
  来源集合**（资金/锚点不计——M4 §5-6）→ 单一来源门（NoRecords/Multi → CalibrationBlockedException，
  多来源提示 PRD 原文）→ 依据交易所只读密钥（api_keys 按交易所名匹配，最近同步优先）→
  fetchBalances 实时余额（exchange_coin_map **反向映射** CoinCatalog.exchangeAssetFor（新）+ symbol 兜底，
  缺余额行按 0 计）→ 校准时市价（现价链；完全不可用 → NO_MARKET_PRICE——PRD「行情完全不可用时暂
  不允许执行校准并提示」）→ ReconciliationService.plan 差额规划 → execute。
- **execute**：重新实时取数（余额/市价以执行时点为准）→ delta=0 不生成记录（「已与交易所一致」）→
  锚点入库前相对校验（**锚点把持仓对齐到其后卖出依赖的余额被削时 V9 阻止**，见 §5-2）→
  reconciliation_records 入库（M012）→ **sync_logs 留痕**（api_key_id + 脱敏摘要「持仓校准 BTC：本地
  1.0 → 交易所 0.8（差额 -0.2，折算 …）」，PRD 故事 4.1-5「在同步日志留痕」）。
- **资金列表入列**：校准行以「校准」类型并入混合列表（数量列 = 差额[可负]、折算列 = base_amount、
  来源去向列 = 依据交易所）；**不可编辑、仅可删除**（PRD §10-8 注；删除走相对校验——删除锚点使其后

## 5. 规格落档（裁决与勘误登记，后续模块引用）

1. **V7 撤资同点绝对校验（收紧，落实 M4 §5-5「宽松口径复核归 M8」）**：相对校验（仅拦「操作新制造」
   负边界）对「既存导入异常位点继续恶化」放行——对撤资而言会静默加深持仓异常、违背 PRD §9.8
   「撤资时对应币种持仓须 ≥ 撤资数量」。裁决：撤资（保存/编辑）在相对校验之上追加**同点绝对校验**
   （撤资本位点任何负边界即 V7 阻止）；其余资金操作与交易半边维持 M4 相对语义不变。
2. **校准执行前相对校验（锚点可被 V9 拦截）**：锚点把持仓对齐到较小余额时，其后记录可能转负
   （如锚点后卖出 > 交易所余额）——按手动操作 STRICT 家族语义在入库前做相对校验，命中即 V9 阻止
   且不入库不留痕；锚点自身位点恒非负（exchangeQuantity ≥ 0）不构成拦截。删除校准记录同理
   （删除后其后记录转负 → V9）。
3. **校准入口偏差登记（GUI，PRD 故事 4.1-5/§9.5）**：PRD 入口 = 币种详情页「以交易所余额校准持仓」
   按钮（仅单一来源显示）；币种详情页归 M12 聚合整合——本模块在**资金管理页命令区**挂「校准持仓」
   入口（弹窗形态承载「按钮隐藏并显示相应提示」），M12 币种详情落地时迁移/并存，届时复核入口唯一性。
   延期项：**详情页校准历史列表**（ia.md §2.7）随 M12（CalibrationUseCase.history 服务面已就绪）。
4. **资金折算价完全缺失 = 名义零折算（fiatValue=0 + estimated，替代「排除出重放」）**：与 M7 §5-12
   同理——排除会断持仓数量链；0 折算使累计增资/撤资暂少计（估算中标注），行情回填后重建事件自动
   纠正（黄金 9 语义）。capital_flows.base_amount 列 = 记录时快照（审计/备份口径），引擎不消费。
5. **三类事件确定性决胜序**：三类表独立 AUTOINCREMENT，同 (at, seq) 可能跨表相撞——装配层显式排序
   (at, seq, 类型序[资金0/交易1/锚点2], uuid) 后交引擎（M4 §5-9「输入序确定」落实）；资金先于交易
   的类型序保证「先增资后买入」同刻记录的正确语义。新记录 seq = 三表行 id 最大值 + 1（M7 §5-7 口径
   推广）。
6. **M011/M012 金额列 TEXT 勘误（C0）**：amount/base_amount/local_quantity/exchange_quantity/delta
   存 TEXT 十进制串——延续 M005/M006/M009/M010 勘误链（SQLite NUMERIC 浮点截断风险），已回写
   data-model §2.6/§2.7；capital_flows.price_status 存保存时点快照（OK/PENDING），列表「估算中」以
   事件构造层动态重建为准（与交易行口径一致）。

## 8. GUI 走查修复轮（2026-09-09，人工 3 项反馈 → 已修复）

> 人工走查反馈：① 增资表单输入 USDT 出 6 条同名候选，点选第一条后保存报
> 「coin not resolvable: USDT（歧义（同名资产49个…））」；② 撤资表单同样操作同样报错（同根因），
> ③ 因 ①② 卡住，后续走查项未进行。另观察：输入 usd 提示「法币不入账」（符合设计）、cny 无对应币种。

**根因（①②同根）**：表单候选点选只回填了符号文本，服务层保存仍按**符号**从目录重新解析——
真实目录中 USDT 同名资产 49 个，纯符号解析必然歧义（`CoinResolutionException`）。设计意图
（flows.md §2「币种基于 coins 目录自动补全」）是候选列表即消歧 UI，但选择结果没有贯穿到服务层。

**修复（§8-1 候选点选直达保存）**：
- `FundInput` 增 `pickedCoinId`（点选冻结的 coins.id；null = 纯手输）；`FundEntryRow` 增 `coinId`
 （编辑回填同样直达）；`fiatValuePreview` 增 `pickedCoinId`；服务 `resolveFundCoin` 点选路径 =
 按行 id 直取 + 校验符号一致（不一致类型化拒绝），完全绕过符号歧义；
- 默认币种由「返回符号文本」改为 **`defaultCoin(): CatalogCoin?`**——按稳定币白名单 cg_id 直取
 （USD→tether / 其余→usd-coin，PRD §9.8），打开表单即「已选择：USDT · Tether（tether）」，不再依赖
 符号再解析；
- **校准弹窗同修**：`CalibrationUseCase.prepare/execute/history` 增 `pickedCoinId`；校准弹窗补候选
 列表 + 「已选择」行（此前无候选通道，同名符号同样会被歧义拦住）；
- **候选行展示 cg_id**（`USDT · Tether（tether）`）——同名资产靠 CoinGecko id 区分；候选列表改
 可滚动（最多 12 条）；
- **错误文案中文化**（观察项顺带）：`FundsCopy.coinResolutionCopy` 把英文异常原文
 （coin not resolvable: …）组装为「币种「USDT」无法唯一确定：歧义（同名资产 49 个…）——请从输入框
 下方候选列表点选后再保存」；表单/校准弹窗/toast 三处统一。
