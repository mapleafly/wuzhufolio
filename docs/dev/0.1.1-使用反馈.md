## 2. 逐条定位与分级建议

### 2.1 反馈 ①：粘贴的数字带空格 → 不能计算总价（**DEF-54**）

| 项 | 内容 |
|----|------|
| **现象** | 从 CSV 等来源复制数字粘进「价格/数量」输入框，数字后带空格 → 总价不计算 |
| **代码事实（只读定位）** | 输入值原样进入 ViewModel，**中间没有任何清洗**：<br>① `ui/.../ledger/TransactionsViewModel.kt:619-624` `computeTotal(price, qty)` = `price.toBigDecimalOrNull()` × `qty.toBigDecimalOrNull()`；<br>② 同文件 `:605-609` `validateForm` 同法解析；<br>③ 同文件 `:577-580` 提交路径同法解析。<br>`BigDecimal("1234.56 ")` 抛 `NumberFormatException` → `toBigDecimalOrNull()` 返回 `null` → **`total` 回落 `"0.00"`**，同时报「价格必须大于 0」。<br>`WzTextField`（`ui/.../components/WzTextField.kt`）用的是 `OutlinedTextField(value, onValueChange)` 重载，**没有** `InputTransformation`/任何归一化 |
| **同类点（影响面）** | 已归一化的：`GeneralSettingsViewModel.kt:116`（有 `.trim()`）、`FeeRuleSettingsSection.kt:120/121/145/146`（有 `.trim()`）。<br>**未归一化**：`TransactionsViewModel.kt`（price/quantity/fee ×3 处）+ `FundsViewModel.kt:283/316/532`（quantity）→ **共 2 个文件 6 处** |
| **建议分级** | **C0**（实现补全：输入归一化是「解析」本就应包含的步骤，不改产品语义）。<br>若人工认为要连带改输入组件行为（见下）→ 按 **C1** |
| **建议修法（两段式）** | **止血（C0）**：在解析层统一归一化——去 `[ \t\u00A0\u202F]`（含 CSV 粘贴常见的 **NBSP/窄 NBSP**）、全角→半角（NFKC）、去货币符号。**必须同时做**：`computeTotal`/`validateForm`/提交三处共用同一个 `parseAmount()`，避免再次漂移。<br>**根治（C1，可选）**：把数值框迁到 `OutlinedTextField(state = rememberTextFieldState(), inputTransformation = …)` ——**粘贴/拖放会自动经过它**（官方文档原文），显示层用 `outputTransformation` 做千分位（**不再需要 `OffsetMapping`**）。<br>⚠️ 两个坑：① **程序化赋值不经过 transformation**（`.cpro` 恢复、表单预填必须自己再清洗）；② 该重载与现有 `value/onValueChange` **不能混用** → 属 `WzTextField` 公共 API 变更。<br>⚠️ **locale 歧义**：`1,234.56`（en-US）与 `1.234,56`（de-DE）语义相反，「` ,` 一律当千分位删」在欧陆格式下会**静默产生 100 倍误差** → 建议**定义唯一规范输入**，歧义串直接报错而不是猜 |
| **不建议** | ❌ 用 `visualTransformation` 做清洗（它改不了实际 value，`BigDecimal` 拿到的仍是脏串——正是本缺陷的形态）；<br>❌ 引入第三方「金额输入框」库（✅ 已逐个核实：候选全是 0.x alpha / 0 star / Android-only） |

### 2.2 反馈 ②：日期时间只能手打，没有弹出选择（**DEF-55**）

| 项 | 内容 |
|----|------|
| **现象** | 「几乎所有窗口中的日期和时间组件需要键盘输入」 |
| **代码事实（只读定位）** | 日期时间 = **纯文本输入框**，格式 `yyyy-MM-dd'T'HH:mm`（示例 `2026-09-28T14:30`）：<br>① 交易表单 `TransactionFormModal.kt`（`state.timeText` → `TxField.TIME`）；<br>② 资金表单 `FundFormModal.kt:116`（`state.timeText` → `FundField.TIME`）；<br>③ 解析 `TransactionsViewModel.parseLocalTime` / `FundsViewModel.kt:546-553`（两种格式 `runCatching`，失败即报错）。<br>**全仓无任何 `DatePicker`/`TimePicker` 使用** |
| **可行性（✅ 一手实测，含渲染 spike）** | **不需要新增任何依赖**：本项目已依赖的 `material3-desktop:1.9.0` 里就有 `DatePicker`、`DateRangePicker`、`TimePicker`、`TimeInput`、`DatePickerDialog`、`TimePickerDialog`、`DateInput`（jar 反查）。<br>opt-in 口径（javap 实测 **1.9.0**）：`DatePicker`/`DateRangePicker`/`TimePickerDialog` **不需要**；`TimePicker`/`TimeInput`/`rememberTimePickerState`/`DatePickerDialog` **需要** `@OptIn(ExperimentalMaterial3Api::class)`。<br>**渲染 spike（2026-09-28）**：在 `WuzhuTheme` 内并排渲染两者 → 无异常、**60 个可交互语义节点**、`14`/`30` 文本节点存在 ⇒ 本项目栈内确实能渲染可交互（临时测试已删）；仍未验证 = **真实 GUI 的键盘/IME** 与上述两个官方缺陷 |
| **建议分级** | **C1**（新增交互组件 + 改两个表单的输入方式，属设计基线增量；不触硬约束红线） |
| **建议修法** | **用无壳的 `DatePicker`/`TimePicker` 内容，套进现有 `WzModal`**（不要用官方 `DatePickerDialog`）：<br>① 守住 `AGENTS.md §7.3-①`「弹层一律同窗口就地叠加」；② 外观/按钮/间距与全应用一致；③ 绕开仍需 opt-in 的那个 API。<br>保留「手打」入口（键盘输入对熟练用户更快）：文本与选择器双向同步，解析失败给明确文案。<br>⚠️ 落地前必须实测两个官方已知缺陷：**UTC 以西时区月份下拉标签错一月**（[CMP-10038](https://youtrack.jetbrains.com/issue/CMP-10038)，✅ 复核仍 Open）与 **TimePicker 在 OpenGL 渲染后端下配色错误**（[CMP-10319](https://youtrack.jetbrains.com/issue/CMP-10319)，✅ 复核 Submitted） |
| **验收（§7.3-③ 强制）** | Compose UI 测试（`performClick` 选日期 → `assertIsFocused`/`performTextInput` 路径）+ 人工 GUI 键盘逐字录入复验；覆盖 24 小时制、跨时区（`TZ=America/Denver` 与 `Asia/Shanghai` 各一遍） |

### 2.3 反馈 ③：在价格/数量输入框里输入空格 → 添加窗口退出（**DEF-56 · 本轮唯一「已定位到根因并已验证修法」的一条**）

| 项 | 内容 |
|----|------|
| **现象** | 「在添加交易窗口的价格和数量输入框中，输入空格，会退出添加窗口」 |
| **复现（✅ Agent 用 Compose UI 测试实证，非推测）** | 打开「添加交易」→ 焦点在 `tx-qty-input` → 注入**真实按键** `Key.Spacebar` → **弹窗关闭**（`tx-modal` 不再显示，焦点计数归 0）。<br>对照：用测试框架的 `performTextInput(" ")` 注入文本**不会**关闭 → **说明差别在「真实按键事件」而非「值变化」**，这解释了为什么 P6 的既有用例没抓到（§7.3 强制项用的是 `performTextInput`，它绕过按键事件） |
| **根因（✅ 已因果验证）** | `ui/.../components/WzModal.kt:107-118`：**遮罩层**（全屏 Box）用的是<br>`Modifier.clickable(interactionSource, indication = null, onClick = onDismiss)`。<br>Compose 的 `clickable` 节点**会把 Space/Enter 当作「激活点击」**处理；而它是弹窗内所有输入框的**祖先节点**，空格按键在输入框插入字符之后**继续冒泡到它** → 触发 `onClick` = `onDismiss()` → 弹窗关闭。<br>**因果验证**：把遮罩换成 `Modifier.pointerInput(Unit) { detectTapGestures { onDismiss() } }`（与卡片吞点击同一手法）后，**同样的操作不再关闭弹窗**，焦点仍留在输入框（✅ 实测）。 |
| **影响面（重要）** | `WzModal` 在全应用 **14 个文件 / 15 处**使用，其中 **11 个文件同时含文本输入框**（交易表单、资金表单、校准、CSV 导入、API 密钥、行情 Key、设置页、数据管理/恢复密码、币种详情…）。<br>⇒ **任何弹窗里只要用户敲空格就可能被关掉**（备注、密码、搜索词、自定义手续费币种…），是**全应用级的弹窗缺陷**，不止「添加交易」 |
| **同源问题（顺带发现，同一处代码）** | 遮罩是 `clickable` ⇒ **它本身是一个可聚焦目标** ⇒ ① 焦点可以从弹窗内容**逃逸到遮罩**（弹窗内按 Tab 可到达，实测：转储聚焦节点时出现「焦点在弹窗内字段之间移动正常，但遮罩参与 Tab 序列」）；② 焦点落在遮罩上时**回车/空格即触发关闭**——对纯键盘用户是「误触关闭」风险。修法一次覆盖两处 |
| **建议分级** | **C0**（实现偏差纠正：遮罩不该是「可聚焦 + 可被空格/回车激活」的点击目标；不改产品语义、不改数据/接口） |
| **建议修法** | ① `WzModal` 遮罩改 `pointerInput { detectTapGestures { onDismiss() } }`（**已验证有效**，与卡片吞点击同源，同时消除遮罩的焦点目标）；<br>② Esc 关闭仍由卡片 `focusable()` + `onPreviewKeyEvent` 承担（不变）；<br>③ **补真实按键回归用例**：`performKeyInput { pressKey(Key.Spacebar) }` 断言弹窗仍在 + 焦点仍在输入框（并把「输入框内敲空格不关闭弹窗」写入 `AGENTS.md §7.3` 的验收强制项——现有强制项只覆盖 `performTextInput`，**抓不到这类缺陷**）；<br>④ 排查同源：`GateWidgets.kt`（认证弹层）也有一份同结构的遮罩实现，需一并核对 |

## 3. 总体感受：「界面笨拙，组件像手工制作，没有总体风格」→ 已单独立项调研

- 这不是「一条缺陷」，而是**组件体系问题**。已完成调研并单独落盘：
  **[`docs/tech/UI框架与组件统一调研.md`](../tech/UI框架与组件统一调研.md)**（含候选清单、硬数据对比、三条路线与工作量评估）。
- **一句话结论**（详见该报告 §0）：本项目**已经依赖了最合适的框架**（Compose Multiplatform 官方 Material 3，
  实测解析为**稳定版 1.9.0**，含 **63 个组件族**，日期/时间选择器就在里面），
  但代码里**只用了 3 个 M3 控件**，其余全部是 Foundation 手绘（`WzButton` = `Box`+`background`+`border`+`clickable`+`Text`）。
  ⇒ 「手工感」的根因是**没有把框架当作唯一真源**，不是「没选对框架」。
- **本次不擅自实施**：路线选择、分级与排期按 `AGENTS.md §8.4` **停人工门**（报告 §7 给了 4 个待拍板选项与建议的最小验证顺序）。

## 7. 追加口径问题（2026-09-29 人工提问，**待人工定级**）

**人工原话**：「我当前还未登录账号，现在是登录窗口，这时候在托盘菜单选择执行『立即刷新行情』，也会提示『更新完毕』提示，
但是这时候还未登录，理论上软件还不知道更新哪些币种吧？」

**代码事实（只读核验）**：

1. **自选清单是「全局设置」，不是账户数据**：`settings` 表的全局行 `watch.coins`（JSON 数组，见
   `domain/market/MarketWatch.kt:42`、`data/market/MarketWatchServices.kt:17`）。因此**未登录时应用确实知道要刷新哪些币种**——
   人工实测日志 `watch.coins=["tether","bitcoin","cross-2","audius","enjincoin"]`（5 枚）与
   `market refresh finished source=COINGECKO coins=5` 一致，**「更新完毕」是真实结果，不是假提示**。
2. **调度器在启动时即开始工作**（不依赖登录）：`AppHost` 在组合期 `scheduler.start(scope)`，日志中登录前已有
   `market refresh started manual=false` / `scheduler started | syncInterval=30min`。
3. **托盘菜单在登录前可用**：托盘与调度器属应用级能力，不受登录门限制（设计如此：托盘驻留、开机自启、后台同步都在登录前就绪）。

**⇒ 这是「按现状设计」而非缺陷**，但引出两个**产品口径问题**，按 `AGENTS.md §8.4` 提报，请人工定级：

| # | 问题 | 现状 | 可选口径 | Agent 的分级建议 |
|---|------|------|----------|------------------|
| ① | **未登录时是否应联网刷新行情？** | 会（启动即刷，登录前也在刷） | 甲：维持（行情是公开数据，先刷好、登录即见）；乙：登录前不发起行情请求（避免"未登录就外联"的观感），登录后立即补刷 | **C1**（行为口径调整，不触 §1.1 硬约束） |
