# D24 · 备份文件密码独立设置（不回填账户密码、禁止空密码）

> 2026-09-10 人工裁决（M9 备份恢复人工门验收期拍板，裁决对象 = 模块记录 M9.md §5-1 规格落档第 1 条偏差）。
> 需求基线处理：`docs/prd/` 为只读基准（AGENTS.md §2），**不改 PRD 正文**；PRD 故事 5.2-3
> 「界面默认填入当前账户密码」以本决策口径为准——有效需求 = PRD V1.9 + `docs/dev/增量台账.md` Δ{…, D24}。

## 1. 背景

PRD 故事 5.2-3 原文要求备份文件密码「导出时由用户设置（**界面默认填入当前账户密码**，可修改）」。
M9 实装时确认该 UX 与安全架构冲突：本产品密码**永不落盘、不留存**（PRD 5.1-4、ADR-002 §2），
会话内只持账户 DEK（KEK = KDF(密码, salt) 单向派生，改密仅重包裹），**无任何途径在导出界面回填
账户密码**——除非将会话全程驻留明文账户密码，违反密码擦除纪律与 5.1-4 硬约束精神。
M9.md §5-1 登记该偏差后，人工于 M9 人工门裁决如下。

## 2. 拍板结论（人工原话摘录）

> 「不默认使用当前账户密码，也不能是空密码，现由用户设置独立密码。」

固化为三条产品口径：

1. **不默认填当前账户密码**：备份导出界面密码栏为空起步，用户自行设置独立备份密码
   （UI 内嵌说明该口径与理由——见 BackupCopy.EXPORT_PWD_NOTE）。
2. **禁止空密码**：导出与恢复两侧均不接受空密码——导出侧按账户密码同一最低强度门槛校验
   （AccountPolicy.meetsMinimum：≥8 位且含字母与数字，PRD 5.2-3 强度要求保留）；恢复侧验证按钮
   在密码为空时不可用，编解码层 Argon2id 拒绝空口令（Argon2Kdf.require）。
3. **独立密码语义不变**：备份文件密码与账户密码无任何派生/存储关联；跨设备/跨账户恢复只依赖
   该文件密码（PRD 5.2-3/5.2-9、共享规范 §8 不受影响）；改密不影响历史备份解密（PRD 5.1-6）。
