## 2. 拍板结论（范围）

**版本 = `0.4.0`（minor）**。理由：含**新交付物**（投递矩阵 + 矩阵守护用例）与**规约增量**，非补丁线语义（`0.1.x` = patch · `0.x.0` = minor 迭代）。

### 2.1 ② 通知 / 反馈体系统一 —— 交付定义

1. **文档交付**：`docs/design/desktop-notifications.md`（新建）——「**平台 × 场景 × 通道**」**投递矩阵**，逐格写明：
   - **平台**：Windows / Linux / macOS（macOS 随 `D51` 进入发布范围后**必须**进矩阵）；
   - **场景**：托盘手动动作（立即同步交易 / 立即刷新行情 / 打开主界面 / 退出）· 后台调度事件（同步完成 / 失败 / 备份提醒）· **门禁拦截**（未登录「请先登录」）· 顶栏手动同步与刷新；
   - **通道**：应用内提示窗（`DesktopToastWindow`）· 原生系统气泡（`AwtTrayHost.notify`）· 窗口内 toast（`MainWindowContent` 的 `manualSyncToast` / `refreshToast`）· **日志**（`logs/`）；
   - 每格标注**是否投递 / 由谁渲染 / 可见反馈文案**；并显式标注「**设了状态但没人渲染 = 静默失败**」这一模式。
2. **守护用例**：新增 `NoticeDeliveryMatrixTest`（或等价）——**逐格断言**投递决策（含**非默认平台**分支），确保新增平台/场景时矩阵不退化。
3. **实现收敛**（若需要）：把「托盘手动动作」与「后台事件」两条投递路径收敛到**同一决策入口**（当前分叉：`AppHost.showNotice()` 只喂应用内窗，后台事件走 `trayHost?.notify`）——**是否动代码由技术步定**，但**不得**改变既有可见反馈。

### 2.2 ③ 工程债固化 —— 交付定义

1. **规约入册**：`AGENTS.md §7.3` 新增 **⑩⑪⑫⑬**（来源 = `retrospective.md §3.1` + 人工 2026-10-14 裁决）——本阶段已随 `D50` 落盘；
2. **脚本纪律**：把「**文件白名单 + 命中数断言 + 写入后回读校验**」与「**带日期的证据行禁改**」写成可复用做法（落 `scripts/` 下的实践说明或 `AGENTS.md §3.1` 第 8 项的附带纪律）；
3. **视觉回归按平台基线**：把当前「三平台共用一套基线 + 容差」升级为「**按平台基线**」，并评估是否由**报告型**转**阻断**（`ci.yml:44-55` 的 `VISUAL_REGRESSION_PNGS == 24` 断言已是 C0 修复产物）；
4. **CI 断言复核**：把本轮 4 项缺陷对应的门禁（产物声明 / 开关进输入 / 精确断言 / 计数断言）逐条复核为**防复发**形态。

### 2.3 不含项

- **macOS 发布范围**：见 **`D51`**（独立决策，口径反转）；
- **`D41` 改「不认领」**：见 **`D52`**（**C2**，走 `§8.3` mini 闭环；返工任务 = `T16.4`）；
- **移动端**：人工裁决**不启动**（`AGENTS.md §1` 既定路线「先桌面端」）。
