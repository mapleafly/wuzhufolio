## 1. 背景（走查实测，证据见模块记录 M12.md §7.2）

人工在真实开发库走查时发现：稳定币 USDT 平均成本显示 **1.4874**、BTC 平均成本 **125,176.63**
（真实买入价 16k–67k）、单笔卖出已实现盈亏 **−57,843.47**，而该笔交易实际是获利的。
逐事件复算定位到**同一根因**：

账户账本只有交易所成交切片（117 笔）、几乎没有入金记录（`capital_flows` 仅 1 笔 1 USDT），
早期持仓也不在账内 → 计价腿与部分币被反复打成负持仓；而 `ReplayEngine` 在**持仓 ≤ 0 期间仍按
`cost += legFiat` 累积成本**。待持仓被买回正数时，这些「没有对应数量」的成本被摊到远小于它的
数量上，平均成本随即失真，并污染**其后每一笔**卖出的已实现盈亏。

实测轨迹（引擎逐步重放）：
- USDT：负区间累积成本 21,721.99 → 2024-07-24 卖出把持仓拉回 +2,512.06 时均价跳到 **11.29** →
  后续按 1:1 稀释到 **1.4874**；
- BTC：2025-01-10 手动补买 0.2 BTC 落在 −0.18997 的空头上 → 持仓 0.01003 而成本 10,000.10 →
  均价 **997,018.94** → 2025-02-02 卖出 0.06443 BTC 的已实现 = 6,394.47 − 0.06443×997,018.94 =
  **−57,843.47**。

影响面（走查当时）：所有「导入账本缺入金 / 缺早期持仓」的账户（API 同步 + CSV 导入的常见形态），
平均成本、浮动盈亏、已实现盈亏、ROI 全部失真，且界面无任何提示。

**分级**：命中 AGENTS.md §8.1 红线 3（改已通过模块 M4 的引擎行为，属返工级）→ **C2**，
按 §8.3 mini 闭环执行（需求 → 设计 → 技术 → 返工 → 人工门），**禁止先码后补**。

## 2. 拍板结论（人工原话）

> 「拍板选甲」

固化为**方案甲的精确口径**（一句话：**负持仓只吃本金、不建成本；成本随数量归零**）：

1. **不变式**：持仓数量 ≤ 0 ⟹ 持仓成本 = 0。
2. **流入**（买入到账 / 卖出入账 / 增资 / 正差额校准）数量 `q`、折算值 `v`：
   - 当前数量 ≥ 0：`数量 += q`、`成本 += v`（与既有口径一致，不变）；
   - 当前数量 < 0（负持仓 `d = −数量`）：
     - `q ≤ d`（全部用于清偿负持仓）：`数量 += q`（仍 ≤ 0），**成本保持 0**；
     - `q > d`（穿越归零点）：只有「抬到 0 以上」的部分 `q − d` 计入成本，
       携带成本 = `v × (q − d) / q`（按数量比例拆分）；`数量 = q − d`、`成本 = 该携带成本`。
3. **流出**（卖出扣减 / 买入支出 / 撤资 / 负差额校准）：数量按比例移出成本；数量归零或转负时
   **成本同步归零**（既有 `reducePosition` 在 `out ≥ 数量` 时已等价于归零，本轮补一条防御性归一）。
4. **已实现盈亏**：仍只在「卖出时持仓 > 0」时推导（异常区段本就不推导，口径不变）；
   但归零后重建的持仓，其成本只由重建期实际支付的金额构成 → 之后的已实现盈亏回到可信区间。
5. **校准锚点**：锚点仍强制对齐数量；其流入部分按第 2 条拆分，数量被强制对齐到 0 时成本归零。

**取舍说明（为什么不是乙/丙）**：
- 乙（数量 ≤ 0 时成本直接置 0、回正时从 0 起算）会**低估**成本（卖出显示为纯获利），
  与「负持仓清偿部分本就没有成本基数」的经济含义不符；
- 丙（只做界面标注）不解决根因，失真会随成交继续累积；
- 甲在**归零点**处给出唯一确定、可解释的答案（「你为当前持有的这些币实际付了多少钱」），
  且对**正常账本（从未转负）完全不改变行为**——这是它能安全返工的前提。

## 5. 返工验收标准（= task-breakdown T4.5）

1. **不变式**：任一事件应用后，若某币数量 ≤ 0 则其成本 = 0（新增单测覆盖买入/卖出/增资/锚点四类流入）；
2. **穿越点拆分**：负持仓被一笔流入完全覆盖时，成本 = `v × (q − d) / q`（新增单测给出精确数值断言）；
3. **清偿不清零外的场景**：`q ≤ d` 时数量仍为负且成本保持 0；
4. **正常账本零回归**：从未转负的账本，全部既有黄金用例与模块用例断言**逐字不变**；
5. **轨迹一致性**：`SellRealizedTracer` 与引擎的逐笔/合计交叉校验全绿；
6. **走查场景复现**：构造「卖出未持有 → 补买回正 → 再卖出」，断言重建后均价 = 补买价、
   再卖出的已实现盈亏为正常量级（不再出现 −57,843 量级的假亏损）。
