## 1. 背景

人工在 0.1.1 使用后提出 3 条具体问题 + 1 条总体感受；其中**总体感受（组件体系缺位）是「大问题」**，
3 条具体问题恰好全部落在表现层（数值输入框、日期时间组件、`WzModal` 遮罩），
因此人工明确：**框架级调整优先，小问题随大改造一并吸收**。

**C2 判定依据（影响面决定级别，不由动词决定）**：

| 红线（§8.1） | 是否命中 | 说明 |
|---|---|---|
| 1 触 §1.1 硬约束 | ❌ | 不涉本地化/遥测/密钥/备份格式 |
| 2 改数据模型表结构或加密边界 | ❌ | 零数据层改动（M14 只改表现层） |
| 3 **改已通过模块的行为（返工级）** | ✅ | M0–M13 全部已通过；本改造替换 `ui/components/*` 实现并统一视觉基线 |
| 4 跨端影响 | ❌ | 桌面端专属；移动端 PRD 本就定 Material 3，方向一致（`跨端共享规范` 无需改） |
| 5 删除/反转已定稿需求 | ❌ | 不删需求，只改实现与视觉 |

## 2. 拍板结论

1. **路线 A**：**Material 3 打底 + token 全量映射 + 组件收口**（拒绝 Jewel 路线 B 与第三方风格库路线 C，
   理由见 ADR-007 §2.1；腾讯 ovCompose / KuiklyUI 经核查**不适用桌面端**，见调研报告 §5.9）。
2. **顺序**：先做**框架级**（主题层 → 组件层 → 日期时间/数值输入），再做零散修复；
   **DEF-54/55/56 随本改造吸收，不单独出 0.1.2 补丁版**。
3. **版本**：本次改造进 **0.2.0**（minor；0.x 语义下可含视觉/交互的破坏性变化）。
4. **阶段路径**：**关闭 P7 → 进 P8（复盘 + 定下一迭代范围）→ 以 0.2.0 走本 C2 mini 闭环** →
   P6 全量复测 → P7 发布 0.2.0。**不把界面改造挂在 P7 里做**（P7 是发布阶段，0.1.1 已上线）。
5. **零新增第三方依赖**：M3 已在依赖树，Hot Reload 为官方插件（Apache-2.0）。
