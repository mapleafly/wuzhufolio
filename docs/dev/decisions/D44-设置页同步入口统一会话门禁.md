# D44 · 设置页「API 管理」同步入口统一会话门禁（C1）

> **级别**：**C1**（人工 2026-10-10 拍板「按建议：B1/B2/B4/B5=C1，B3=C2」；B 迭代 **B4**）
> **来源**：`D43 §3` 遗留登记（「设置页『API 管理』内的同步入口未纳入统一会话门禁」）+ 全面评审 F5 确认在册
> **实施**：2026-10-10（B 迭代首项）· **模块记录**：`docs/dev/modules/M15.md` · **任务**：`T15.1`

## 1. 背景

D43（2026-09-29）已把**托盘 / 顶栏 / 后台**三条手动同步入口收敛到**唯一会话门禁**
（`BackgroundScheduler.syncNow()` → `syncOnce()` 内 `hasActiveSession()` 判定）。但**设置页「API 管理」分组**的两个入口仍直连用例层：

| 入口 | 代码位置 | 现状 |
|------|----------|------|
| 行级「立即同步」 | `ApiManagementSection.kt`（`api-key-sync-<id>`）→ `ApiManagementViewModel.syncNow(key)` → `service.syncNow(key.id)` | 直连 `ExchangeSyncService` |
| 页面级「立即同步（全部密钥）」 | `ApiManagementSection.kt`（`api-sync-all`）→ `ApiManagementViewModel.syncAll()` → `service.syncNow(null)` | 直连 `ExchangeSyncService` |

风险（低但真实）：

1. **结构上绕过 D43 建立的唯一门禁**——四条手动入口有两条不受管；
2. 若会话在页面停留期间失效（登出/切换账户），行级入口会命中用例层 `requireActive` 抛异常，
   用户看到的是**归因错误的异常文案**而非「请先登录」——与 D43 修复的托盘问题**同因**；
3. 页面级若直接改走调度器，在无会话时 `syncOnce()` 返回 `emptyList`（`BackgroundScheduler.kt:278-281`），
   会被 UI 误读为「没有可同步的密钥」——**必须入口先判**。

## 2. 拍板结论（人工 2026-10-10）

**B4 = C1**，实施口径：

1. **页面级**：`ApiManagementViewModel.syncAll()` 改经**组合根注入的执行体**（`runtime.scheduler.syncNow()`），
   与托盘/顶栏同一条路径；
2. **行级**：保持走 `ExchangeSyncService`（调度器无单 key 路径），但在**入口前置判定**会话——
   未登录只提示「请先登录」，不进入服务层；
3. **门禁判定统一为「入口前置」**（`TrayActionGate` 同法：文案直达原因，不靠数据层抛异常兜底）；
4. **文案同口径**：新增 `exchangeStrings.loginRequired`（zh「请先登录后再同步交易」/ en「Please sign in before syncing trades」），
   经 `ApiCopy.LOGIN_REQUIRED` 消费；与托盘 `DesktopNoticeText.loginRequired`（标题「请先登录」）语义一致。

> 本档是 **D43 的延伸落实**（补齐第四条入口），**不改 D43 结论**，故不按 amend 处理（`§8.5` 修订仅适用于改已登记 Δ 的结论）。
