## 1. 需求增量（`§8.3-1`）

**把「其它账户」的行情自选清单，经用户显式操作，一次性复制（导入）到当前账户。**

### 1.1 不变量（必须由代码与守护测试保证）

| # | 不变量 | 落实方式 |
|---|--------|----------|
| 1 | **仅复制自选清单本身**——`settings(account_id, key='watch.coins')` 的 cg_id 列表；**绝不复制**交易、资金流水、API 密钥、账户资料等任何其它数据 | 实现**只读/只写**该一行：读来源行 + 经既有自选服务写当前账户行；守护测试逐表断言「来源与目标的其他数据行数与内容均不变」 |
| 2 | **必须显式**：用户**选择来源账户 + 二次确认**（确认前显示将导入的币种数量/列表摘要）；**不得**做隐式跨账户可见、**不得**做「全部账户聚合视图」 | UI 两步弹层（选择 → 确认）；确认前**零服务调用**（守护用例断言） |
| 3 | **单向**：导入只写当前账户；**来源账户数据一字不改** | 来源侧**只读原始行、不做 D41 的一次性认领**（认领会写来源账户）；守护测试断言来源行**逐字节不变**、`watch.migrated` 不被置位 |
| 4 | **未登录 / 无其它账户 / 来源为空 ⇒ 类型化结果 + 可操作文案 + 零写入**；**全量重复 ⇒ 幂等提示** | `WatchImportResult` 类型化结果（`Imported` / `AlreadyComplete` / `NoSource` / `Failed`）；守护测试逐态断言「零写入」 |
| 5 | 账户级作用域由既有 `ActiveSessionStore` + 既有服务保证；**不新增表、不改 `.cpro` 格式** | 复用 D41 的账户级 settings 行（`watch.coins` 本就在账户级行内、已在 `.cpro` 范围内）⇒ **零 schema 变更、零备份格式变更** |

> **口径澄清（C0，2026-10-12，仅收窄措辞、不改行为）**：不变量 1 的「只读/只写该一行」是**写入面**的表述——
> 实现**并非**「唯一读写 settings 行」：**只读**另涉 `accounts.username`（来源/目标展示名）与 `coins` 目录表
> （symbol 解析）；不变量 4 的「零写入」指**不写自选清单本身**（不产生部分写入），**不排除 D41 认领副作用**——
> 目标侧取合并基线经 `currentStoredIdsOrNull()` → `readStoredIds` → `claimLegacyIfFirst`，
> **当前账户尚无自选行时，Reject 分支亦会物化当前账户行 + 全局 `watch.migrated`**（来源账户仍一字不改）。
> 对应 KDoc 已同步收窄（`domain/.../WatchImportService.kt` · `data/.../MarketWatchServices.kt` · `data/.../SettingsWatchImportService.kt`）。

### 1.2 不做什么（范围护栏）

- **不做**「所有账户自选聚合视图」——那会实质改变 `§1.1-5` 的「账户数据互相隔离」语义，需另立决策（**不在本次范围**）；
- **不做**任何自动/后台导入、不做导入历史、不做「删除来源自选」等破坏性选项；
- **不做**自选以外的任何跨账户搬运（交易/资金/密钥一律不涉）。

## 3. 技术增补（`§8.3-3`）

### 3.1 domain（**新增**契约，未改任何既有签名）

新增 `domain/.../market/WatchImportService.kt`：

```kotlin
interface WatchImportService {
    suspend fun listOtherAccounts(): List<AccountWatchSummary>       // 只读摘要（未登录 ⇒ 空列表）
    suspend fun importFrom(sourceAccountId: Int): WatchImportResult  // 显式一次性复制
}
```

- `AccountWatchSummary(accountId, username, cgIds, displayNames, defaultSeed)`——**只读**摘要；
  `cgIds` = 来源账户**有效**自选（原始存储序；未写入过 ⇒ 默认种子），`displayNames` 与 `cgIds` 同序同长
  （目录可解析 = symbol，缺行回退 cg_id）；
- `WatchImportResult` = `Imported(added, skipped, sourceAccountId, sourceUsername)` / `AlreadyComplete(...)` /
  `NoSource(...)` / `Failed(reason, detail?)`；`WatchImportFailReason` = `NO_SESSION` / `SOURCE_NOT_FOUND` / `WRITE_FAILED`；
- 合并语义 = **保序去重追加**（与 D35 `addCoins` 同口径）：当前账户清单为基（未写入 ⇒ 默认种子），
  来源中**尚不存在**的 cg_id 按来源序追加在末尾；已存在的**跳过**且**不打乱**既有排列。
  **来源清单先归一**（trim → 去空串 → 去重，与 `addCoins` 同口径）——摘要与导入**共用同一归一**，
  保证「弹层里看到的清单」= 「实际会导入的清单」，且手工改库/异常载荷不会把空串或重复项带进当前账户。

### 3.2 data（**新增**实现，未改既有签名）

新增 `data/.../market/SettingsWatchImportService.kt`：

- 来源侧：`settings.getAccount(sourceId, MarketWatchService.SETTINGS_KEY)` **裸读 + 解码**，
  **刻意不走** `SettingsMarketWatchService.readStoredIds`——后者会触发 **D41 的旧全局清单一次性认领**
  （写来源账户 + 置位全局 `watch.migrated`），会破坏不变量 3（**来源账户一字不改**）。损坏载荷按既有口径回退默认种子；
- 目标侧：**复用既有自选服务**取合并基线与写回（新增两个 `internal` 方法
  `currentStoredIdsOrNull()` / `persistCurrent(ids)`，**只增不改**）⇒ 目标账户的 D41 认领/编码语义与行情页**完全同源**；
- 账户列表：既有 `AccountRepository.list()`（只读）；
- **零 schema 变更、零新增表、零新增 settings 键、零 `.cpro` 格式变更**
  （`SettingsKeyNamespaceGuardTest` 无需扩表：`watch.coins` 已是登记的账户级键）。

### 3.3 app / ui

- `AppBootstrap.Runtime` + `MarketServicesBundle` 增 `watchImportService`（装配同 D44/D46 方式）；`Main.kt` 注入行情页；
- `MarketWatchPage` 增**可选**参数 `importService: WatchImportService? = null`（**不注入 ⇒ 页面行为与改造前完全一致**，
  既有 UI 测试调用点零改动）；`MarketWatchViewModel` 增 `importService` 可选参数 + 弹层状态与四个动作。

### 3.4 数据模型与备份（`data-model.md §2.3`）

**零 schema 变更**：`watch.coins` 仍是账户级 settings 行（D41）；跨账户**只读**取用口径 =

## 4. 红线核验（`§8.1`）——**命中红线 1，为何不改变隔离语义**

| 红线 | 是否命中 | 说明 |
|------|----------|------|
| 1 触及 `§1.1-5` 硬约束（多账户隔离 / 备份格式） | **✅ 命中**（人工定级即据此） | 本项**新增一条跨账户数据通路**，故必须走 `§8.3` mini 闭环 + 安全清单 §5 复核。**但隔离语义未被削弱**，理由见下 |
| 2 改数据模型表结构 / 加密边界 | ➖ 不命中 | 复用既有账户级 settings 行；零新表、零列、零索引、零迁移、零加密边界变化 |
| 3 改已通过模块的行为（返工级） | ➖ 不命中（**纯新增**） | 既有自选读写、D35 自动加入、D41 隔离与认领**行为一字未改**；既有页面在未注入新服务时行为不变 |
| 4 跨端影响 | ➖ 不命中 | 桌面端专属；移动端未启用（A 迭代启动前统一对齐） |
| 5 删除/反转已定稿需求 | ➖ 不命中 | 不删不反转；D41 的隔离要求**原样保留**，本项是其**显式例外补充**（`§8.5` 修订行） |

**「显式一次性复制 ≠ 破坏隔离」的论证**（本档核心）：

1. **默认态未变**：账户之间仍然**互不可见**——不打开本入口就**没有任何**跨账户数据通路；
   `MarketWatchService` 的读接口（`watchCoins`/`hasCustomList`）与 D41 完全一致，仍是「只看当前账户」；
2. **可见性来自用户主动、逐次、可预期的一次动作**：必须 ① 点入口 → ② 选来源账户 → ③ 看摘要后二次确认；
   **确认前零服务调用、零写入**（守护用例断言）⇒ 不存在「隐式跨账户可见」；
3. **单向且不可逆性有限**：只写**当前账户**；**来源账户一字不改**（含不触发其 D41 认领）；用户可随时在行情页移除导入的币；
4. **不提供聚合视图**：跨账户「同时可见」的形态被明确排除（`§1.2`），故 `§1.1-5` 的隔离判定口径
   （「账户 A 的数据在账户 B 的会话中默认不可见」）**依然成立**；
5. **可审计**：导入为显式用户动作，数据层记 INFO 日志（来源账户 id / 目标账户 id / 新增与跳过条数），不涉敏感内容。
