## 1. 背景（P5 人工验收实测，证据见集成报告 §11-4）

人工按 P5 验收脚本实机走查时发现三处「对不上」，逐事件复算定位到**同一根因**：

| 现象（人工实测） | 期望（票面口径） |
|------------------|------------------|
| 增资 100,000 USDT → 总览卡「可用现金 **99,964.80**」 | 100,000 |
| 卖出 0.1 BTC @ 60,000 USDT → 已实现盈亏 **999.65** | 1,000 |
| 净值/ ROI 与手算差 0.0x% | 100,000 / +1.00% |

**根因**：折算价解析链为「① 事件时刻前最近快照 → ② **USD 锚定 1:1** → ③ 最近可得快照（估算）」——
② 只是**缺价兜底**。人工账户在**增资时**尚无 USDT 快照（命中 ② → 事件值 100,000，故「投入本金」显示 100,000），
而**其后所有交易与估值都有真实市价快照**（CoinGecko USDT ≈ 0.999648）→ 命中 ①：

- 买入 1 BTC @ 50,000 → 成本基数 `50,000 × 0.999648 = 49,982.40`；
- 卖出 0.1 BTC @ 60,000 → 卖出所得 `6,000 × 0.999648 = 5,997.89` → 已实现 `999.648 ≈ 999.65`（与实测一致）；
- 可用现金 = 稳定币**市值** `50,000 × 0.999648 = 49,982.40`（与实测一致）。

即：**票面金额被系统性打 0.9996 折**，且净值随稳定币微小波动漂移（现金类资产不应如此）。

**分级**：命中 AGENTS.md §8.1 红线 3（改已通过模块 M4 的引擎行为，返工级）→ **C2**，按 §8.3 mini 闭环执行。

## 2. 拍板结论（人工原话）

> 「1. 稳定币折算口径：白名单稳定币优先 1:1 锚定（非白名单照市价）；白名单是用户可调整的吗？」

**口径（方案 B）**：

1. **USD 锚定白名单稳定币**在基础法币为 **USD** 时，折算价**恒取 1**（不再查市价快照）——
   含事件折算（成本基数 / 卖出所得 / 资金流水 base_amount / 手续费折算）与**当前估值**
   （市值 / 可用现金 / 未实现盈亏 / 24h 盈亏）；
2. **非白名单币种**（含 BTC/ETH 等）与**基础法币非 USD** 时，一律照市价快照折算（行为不变）；
3. **白名单可调整**：《跨端共享规范》名词表原文即「默认 USDT、USDC、DAI、TUSD，**可在设置中扩展**」——
   设置 → 通用 →「稳定币白名单」提供**扩展项增删**（`cash.coins` 全局键），
   默认四项**固定不可移除**（M10 T10.1 既有口径）。扩展项即刻纳入 1:1 锚定与「可用现金」判定；
4. **24h 盈亏**：锚定币恒为 0 变化（1:1 → 1:1），不再取市价快照配对——消除稳定币的无意义波动噪声；
5. **`priceAsOf`（行情时刻展示）**：仍取最近快照时刻（展示口径，不参与折算）——纯稳定币账户不丢「上次行情时刻」。

## 5. 风险与边界

1. **脱锚失真**：若某稳定币真实脱锚（如 0.95），账本仍按 1:1 展示——属**用户显式选择的口径**
   （与本产品「稳定币 = 现金代理」的定位一致）；用户可把该币**移出白名单**（仅扩展项可移除，
   默认四项不可移除——若需移除默认项，另行提报）。
2. **非 USD 基础法币**：基础法币切 EUR/CNY 时不锚定（仍按市价），因为白名单是 **USD 锚定**集合；
   如需 EUR 锚定集合，属后续增量（未提报）。
3. **24h 盈亏**：锚定币不再贡献 24h 变化（恒 0），组合 24h 覆盖数因此上升（分母含稳定币现金）。
