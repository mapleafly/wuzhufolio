## 1. 背景

- **现状**：全新账户进入「交易管理」只有一行「暂无记录」；看板/资金页全为 `--`。用户（与宣传片拍摄）
  都没有一个「开箱即用、看起来像真账本」的起点；P7 宣传片只能靠**测试夹具**造数据，观感偏「测试态」。
- **目标（B1）**：首次启动可**一键加载示例组合**并有**引导**；同时按 `B迭代 §2` 的硬要求——
  **必须显式标记 + 可一键清除**，避免示例数据与真实账本混淆。
- **不做什么**（延续复盘「明确不做」）：不引入第三方 UI 库、不新建演示专用数据模型/表、
  不做「自动加载」（**必须由用户显式点击**——避免用户把示例当成自己的数据）。

## 2. 拍板结论与实施口径

### 2.1 标记方式（关键取舍）

**结论：用 `notes` 行首统一前缀 `[示例] ` 作为示例数据的唯一识别依据**（`DemoData.MARKER`）。

| 方案 | 取舍 |
|------|------|
| **notes 前缀（采用）** | `transactions.notes` / `capital_flows.notes` **两列既有** ⇒ 零 schema、零新表、零 `.cpro` 格式变更、**零新增 settings 键**；且随 `.cpro` 备份/恢复**天然保留**（`BackupStores`/`BackupRestoreStore` 原样搬运 notes）⇒ 恢复后仍可识别与清除 |
| 新增 settings 引导标记 | 需新增设置键（`data-model` 补注 + 命名空间守卫测试扩展），且**标记的是「加载过」而非「哪些行」** ⇒ 仍需行级依据才能「只删示例行」 |
| 新增 `is_demo` 列 | 命中 `§8.1` 红线 2（改表结构）⇒ 直接升 C2，与人工定级冲突 |

- 标记**不随界面语言变化**（否则清除逻辑与历史数据识别失效）；界面上的「示例数据」徽标与引导说明
  由 UI 层 i18n（zh/en 双档）提供。备注正文（如「建仓买入 BTC」）为固定串，与数据层既有中文串
  （CSV 模板示例行备注）同口径。
- **与 i18n 守护的交互（实施期取舍）**：en 档按 `I18nCatalogTest`「英文档不得残留 CJK」的既有守护
  **不引用 `[示例]` 字面量**，改以「notes 列 / sample record」表述（首跑该守护用例拦下 en 档中的该字面量，
  已修正文案而非放宽守护）。中文档正常引用标记，用户可在备注列直接对照。
- 数据集内容（`DemoPortfolio`）：**1 笔增资 100,000 USDT + 3 笔买入（BTC/ETH/SOL）+ 1 笔卖出（BTC 0.2）**，
  金额一律 `BigDecimal`，时间轴 = 相对加载时刻的固定天数偏移（60/55/50/45/20 天前）。
  加载后账本：USDT 40,952.5 · BTC 0.8 · ETH 5 · SOL 40；累计增资 100,000；卖出已实现 **+1,983**。

### 2.2 加载口径（幂等 + 拒绝）

| 场景 | 结果 | 说明 |
|------|------|------|
| 空账户（无任何真实记录、无示例记录） | `Loaded(4, 1)` | 先写增资、再按时间升序写交易 |
| 已存在示例记录 | `AlreadyLoaded` | **幂等**：不重复写入（判据 = 存在带标记行） |
| 账户已有**非示例**交易/资金记录 | `Rejected(ACCOUNT_NOT_EMPTY)` | **一条都不写**；示例数据只在空账户可加载 |
| 未登录 | `Failed(NO_SESSION)` | 类型化失败，不抛未类型化异常 |
| 币种目录暂缺 BTC/ETH/SOL/USDT | `Failed(COIN_UNAVAILABLE)` | 离线且从未刷新目录时；UI 提示「联网刷新一次行情后重试」 |
| 被既有重放校验拦截 | `Failed(DATASET_INCONSISTENT)` | 数据集自洽性回归信号（`DemoPortfolioTest` 守护） |
| 其他落库失败 | `Failed(LOAD_FAILED)` | 失败时**回滚**本次已写入的示例行（复用 `clear()`，只删标记行） |

**为什么数据集必须自洽**：手动保存路径走 `ReplayEngine.validateMutation` **STRICT 相对校验**，
会拦「本笔新制造」的负边界 ⇒ 序列必须「先增资、再买入、卖出量 ≤ 当时持仓」。该不变式由
domain 纯函数用例（STRICT 全量重放）守护。

### 2.3 清除口径（只删标记行 + 清除顺序）

- **只删带标记行**：真实记录（无标记）**永不**被示例数据路径删除（专项用例覆盖）；
- **顺序 = 先交易、后资金**：示例增资是示例买入的余额来源 ⇒ 先删增资会被相对校验拦住（负持仓），
  先删全部示例交易则不制造负边界（空账户路径必然成功）；
- **边界（已知并已登记）**：若真实记录**依赖**示例增资（用户在示例数据之上直接记了真实买入），
  资金行删除会被既有校验拦住 ⇒ `clear()` 返回**已删条数**、**保留**该示例增资行
  （`hasDemoData()` 仍为 true），UI 给「部分清除」提示并保持标识可见。
  **任何真实记录都不会被删除**；用户需先调整/删除依赖它的真实记录再清除。

### 2.4 UI 落点（最小改动）

- **交易管理页**（`TransactionsPage`，空态 `tx-empty` 旁）：空态新增一句引导 `tx-demo-guide` +
  「加载示例数据」按钮 `tx-demo-load`；存在示例数据时在命令区下方渲染标识条 `tx-demo-banner`
  （徽标 `tx-demo-badge`「示例数据」+ 说明 + 「清除示例数据」`tx-demo-clear`）；
- **清除为破坏性动作** ⇒ 走 `WzModal` 二次确认（`tx-demo-clear-confirm`，共性约束 §7.3-1/5/7：
  同窗口就地叠加、挂在页面根、遮罩用 `pointerInput` + `detectTapGestures`（**不参与焦点、不响应键盘**））；
- **设置页「数据管理」区不改**（二选一，取改动面更小的一处）；
- 未注入 `demoService` 时页面行为与改造前**完全一致**（`TransactionsPage` 新增参数带默认值
  `null` ⇒ 独立预览与既有 17 处 UI 测试调用点零改动）。
