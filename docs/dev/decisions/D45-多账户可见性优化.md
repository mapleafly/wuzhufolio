# D45 · 多账户可见性优化（B2）：顶栏常驻账户名 + 切换确认「当前 → 目标」（C1）

> **级别**：**C1**（人工 2026-10-10 定级「按建议：B1/B2/B4/B5 = C1，B3 = C2」；B 迭代 **B2**）
> **来源**：`retrospective.md` 二轮 §2 问题 #4（「0.1.1 数据不见了」误报）教训——「**多账户产品需要更强的『当前账户』可见性**」
> **实施**：2026-10-10 · **模块记录**：`docs/dev/modules/M15.md` · **任务**：`T15.2`

## 1. 背景

复盘问题 #4：用户登录 `lifxue` 却去找 `xue` 的数据，误判「数据不见了」（只读查库定性 = 数据完好）；
行情页又因旧全局自选迁移显示着另一账户的币。教训 = **多账户产品的「当前账户」必须处处可见**。

实施前现状盘点——账户名只出现在三处：

1. 侧栏底部 `acct-chip`（用户名 + 「切换账户 / 登出」）；
2. 账户菜单弹窗（`✓ X（当前）`）；
3. 仪表盘副标题。

**缺口**：**顶栏**（任何页面常驻）没有账户标识——在行情 / 交易 / 设置页无法一眼确认自己在哪个账户。

## 2. 拍板结论与实施口径

1. **顶栏常驻账户标识**：渲染「账户 · <账户名>」（`topbar-account`），任何页面可见；
   账户名为空（未注入 / 未登录）时**不渲染**（不制造空壳）。
2. **切换确认显示「当前 → 目标」**：切换弹窗新增「当前账户：X」行（`switch-current`），
   与既有标题「切换到账户「Y」」形成对照，避免误判自己在哪个账户。
3. **切换后提示**：既有 `已切换到账户「X」` toast **已满足**，本轮不改（列为已具备项）。
4. **不做**：窗口标题带账户名（OS 标题栏）——留作可选增强（未拍板，避免扩大改动面）。

> **随行 C0（`§8.1` 勘误，不另建档）**：**顶栏账户名实为设计已定稿要求**——
> `ia.md:43`（顶栏核心元素含「当前账户名（点击展开账户菜单）」）与 `ia.md:183`
> （「账户隔离清晰：**顶栏常驻当前账户名** + 状态栏，切换账户走密码验证」）**早已写明**，此前实现缺失。
> 按 `§8.1` 判定为「纠正实现偏差、不改产品语义」⇒ **C0**：以模块勘误登记（`M15.md §5`）+ 本节留痕，
> **不改 PRD / 设计正文**。本批整体仍按人工定级的 **C1** 记账（先例：`D36` 的「随行 C0」）。
