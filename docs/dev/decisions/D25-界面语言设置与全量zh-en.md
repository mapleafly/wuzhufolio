# D25 · 界面语言设置与全量 zh/en 文案（C1 增量）

> 2026-09-11 人工拍板（M12 UI 整合收尾启动期，范围问答拍板对象 = T12.4 i18n 的实现范围）。
> 需求基线处理：`docs/prd/` 为只读基准（AGENTS.md §2），**不改 PRD 正文**；PRD §6
> 「国际化 (I18N)：支持多语言（初期支持英文、中文）」以本决策口径落地——
> 有效需求 = PRD V1.9 + `docs/dev/增量台账.md` Δ{…, D25}。

## 1. 背景

task-breakdown **T12.4** 早已要求「i18n：en/zh、UTC 存本地显、多法币、精度」，但存在两处落差：

1. **设计侧无入口**：P1 `ia.md` §2.12「设置 → 通用」分组清单（基础法币/主题/盈亏配色/默认精度/
   用户名枚举/稳定币白名单/小额阈值）**没有「语言」项**，`design-tokens.md` 与原型同样未定义；
2. **实现侧无资源层**：M2–M11 全部页面均把中文文案内联在 50 个 UI 文件里（约 620 条），
   `*Copy` 对象以 `const val` 硬编码，`ui` 模块无任何 i18n 机制。

因此「做 i18n」的实际范围有三个数量级不同的选项（新增入口 + 资源层 + 是否回改已通过模块），
按 AGENTS.md §8.4「Agent 不得自行定级自行实现」，开工前把范围作为**人工门前置问答**提报。

## 2. 拍板结论（人工选择摘录）

> 三选项：A 分层落地（本次仅新页面 + 资源层，存量另走 C1）／ **B 本次一并做全量 zh/en** ／
> C 本次不做语言切换。人工选择：**「B 本次一并做全量 zh/en：50 个 UI 文件 618 条文案全部抽取翻译
> 并回归全部 UI 测试」**。

固化为四条口径：

1. **全量覆盖**：`ui/src/main` 下全部用户可见中文文案（含既有 M2–M11 页面、Toast、错误映射、
   空态、提示）一律抽取为 zh/en 双档；**源码内联中文（i18n 目录外）为回归红线**，由
   `I18nCatalogTest` 守护（注释先剥离，KDoc 按项目约定仍为中文）。
2. **新增「界面语言」设置项**（设置 → 通用；中文 / English）：属**新增需求**，按 C1 处理——
   本决策档 + 台账登记 + 下游文档回写（见 §4）。
3. **切换即时生效并持久化**：与主题/盈亏配色同路（`ShellViewModel` → settings 全局行），
   重启后保持；语言切换触发整棵 UI 子树重建（文案是动态取值属性，非 Compose State）。
4. **落地范围与基线不变**：语言只影响**展示层**（文案 + 日期时间格式 + 数字分组），
   不改数据模型、不改加密边界、不改接口契约、不改任何已通过模块的行为语义；
   既有 zh 文案**逐字保持**（各模块由脚本比对 HEAD 验证），因此全部既有 UI 测试无需改断言。

## 5. 实现落点（摘要，详见模块记录 M12.md）

- 资源层：`ui/i18n/`（10 个模块目录 + `I18n` 持有器 + `WzFormat` 数值/时间格式化）；
- 语言档：`AppLanguage`（domain）存储于 settings 全局行 `locale`（复用 M002 迁移既有键，
  **不另立新键**；`zh-CN`/`en-US`，解析兼容 `zh`/`en` 简写）；
- 入口：设置 → 通用 → 「界面语言」（语言名以本语言书写）；
- 排序/空态/徽标等交互件同时补 a11y（键盘可达 + 焦点可见 + 按钮语义 + 无障碍标签）。

## 6. 遗留

1. **原型补行延期**（§4）：到期检查点与 DoD 见上，未到期前不得视为已完成。
2. **英文文案润色**：全量 en 由 Agent 落地（金融术语口径统一为 realized/unrealized P&L、
   calibration、watchlist、cost basis 等），建议人工在语言切换走查时抽查措辞。
3. 领域层历史中文异常正文（`CoinResolutionException.reason` 等）已按类型化方案收敛
   （见模块记录 M12.md §1.7 勘误），如后续新增领域异常请一并给出类型化原因码。
