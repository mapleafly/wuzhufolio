# D35 · 成交币自动进入「行情」自选（C1）

> **决策日期**：2026-09-24 · **级别**：**C1**（纯新增行为、无表结构/加密/接口签名变更）
> **来源**：P7 发布后 **Linux 真机验收反馈第 5 条**（`docs/test/defects.md §2.2` 增量提案）
> **人工拍板原话（三问三答）**：
> ① 用户手动从行情页删掉的币，下次同步要再自动加回来，**注意不能重复**；
> ② 超过自选上限 50 怎么处理：**不要限制自选上限**；
> ③ 只对手动交易生效，还是交易所同步来的也生效：**都生效**。

---

## 1. 背景

行情页（D21）的自选列表 `watch.coins` 此前**只由用户手动增删**：

- `SettingsMarketWatchService.addCoin/removeCoin` 是唯一写入路径；
- 账本写入（手动交易 / CSV 导入）与交易所同步**都不碰自选列表**；
- 后果：用户记了一笔 BTC 交易，行情页仍然只有默认种子（USDT），既看不到 BTC 行情，也不会被行情刷新覆盖——
  必须去行情页手动搜一次、加一次。

人工由此提出：**有实际成交的币应当自动进入行情自选**，以便后续刷新这些币的行情。

## 2. 拍板结论（C1）

### 2.1 三条口径（人工逐条确认）

| # | 口径 | 决定 | 实现落点 |
|---|------|------|----------|
| ① | 手动删掉的币会不会被「复活」 | **会**：下次同步/交易触达该币即自动加回；**不设「用户已移除」排除集**；幂等（已存在不重复写入、不打乱顺序） | `SettingsMarketWatchService.addCoins`（`distinct` + 顺序追加） |
| ② | 自选数量上限 | **取消上限**（原 `WATCH_LIMIT = 50` 与 `IllegalArgumentException` 一并移除） | 领域契约 + 数据实现 + UI「已达上限」文案下线 |
| ③ | 生效范围 | **手动交易 + CSV 导入 + 交易所同步，全部生效** | 账本服务 `saveTransaction`/`updateTransaction`/`confirmCsvImport` + 同步服务 `syncNow` |

### 2.2 实现方式（窄接口 + 装配注入）

新增数据层窄接口 **`TradedCoinSink`**（`data/market/TradedCoinSink.kt`）：

- `suspend fun accept(cgIds: Collection<String>)`，**实现必须幂等**；
- 账本服务与交易所同步服务各加一个 **默认 no-op** 的构造参数（`TradedCoinSink.NONE`），
  由 `AppBootstrap` 注入 `MarketWatchService::addCoins`；
- **失败隔离**：两处调用点统一 `runCatching`（自选维护失败**绝不允许**影响交易落账或同步结果），
  仅落 debug 日志。

为什么不让账本/同步服务直接依赖 `MarketWatchService`：两者领域不同（账本 vs 展示偏好），
窄接口还能让单测在无行情栈时照常跑（默认 no-op）。

### 2.3 触发点明细

| 入口 | 收集口径 | 何时写入 |
|------|----------|----------|
| 手动记录交易 | 该笔 base ∪ quote 两腿的 `cg_id` | `repository.insert` 成功之后 |
| 编辑交易 | 同上（编辑后仍触达） | `repository.update` 成功之后 |
| CSV 导入 | **本批实际落库**（`inserted = true`）的行的 base ∪ quote | 导入循环结束后（`CsvInsertTally.importedCoins`） |
| 交易所同步 | 本轮 `insertIfAbsent` 为真的成交的 base ∪ quote（`SyncTally.tradedCoins`） | 单 key 同步收尾 |

## 6. 验收标准（已写入 task-breakdown T12.9）

1. **A1 手动交易**：记录一笔 `BTC/USDT` 买入 → 行情页自选出现 `bitcoin`（无需手动添加）；
2. **A2 CSV 导入**：导入含 `ETH/USDT` 的 CSV → 自选出现 `ethereum`；
3. **A3 交易所同步**：同步新增成交 → 该成交的 base/quote 自动进入自选（无新增则不写）；
4. **A4 幂等**：重复触发/重复成交不产生重复条目，既有顺序不被重排；
5. **A5 删后回加**：用户移除某币后，再次交易/同步触达该币 → 自动加回；
6. **A6 无上限**：连续加入 > 50 个币不报错、不截断；
7. **A7 失败隔离**：自选写入失败（如 settings 写异常）不影响交易落账与同步结果。
