## 1. 背景（M12 走查 + P5 人工验收实测）

- M12 实测：USDC −4,204（有价）→ 净值被扣 **4,202.79**；
- P5 第二轮人工追问「负持仓怎么出现的？是不是不应该出现？」→ 分析结论：

| 路径 | 能否产生负持仓 | 依据 |
|------|----------------|------|
| 手动新增/编辑/删除交易或资金 | **不能**（引擎相对校验阻止新制造的负边界：V5 余额不足 / V7 持仓不足 / V9 重放冲突） | PRD 全局说明「重放校验规则」 |
| **CSV 导入 / 交易所 API 同步** | **能**（PRD 明确「导入路径例外：不做余额校验」） | PRD 全局说明「导入路径例外」 |
| 持仓校准 | **不能**（负差额 ≤ 本地持仓，交易所余额 ≥ 0） | PRD 全局说明「持仓校准规则」 |

即：**负持仓是「账本缺数据」的信号**（缺入金 / 缺早期成交 / 成交超出 API 500 条窗口 / 该币当时未解析被跳过），
物理上现货不存在负头寸；PRD 附录 A 用例 6 的修复闭环即为「导入卖出 → 负持仓标记 → 补录增资 → 异常消除」。

## 2. 人工原话与结论

> 「2. 行情的负持仓其负市值 选B不计入。」

**口径（方案 B）**：

1. **Δ持仓数量 < 0 的币种**，其市值**不计入净值**，也**不计入可用现金**（两处口径必须一致，
   否则现金与净值自相矛盾）；
2. 被排除的金额合计单列 `PortfolioMetrics.anomalousExcludedFiat`（负值），
   **仪表盘显式提示**：「⚠ N 个币种持仓为负…其市值 −$X 未计入净值与可用现金；补录增资、补导入历史或
   执行持仓校准后自动恢复」（不做隐式扣减，也不静默忽略——避免被读成「净值虚高」）；
3. **币种行自身仍展示负市值**与「持仓异常」徽标（透明可见，便于定位数据缺口）；
4. 数量 ≥ 0 的币种行为完全不变（含缺价币不计入的既有口径）；D26 的成本不变式不受影响。

## 4. 风险与边界

1. **净值可能"看起来偏高"**：排除负市值后净值不再被异常币拉低——由 §2-2 的显式提示 + 行内负值共同兜住透明性；
2. **总收益/ROI** 随净值联动（同一恒等式），不另设口径；
3. **校准/补录后自动恢复**：异常消除 → 该币市值重新计入（无需手工干预）。
