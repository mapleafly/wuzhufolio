## 1. 背景

P6 人工门第四轮 Windows 走查报出两条**纯键盘**使用问题（`docs/test/manual-test-guide.md §11`）：

1. **DEF-20**：「记录增资」币种候选 /「添加交易」交易对候选，用键盘选中后候选行消失，**焦点掉出弹窗**——
   再按 Tab 从**侧边栏第一项**重新开始；交易表单里要连选 3 次候选（基础币 / 计价币 / 自定义手续费币种），
   每次都掉一次焦点。
2. **DEF-21**：回车选中侧边栏项后焦点**仍停在侧边栏**，要再按约 7 次 Tab（穿过侧边栏其余项与顶栏）才进页面；
   焦点进入页面后**没有任何回到外壳循环的出口**；侧边栏内方向键也不移动焦点。

PRD §6 无障碍基线要求「桌面端支持全键盘导航（Tab 焦点顺序合理、核心操作可达）」；
`keyboard-walkthrough.md §6 改进提案 A` 已登记该改法，人工在第四轮走查中直接给出方向（要求「回车进页面内容 +
方向键/Esc 可回外壳循环」）。

## 2. 拍板结论

### 2.1 DEF-21 → **C1**：焦点流（本次新增行为）

1. **回车进页面内容**：切页 / 进入币种详情子页 / **对当前页项再次回车** → 焦点交给页面内容
   （页面槽挂 `focusRequester`，挂**非可聚焦容器**；Compose 语义 = 焦点落到子树内**第一个可聚焦控件**）。
   容器**不得**加 `.focusable()`——那会多出无焦点环的 Tab 停靠点（DEF-13 教训）。
2. **Esc / ↑ / ↓ 回外壳**：页面内**未被页面控件消费**的 Esc / ↑ / ↓ → 焦点回到侧边栏**当前页项**
   （此后 ↑/↓ 可在导航项间走、Tab 可到顶栏），恢复完整「侧边栏→顶栏→页面」循环。
3. **侧边栏 ↑ / ↓**：在导航项之间移动焦点（顺序 = `NAV_FOCUS_ORDER`：六个一级页 + 组件走查页）。
4. **三条护栏（缺一不可）**：
   - 页面退出走**冒泡阶段**（`onKeyEvent`）而非 preview —— 输入框光标移动、下拉/列表导航等**已消费**的方向键不受影响；
   - **弹层打开时不接管**（`WzOverlayRegistry.openModalCount > 0` 时让出）—— 否则焦点会跑到弹层背后，
     弹层还开着而键盘已无法操作（Esc 归弹层）；
   - 带 **Ctrl / Alt / Meta** 的组合键不接管 —— 留给 P8 全局快捷键（提案 B）。

### 2.2 DEF-20 → **C0 勘误**（随行落地，不另建档）

候选行由 `clickable` 提供唯一焦点目标，选中后候选清空 → 焦点目标消失 → Compose **无处恢复** → 回落窗口根。
属**实现未达 `AGENTS.md §7.3` 键盘可用性强制项**的实现偏差，非产品语义变更 → 按 C0 处理：
**选中后显式交接焦点**（资金 币种 → 数量；交易 基础币 → 计价币、计价币 → 价格、自定义手续费币种 → 原字段；
`WzSelect` 候选 → 触发框）。模块勘误登记见 `docs/dev/modules/M7.md` / `M8.md` §勘误。

- **提案 B · 全局快捷键**（`Ctrl+1..6` 切页、`F5` 刷新行情、`Ctrl+B` 备份）：PRD 未要求，登记 P8 评估；
