# D51 · macOS 进发布范围（**C1**，**反转** 2026-09-22 与 2026-10-13 两条口径）

> **决策号**：D51 · **日期**：2026-10-14 · **级别**：**C1**（**发布范围与文档**：CI 已在产出 macOS 构件，本决策**零代码改动**；但**反转两条既有口径**，故按 `§8.5` 附影响面扫描 + 逐处回写）
> **来源**：人工 **2026-10-14** 澄清（原话要点）——「**不办证发 macos**」⇒ 准确含义 = **不采购 Apple Developer 证书、但把 macOS 产物放进 Release**；并**已知悉并接受**「**无真机验证**」这一残差风险
> **关系**：**反转** ①`certificate-procurement.md §0`（2026-09-22「不采购任何证书、**macOS 不发布发行包**」）②`certificate-procurement.md §0` 2026-10-13 复核注（「**维持原口径 A**」）
> **流程**：`AGENTS.md §8.5`（影响面扫描 + 逐处同步）；`D50`（0.4.0 范围）把实施任务登记为 **`T16.5`**

**为什么现在可以发**：`D50` 的 ② 交付（「平台 × 场景 × 通道」投递矩阵）**要求把 macOS 纳入矩阵**；而 macOS 长期不进发布范围会使该矩阵缺一列。人工据此决定「发、但如实标注未验证」，把**验证责任转移给用户反馈**（文档显式声明，不含任何「已通过 macOS 验证」的表述）。

## 2. 架构口径核实（**事实，非推断**）

### 2.1 结论

> **CI 当前产出的 macOS 产物为 `arm64`（Apple Silicon）only —— Intel Mac 无法运行**（arm64 二进制不能在 Intel 上执行；Rosetta 只做 x86→arm，方向相反）。

### 2.2 证据链（逐条可复核）

| # | 证据 | 出处 |
|---|---|---|
| 1 | 打包作业矩阵含 `macos-latest`（另两个 = `ubuntu-latest` / `windows-latest`） | `.github/workflows/ci.yml:117` |
| 2 | **工件名实测**：`./portable/WuZhuFolio-portable-macos-arm64.zip`（145,828,409 B · sha256 `06ae9675…`）—— 文件名中的 `arm64` 由 `arch=$(uname -m)` 生成，即**运行器实测架构 = arm64** | `ci.yml:305`（`arch=$(uname -m)`）+ CI run `38364147657` 的 `wuzhufolio-macos-latest-artifacts-manifest` |
| 3 | 同 manifest 实测另外两件：`./dmg/WuZhuFolio-1.0.0.dmg`（150,944,496 B · `a1a7e8c6…`）· `./pkg/WuZhuFolio-1.0.0.pkg`（145,665,677 B · `de551d90…`） | 同上（0.3.0 期实测值，**仅供口径参考，非 0.4.0 发行哈希**） |
| 4 | 打包任务为 `:app:packageDistributionForCurrentOS` ⇒ jpackage **只产出宿主架构**包，**无交叉编译** | `ci.yml:168-176` · `app/build.gradle.kts:24`（`macOS → Dmg + Pkg`） |
| 5 | `macos-latest` 为 Apple Silicon（arm64）运行器镜像；Intel 侧镜像 `macos-13` 已停用，替代标签为 `macos-15-intel` | **外部来源（非本仓）**：GitHub Changelog「macOS 13 runner image is closing down」(2025-09-19) · `actions/runner-images` issue #13045（macOS 15 Intel 镜像）⇒ **标签可用性建议在 CI 上实测一次再定** |

### 2.3 命名口径（**必须写进 §2 平台/产物命名表**）

macOS 产物的文件名**不带应用版本**（`0.3.0` / `0.4.0`），而用 **bundle 版本 `1.0.0`**：

- 成因：Apple 规定 `CFBundleVersion` 首段不得为 0（jpackage 会报 `The first number in an app-version cannot be zero or negative`）⇒ `app/build.gradle.kts:181-190` 显式 `packageVersion = "1.0.0"` + `packageBuildVersion = "1"`；
- 表现：Release 附件将出现 **`WuZhuFolio-1.0.0.dmg` / `WuZhuFolio-1.0.0.pkg`**（与同批 `WuZhuFolio-0.4.0.msi` 形成**版本号不一致**），另有 `WuZhuFolio-portable-macos-arm64.zip`（含架构、不含版本）；
- 要求：**Release 说明必须保留一句**说明该差异（`release-plan.md §2` 已有对应注，本决策要求**补 macOS 已解除排除**的口径）。

### 2.4 Intel 支持候选（**待人工拍板**）

| 候选 | 做法 | 代价 | 风险 |
|---|---|---|---|
| **(a) 仅 arm64（推荐）** | 文档明确「**仅支持 Apple Silicon（M 系列）**」；Intel 用户走「源码自编译」既有路径 | **0**（零 CI 改动） | Intel 用户无法用官方包（可接受，已在文档声明） |
| **(b) 增 Intel 产物** | CI 打包矩阵增 Intel 标签（`macos-15-intel`，**可用性待实测**），产出第二套 `dmg`/`pkg`/`zip`（命名需区分 `arm64` / `x64`） | 中（CI 时长 + 工件体积翻倍；`§2` 命名表与 `SHA256SUMS` 相应扩展） | 标签/计费待核实；**仍无真机验证**，等于多一个未验证平台 |
| (c) universal binary | `lipo` 合并两套 runtime | **高**（jpackage 不直接支持；需自建后处理） | 收益低于成本 ⇒ **本轮不建议** |

## 3. 发布口径（未签名 / 未公证 / 未真机验证）

1. **必须显式标注**（Release 说明 + 用户指南 + `README`）：「**未签名 · 未公证** ⇒ 首次打开需 **右键 → 打开**（或「系统设置 → 隐私与安全性 → 仍要打开」）放行」；
2. **不得**出现任何「已在 macOS 验证 / 已测试」的表述；`manual-test-guide.md §23` 的 macOS 章节**只列用户可自查项**，不虚构结论；
3. **不新增任何网络行为**（`§1.1-2` 零遥测不受影响）；不内置自动更新（沿用既有口径）；
4. **签名/公证链路保持「占位待用」**：`ci.yml:120-128` 的 secrets 注入分支**不删**，将来办证后**零代码改动**即可启用（本决策**不**采购证书）。

## 5. 风险与缓解

| # | 风险 | 影响 | 缓解 |
|---|---|---|---|
| 1 | **Gatekeeper 拦截**（未签名/未公证） | 用户以为包坏了 | Release 说明 + 用户指南**首屏可见**的「右键 → 打开」步骤；FAQ 补条目 |
| 2 | **未签名被安全软件误报** | 信任损耗 | 显式声明未签名 + 提供 `SHA256SUMS` 供校验；不承诺「绝不误报」 |
| 3 | **arm64-only** | Intel 用户无法使用 | 文档明确机型要求；Intel 用户走既有「源码自编译」；如人工选 §2.4(b) 则后续补 x64 产物 |
| 4 | **无真机验证** | 平台专属缺陷（托盘/钥匙串/窗口）可能直达用户 | ① 发布说明显式声明「未验证」② `§23.6` 引导用户自查与反馈 ③ 缺陷按 `§8.4` 提报 → 定级 → 必要时 **0.4.1 patch** 或**撤资产**（§4-5） |
| 5 | **命名混淆**（`1.0.0.dmg` vs `0.4.0.msi`） | 用户下载时疑惑 | `release-plan §2` 差异句 + Release 说明一句 + `README` 注明 |
| 6 | 支持成本（无法复现的 macOS 问题） | 维护负担 | 以「已知限制」登记；不阻塞主线 |
