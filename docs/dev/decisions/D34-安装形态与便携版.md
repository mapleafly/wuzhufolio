## 1. 背景

### 1.1 现象与根因（已在 CI 上实证，非推测）

人工门第十轮：Windows 安装版双击图标 → jpackage **原生启动器**弹窗 `Failed to launch JVM`（不是 Java 异常、
与应用代码无关；安装版自带 jlink 私有 JRE，故机器上的 Temurin 21 与本问题无关，ADR-006 §1.1）。

Agent 在 CI（干净 Windows runner）上对**同一份打包产物**做三组路径对照实验：

| 变体 | 路径 | 结果 |
|------|------|------|
| ASCII | `D:\a\wuzhufolio\…\app\WuZhuFolio\WuZhuFolio.exe` | ✅ PASS（`bootstrap ok \| build=0.1.0+fe6a795 \| schema=12`） |
| latin1 | `…\wzf-café-path\…`（`é` 在该机 ANSI 代码页 CP1252 **可表示**） | ✅ PASS |
| cjk | `…\wzf-非ASCII路径\…`（中文在 CP1252 **不可表示**） | ❌ **FAIL：2 秒内 `exitCode=2`、零应用日志**（与人工门现象同型） |

另用 **Temurin 21** 重新打包后同样 `ascii=PASS / cjk=FAIL` ⇒ **换 JDK 修不掉**（实验 job `probe-jdk21-nonascii`）。

**结论**：jpackage 的 Windows 原生启动器在**安装路径含系统 ANSI 代码页无法表示的字符**时，无法加载随包
`runtime\bin\server\jvm.dll`。ASCII 路径与「该代码页可表示」的非 ASCII 字符均正常。

### 1.2 为什么必须改安装形态（而不是改一个路径参数）

`man jpackage` 明确：**`--install-dir` 在 Windows 只接受「安装根下的相对子路径」**（如 `Program Files`、`AppData`）。
因此**per-user 安装无法摆脱默认根 `%LOCALAPPDATA%\<用户名>\…`** —— 用户名非 ASCII 时必然踩坑，
单纯设置 `installationPath` 治不了本。可选路径只有三条：改安装范围（per-machine → `C:\Program Files\…`）、
放开让用户自选（不可控）、或提供不依赖安装器的**便携版**。

## 2. 拍板结论（C1）

### 2.1 安装形态改为 per-machine，并关闭安装目录选择页

`app/build.gradle.kts`：

```kotlin
windows {
    perUserInstall = false   // 默认安装目录 = C:\Program Files\WuZhuFolio（任何区域设置下都是纯 ASCII）
    dirChooser = false       // 关闭目录选择页：避免用户选到非 ASCII 目录再次触发同一崩溃
    // shortcut/menu/upgradeUuid 维持不变
}
```

- **代价**：安装/卸载需要管理员确认（UAC）——这是桌面应用的常规形态；无管理员权限或需要自定义位置的用户
  改用 **§2.2 便携版**。
- **旧 per-user 安装的处置**：per-user → per-machine 不属同一升级路径（即便 `upgradeUuid` 不变），
  **须先卸载旧的 per-user 版本再装新版**（写入手册安装步骤与 §4 影响面）。
- **不采用的选项**：`installationPath` 设绝对 ASCII 路径（Windows 语义不支持，见 §1.2）；
  升级打包 JDK（实验已排除）；仅靠文档提醒用户「别用中文目录」（不可控）。

### 2.2 新增「便携版」产物（三平台）

jpackage app-image 直接压缩为便携包，**解压即用、无安装器、不写注册表**（数据仍在 `~/.wuzhufolio`）：

| 平台 | 产物（CI artifact `wuzhufolio-<os>-native` 内） | 用法 |
|------|-----------------------------------------------|------|
| Windows | `portable/WuZhuFolio-portable-windows-x64.zip` | 解压到**纯 ASCII 路径**（如 `D:\WuZhuFolio`）→ 双击 `WuZhuFolio.exe` |
| Linux | `portable/WuZhuFolio-portable-linux-x64.tar.gz` | 解压 → 运行 `bin/WuZhuFolio` |
| macOS | `portable/WuZhuFolio-portable-macos-<arch>.zip` | 解压 → 运行 `WuZhuFolio.app` |

包内含 `LICENSE.txt` 与 `README-portable.txt`（含「请解压到纯英文路径」提示）。

### 2.3 预防项（随行 C0，人工已追认）

`.github/workflows/ci.yml` 在产物上传**之后**新增三段观察期非阻断冒烟：

1. **打包版启动冒烟**（ascii / latin1 / cjk 三组路径，判定串 `PACKAGED_LAUNCH_SMOKE*`）；
2. **安装版实跑冒烟**：MSI 静默安装 → 断言 exe 落在 `C:\Program Files\WuZhuFolio` → 实跑 → 卸载
   （判定串 `INSTALLED_LAUNCH_SMOKE`，验收 §6 的 A3/A4）；
3. 按需实验 job `probe-jdk21-nonascii`（仅当提交信息含 `[probe-jdk21]`）。

探针脚本 `scripts/probe-packaged-launch.ps1` 亦可人工在本机复跑；现场取证用
`scripts/diagnose-packaged-launch.ps1`（只读 + 启动探针）。

## 6. 验收标准（同时写入 task-breakdown T12.8）

| 编号 | 验收项 | 证据 |
|------|--------|------|
| A1 | Windows 安装包默认装到 **纯 ASCII** 路径 `C:\Program Files\WuZhuFolio`，安装向导**无目录选择页** | CI `package-windows-latest` 的安装版实跑冒烟输出「安装目录 = C:\Program Files\WuZhuFolio」；人工安装确认无目录页 |
| A2 | 安装版在**非 ASCII 用户名的机器**上可正常启动（不出现 `Failed to launch JVM`） | 人工在中文用户名机器安装复验（`manual-test-guide.md §16` 四步取证全绿） |
| A3 | 安装版冒烟：从已安装目录启动并写出 `bootstrap ok` | CI 判定串 `INSTALLED_LAUNCH_SMOKE=True` + 探针输出 |
| A4 | app-image 冒烟三组路径结论稳定（ascii/latin1 PASS、cjk FAIL 作为**已知限制**留档） | CI 判定串 `PACKAGED_LAUNCH_SMOKE*` |
| A5 | 三平台均产出便携版包且**解压即用**（Windows：解压到 ASCII 路径双击 exe；Linux：`bin/WuZhuFolio`） | CI artifact `portable/*`；人工 TC-MAN-11 |
| A6 | 便携版不写注册表、不改数据位置（数据仍在 `~/.wuzhufolio`），卸载 = 删除目录 | 人工 TC-MAN-11 取证（`reg query HKCU\...\Run` 无项；数据目录时间戳更新；删除目录后无残留） |
| A7 | 冒烟失败**不阻断**产物上传（观察期口径） | CI step `continue-on-error: true` + 上传步骤在冒烟之前 |

## 7. 未纳入本次（登记 P8）

- **彻底消除启动器的 ANSI 路径限制**：自建启动器/自定义 WiX 引导（替代 jpackage 启动器）——成本高，待该限制在
  上游 jpackage 修复或确有用户诉求时再评估；当前以「per-machine 默认 ASCII + 便携版」覆盖。
- **MSI/EXE 代码签名**：P7 采购证书后启用（未签名产物更易被杀软拦截，属同一「安装即用」体验链路）。
- **安装包体积优化**（jlink 裁剪 + 字体子集化）：P7 携带项。
- **自动更新**：PRD 明确 MVP 不内置检查更新。
