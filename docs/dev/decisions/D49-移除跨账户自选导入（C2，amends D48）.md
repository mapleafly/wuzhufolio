# D49 · 移除「自选清单跨账户显式导入」（**C2**，`amends D48`）

> **决策号**：D49 · **日期**：2026-10-13 · **级别**：**C2**（人工 2026-10-13 走查后裁决「**A. 完全移除**」）

> **关系**：**废止 `D48`**（`D48-自选跨账户导入（C2）.md`，2026-10-10）；台账按 `AGENTS.md §8.5` 追加修订行，**不覆盖** D48 原行
> **流程**：`AGENTS.md §8.3` **C2 mini 闭环**——需求（本档）→ 设计 → 技术 → 返工（代码与测试彻底删除）→ **停人工门**

## 1. 背景

### 1.1 人工走查判定（2026-10-13，`manual-test-guide.md §22.4`）

人工在 **2026-10-13** 走查 **0.3.0 / B 迭代**清单（`docs/test/manual-test-guide.md §22`）的 **B3 项**
（「自选清单跨账户显式导入」）后裁决 **A. 完全移除**。人工原话要点：

> 「行情页不应该有『从其他账户导入』功能，这会暴露其他账户的交易品种。」

### 1.2 实测暴露证据（走查期已实测，非推测）

**来源列表对「每一个其它账户」直出币种摘要**——`ui/.../i18n/MarketStrings.kt:151-152`
（`fun watchImportSourceSummary(count: Int, names: String)`）在行情页弹层里逐账户渲染形如
「**3 个币种：BTC、ETH、USDT**」的摘要（zh 档 `:305` 实现、en 档 `:452` 实现）。

- **暴露面**：只要有第二个账户，打开行情页 → 点入口 → **一次性看到全部其它账户的自选币种符号**，
  无需知道对方密码、无需任何二次确认；
- **大于需求原口径**：`D48 §1.1-2` 只要求「**二次确认前**展示将导入的币种数量/列表摘要」——
  而实现把摘要放在了**第一步的来源列表**（选来源之前），即「确认」这一道门并未保护到摘要本身；
- **对账户隔离的实际影响**：自选清单是 D35「**成交币自动进入自选**」的落点，因此其它账户的自选
  ≈ **该账户交易过的币种集合**（`D35` / `D41` 口径）⇒ 该摘要实质暴露了其它账户的**交易品种**。

### 1.3 为什么不靠「收窄文案」而是「完全移除」

三条备选与人工裁决：

| 方案 | 内容 | 判定 |
|------|------|------|
| A | **完全移除**该功能（含入口、弹层、服务契约、测试、文案） | ✅ **人工裁决采纳（2026-10-13）** |
| B | 保留功能，把摘要挪到二次确认之后 / 只显示数量不显示币种 | ✖ 未采纳：仍存在「跨账户自选通路」，`D41` 的严格隔离口径仍需开例外 |
| C | 保留功能但加审计/提示 | ✖ 未采纳：不解决「其它账户交易品种可见」这一根因 |

**采纳 A 的核心理由**：`D41`（自选改账户级）的立档根据就是 `§1.1-5`「**账户间严格互不可见**」。
`D48` 在当时把这条例外论证为「隔离语义未削弱」（`D48 §4`），但走查证实**摘要本身即是跨账户可见面**
⇒ 例外的前提不成立。**账户间严不严、有没有显式确认，都不能成为跨账户自选通路存在的理由。**

## 2. 拍板结论（人工 2026-10-13）

1. **完全移除**「自选清单跨账户显式导入」——入口、弹层与其状态、领域契约、数据实现、装配注入、
   zh/en 文案键、以及全部守护用例，**一处不留**（不留死代码 / 死文案 / 死用例）；
2. **`§1.1-5` 回到严格口径**：账户之间**严格互不可见**，**不存在任何跨账户自选通路**
   （既无隐式可见、也无显式导入、无聚合视图）；
3. **不新增任何替代功能**：本次是**净删除**，不引入「导出/导入文件」「匿名化复制」等变体；
4. **数据不动**：`D48` 实施期**已导入**的自选是**普通账户级自选数据**（`settings(account_id,key='watch.coins')`），
   **不回滚、不清库、不做标记**——用户可在行情页按既有「移除」逐条删除；
5. **`D41` 不受影响**：自选仍为**账户级**、仍有**一次性认领**（首个访问账户认领旧全局行）、
   未登录仍为空集且不可写、仍随账户级 settings 进 `.cpro`。
