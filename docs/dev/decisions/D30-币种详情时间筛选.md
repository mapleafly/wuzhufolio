# D30 · 币种详情交易记录补「时间」筛选维度

> **决策号**：D30（`AGENTS.md §8.6`：从 D23 起连续编号）

## 1. 背景

PRD 故事 3.4（单币种资产详情）验收 4：

> 「交易记录列表支持按**交易所、交易类型、时间**进行筛选和搜索。」

P6 用例覆盖扫描（TC-A3.4-4 / TC-F2.2-2）发现：币种详情页实现了**交易所 + 交易类型 + 搜索**三个维度
（`ui/portfolio/CoinDetailPage.kt` 筛选区），**缺「时间」维度**——而交易管理页有时间筛选需求、资金页已有
四档时间筛选（`FundDateRange`：全部 / 近 30 天 / 30–90 天 / 90 天以上）。属**验收标准少一项维度**。

## 2. 拍板结论（人工 2026-09-14）

**按建议本轮补做（C1 mini 闭环）**：在币种详情交易记录区增加**时间档位筛选**，口径与资金页**完全一致**
（复用 `domain/ledger/FundDateRange` 四档 + `contains(time, now)` 纯规则），不做时间区间自定义输入
（MVP 不做区间选择器——与资金页保持同一交互，避免两页筛选语义分叉）。

## 5. 验收标准（进 task-breakdown）

1. 币种详情交易记录区出现**时间档位**筛选，档位与资金页一致（全部时间 / 近 30 天 / 30–90 天 / 90 天以上）；
2. 切换档位后列表**即时**（无需手动刷新）按交易时间过滤；与交易所/类型/搜索三维可**叠加**；
3. 无匹配行时显示既有空态（「暂无交易记录」/列表空占位），不出现异常；
4. 英文界面下档位文案为英文（i18n 双档守护覆盖）；
5. UI 测试：`PortfolioPagesUiTest::coin detail filters transactions by time range` 绿；**去掉过滤实现该用例必红**（已实证）。
