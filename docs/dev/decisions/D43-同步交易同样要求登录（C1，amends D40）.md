# D43 · 托盘「立即同步交易」同样要求登录（**C1**，`amends D40`）

> **决策号**：D43 · **日期**：2026-09-29 · **级别**：**C1**（人工拍板；属 D40 的口径延伸，不反转任何请求层行为）
> **修订**：**`amends D40`**（D40 §6「遗留 / 待人工确认」第 1 条：交易同步是否同样要求登录 → **本档给出结论**）
> **来源**：人工 2026-09-29 指令——「托盘『立即同步交易』也应该和『立即刷新行情』一样，不登录不能执行；
> 同步所需的交易所 Key 归属于账户而不是全局，所以只有登录账户才能同步交易」
> **关联**：`D40` · `task-breakdown M14/T14.11` · `interaction.md §1.6` · 用户指南 §3.5/§5.8

---

## 1. 背景（核查结论，2026-09-29）

人工提出要求后，Agent 先做核查（**先查证、后动手**），四条路径逐一验：

| 路径 | 会话门禁 | 未登录是否发请求 / 碰账户 Key | 核查结论 |
|---|---|---|---|
| 后台周期同步 `syncLoop` → `syncOnce()` | ✅ 有（P6 §7-6 既有） | 否 | ✅ 符合 |
| **托盘「立即同步交易」** `AppHost.syncFromTray()` → `scheduler.syncNow()` → `syncOnce()` | ✅ 有（同一条门禁） | 否 | ⚠️ **数据层符合，交互层不符合** |
| **顶栏「立即同步」** `TopBarSyncViewModel` → `runtime.exchangeSyncService.syncNow()`（**直连用例层，绕过门禁**） | ❌ 无 | 否——用例层 `requireActive()` 抛异常 | ⚠️ 未登录实际不可达（顶栏仅在登录后的主壳内），但**结构上绕过了唯一门禁** |
| 用例层 `DefaultExchangeSyncService` | ✅ `requireActive()` 兜底 | 否 | ✅ 符合 |

**Key 归属核实**：`api_keys` 表含 `account_id`（**账户级**）；同步用例一律经 `sessions.requireActive()` 取会话
⇒ 未登录**在物理上不可能**读到任何账户的 Key、也不可能发出同步请求。

**因此本次要修的不是「会不会联网」，而是两处交互/结构问题**：
1. 未登录点托盘「立即同步交易」会先弹「**正在同步交易数据…**」（误导），随后因结果为空弹
   「**没有可同步的密钥** · 尚未添加交易所 API 密钥」（**归因错误**——真实原因是未登录，而设置页只有登录后才进得去，
   用户会卡在走不通的指引上）；
2. 顶栏入口直连用例层，**绕过了调度器的唯一会话门禁**。

## 2. 拍板结论

**托盘上的两个联网动作一律以「会话已解锁」为前提，入口先判、文案直达原因**：

| 动作 | 未登录时 | 已登录时 |
|---|---|---|
| 立即刷新行情（D40） | 不发请求；提示「请先登录——登录后才能刷新行情。」 | 正常执行 |
| **立即同步交易（D43）** | **不进入任何同步路径**；提示「请先登录——登录后才能同步交易数据。」 | 正常执行 |

**理由（口径统一）**：交易所 Key 归属账户 ⇒ 未登录没有可同步的主体；
且与 D40 的隐私口径（登录前不产生外联）一致 ⇒ 两条入口**行为对称**。

**结构加固（同批实施）**：顶栏「立即同步」改为经**调度器**执行（组合根注入 `scheduler.syncNow()`），
使**托盘 / 顶栏 / 后台**三条入口共用**唯一门禁**（`BackgroundScheduler.syncOnce` 的 `hasActiveSession` 判定）。

## 5. 验收标准

1. 未登录点托盘「立即同步交易」：**不出现**「正在同步交易数据」；提示为「请先登录——登录后才能同步交易数据。」；
2. 未登录点托盘「立即刷新行情」：行为不变（D40 口径）；
3. 日志出现 `tray sync ignored | session locked`，且**无**任何同步相关调用；
4. 已登录时两个动作行为不变；
5. 顶栏「立即同步」经调度器执行（代码结构上不再直连用例层）；
6. 既有回归全绿（含数据层「无会话跳过同步」既有用例）。
