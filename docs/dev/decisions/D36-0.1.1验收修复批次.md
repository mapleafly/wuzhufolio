## 2. 四项 C1 的结论与影响面

### 2.1 DEF-48 · 托盘图标显示不全 → **图标资产统一 + 安全边距 + 按宿主尺寸出图**

- **根因**：`TrayIcon` 是 M11 期的**程序化占位图**，64×64 位图上**满幅**绘制（无透明安全边距），
  由 `setImageAutoSize(true)` 交给面板缩放到 16–22px → 四角/笔画被裁；且托盘未使用 P7 的正式图标资产。
- **落地（一轮 → 二轮）**：一轮只加 `PADDING = 0.08` 安全边距（**人工复测仍显示不全**）；二轮经真机像素取证后改为：
  ① `TrayIcon.awtImage(px)` 产出**实体 BufferedImage**（Compose 的 `Painter.toAwtImage` 是惰性 `PainterImage`，
  AWT 会按自己的缩放栅格化）；② `preferredTraySizePx()` = **AWT 报告值 ÷ 屏幕缩放**（夹取 16–64；本机 24÷2 = 16）；
  ③ `AwtTrayHost` 的 `autoSize` 由策略决定。**平台分叉**：Linux/X11 用「逻辑尺寸 + `autoSize=false`」；**Windows/macOS 维持 0.1.0 行为（64px + `autoSize=true`，由系统按 DPI 缩放）**——Linux 的二次缩放问题源自 XEmbed，原生托盘不存在，套用会导致高 DPI 下图标偏小发糊。实测矩阵与截图证据见 `defects.md §2.2/§2.3`。
  **打包图标与托盘图标仍是同一枚标记**（同一几何，`scripts/generate-icons.mjs` 同源）。
- **影响面**：`app/tray/TrayIcon.kt`、`app/AppHost.kt`、新增 `app/tray/TrayIconTest`（边距/中心/尺寸三例）。
- **未纳入**：Linux 原生 SNI/AppIndicator 路径（ADR-001 已列 dorkbox 备选）→ P8。

### 2.2 DEF-49 · 托盘菜单缺「刷新行情」且同步无可见反馈 → **加项 + 可见反馈通道**

- **根因**：① 菜单只有三项（打开主界面/立即同步/退出）；② **同步确实执行了**（`AppHost` → `scheduler.syncNow()`），
  但唯一反馈通道是 AWT `TrayIcon.displayMessage`，在 GNOME（XEmbed → SNI 代理）下**没有承载** → 表现为「点了没反应」。
- **落地**：
  - 菜单四项：打开主界面 / **立即同步交易** / **立即刷新行情** / 退出（行情与交易分列——两类 API 独立，PRD §1.1-4）；
  - 新增 `NoticeDelivery`：**Linux → 应用内提示窗**（`DesktopToastWindow` + `TrayNoticeCard`，右下角、置顶、不抢焦点、3.2s 自动消失）；
    **Windows/macOS → 保持原生气泡**（0.1.0 行为不变）；
  - 手动动作给**开始 + 结果**两段反馈（`DesktopNoticeText.manualSyncStarted/manualSyncNoKeys/manualRefreshStarted/manualRefreshFinished/manualActionFailed`）。
- **影响面**：`ui/tray/TrayMenuContent.kt`、`ui/tray/TrayLabels.kt`、`ui/tray/TrayNoticeCard.kt`（新）、
  `ui/i18n/ShellStrings.kt`（`trayRefreshQuotes` zh/en）、`app/tray/TrayMenuWindow.kt`、
  `app/tray/DesktopToastWindow.kt`（新）、`app/tray/NoticeDelivery.kt`（新）、`app/tray/DesktopNoticeText.kt`、`app/AppHost.kt`。
- **测试**：`TrayMenuContentUiTest`（四项 + 四个回调）、`NoticeDeliveryTest`、`DesktopNoticeTextTest`（+5 例）。

### 2.3 DEF-51 · 币种候选「排序未用市值排名 + 三处口径不一」→ **统一排序 + 统一组件**

- **根因（已用真实数据复现）**：`SqlCoinCatalog.search` 排序键 = 相关性 → ACTIVE → **symbol 字母序** → name 字母序，
  **完全未使用已有的市值排名缓存**；`usdt` 命中 131 条、其中 **49 条 symbol 恰为 `USDT`** → 真 Tether 排第 42 位
  （`btc` 第 1 名竟是 Big Tom Coin、`eth` 把 Ethereum 挤到第 6、`sol` 前 6 无 Solana）。
  另：交易表单 `take(6)` 且**不可滚动**、资金/校准 12 条可滚、行情页 20 条可滚；默认币置顶只有资金路径有。
- **落地**：
  - `SqlCoinCatalog.search` 排序键插入 **`rankProvider.rankOf(cgId)` 升序**（未入前 1000 名排后；离线未热时自动退化为原行为，无新网络请求）；
  - 新增 `PinnedCoinSearch`（**资金与交易两条路径共用**）：目录检索 + 默认币（USD→`tether`、其他法币→`usd-coin`，PRD §9.8）命中即置顶 + 先放大 50 条再裁剪；
  - 新增统一组件 **`CoinSuggestionList`**（上限 20、**一律可滚动** + 可见滚动条、行 = `symbol · name · cgId`），
    交易表单三个字段 / 资金表单 / 校准弹窗全部接入；行情页候选浮层本已符合（20 + 滚动），仅共享同一排序口径。
- **影响面**：`data/catalog/SqlCoinCatalog.kt`、`data/catalog/PinnedCoinSearch.kt`（新）、
  `data/ledger/DefaultFundService.kt`、`data/ledger/DefaultTransactionLedgerService.kt`、
  `ui/components/CoinSuggestionList.kt`（新）、`ui/ledger/{TransactionFormModal,FundFormModal,CalibrationModal}.kt`、
  `ui/ledger/FundsCopy.kt`（去掉 `MAX_CANDIDATES`）。
- **测试**：`SqlCoinCatalogTest`（排名打破同名并列 / 未入榜排后）、`PinnedCoinSearchTest`（6 例）、
  `TransactionsPageUiTest`（第 7 条存在 + 第 20 条滚动可达 + 行含 cg_id）。

### 2.4 DEF-52 · Ubuntu 图标为通用齿轮 → **窗口图标 + 桌面条目关联 + 图标主题**

- **根因（解包 + 实跑双重取证）**：① `Window(...)` 从未设置 `icon=`，jpackage `cfg` 亦无
  `-Dsun.awt.application.icon` → **`_NET_WM_ICON` 完全缺失**（本机 `xprop` 实测 `not found`）；
  ② 已安装 `.desktop` 用**绝对路径** `Icon=/opt/.../WuZhuFolio.png`、**无 `StartupWMClass`**、`Categories=Unknown`；
  ③ 图标**未进图标主题**（`/usr/share/icons/hicolor/*/apps/` 无本应用）、`postinst` **不刷新**图标缓存/桌面数据库。
  三者叠加 → GNOME 顶部栏/Dock/应用网格回落通用齿轮。
- **落地**：
  - **代码**：`AppHost` 的 `Window(icon = TrayIcon.painter(WINDOW_SIZE))` → 提供 `_NET_WM_ICON`（这条单独即可修好运行期图标）；
  - **打包**：新增 `scripts/patch-linux-desktop-integration.sh`（.deb 后处理，**已用线上 0.1.0 `.deb` 实测通过**）：
    `.desktop` 改 `Icon=wuzhufolio` + `Categories=Office;Finance;` + 追加 **`StartupWMClass=com-wuzhufolio-app-MainKt`**（实测 WM_CLASS，见下注）；
    从 `wuzhufolio.ico` 抽 8 档尺寸装进 `hicolor/<N>x<N>/apps/`；
    `postinst` 追加 `update-desktop-database` / `gtk-update-icon-cache`（缺失静默跳过）；`dpkg-deb --build` 重新打包；
  - **CI**：package job（Linux）在原生打包后执行该脚本并**校验三个字段 + hicolor 512 图标**（缺一即失败）。
- **影响面**：`app/AppHost.kt`、`scripts/patch-linux-desktop-integration.sh`（新）、`.github/workflows/ci.yml`、
  `docs/release/release-plan.md`（发布步骤补一步）、`ADR-006`（分发口径）。
- **未纳入**：rpm / AppImage 的同类补齐（本机无 rpmbuild、AppImage 无桌面条目）→ P8；GNOME 原生 SNI 托盘路径 → P8。

> **StartupWMClass 取值订正（2026-09-24 复核）**：首版误取 `WuZhuFolio`（`xprop -name WuZhuFolio` 命中的是窗口框架
> mutter-x11-frames，不是客户端窗口）；改用 `_NET_CLIENT_LIST` + `_NET_WM_PID` 反查后实测
> **打包版 WM_CLASS = `com-wuzhufolio-app-MainKt`**（AWT 取主类名，`.`→`-`；app-image 与 `.deb` 安装版一致）。
> 另：`-Dsun.awt.X11.XWMClass=WuZhuFolio` **实测无效**（JDK 21）→ 不保留死配置，`.desktop` 直接写实测值。
