## 3. 经验（可复用的做法）

1. **平台约束要用真实缺陷换**：`AGENTS.md §7.3` 每一条（就地叠加层、打开即聚焦、弹层挂页面根、保存类状态一致）都源自一次真实事故；
   本次新增第 7 条（遮罩禁令 + 真实按键验收）同理——**约束条目 = 事故的复利**。
2. **验收手段决定缺陷发现率**：`performTextInput` 绕过真实键盘事件 → DEF-56 在 748 用例全绿的情况下依然漏到用户手上。
   **测试注入路径 ≠ 用户输入路径**，凡涉键盘/IME 必须补真实按键用例。
3. **「已通过模块」不等于「不用再看」**：M0–M13 全部通过，界面仍然被用户判为「笨拙」——**质量门衡量的是"有没有坏"，不是"好不好"**。
   设计层面的欠账需要单独的质量维度（本次以「D37/ADR-007 组件体系 + 人工目视对照区」补上）。
4. **换框架之前先确认"框架是否已在手里"**：调研 16 个候选后发现最优解是**已在依赖树里的官方 M3（稳定版 1.9.0，63 个组件族）**；
   真正缺的是「token 全量映射 + 组件收口」这两件工程活。**先做证据（jar/依赖解析/源码）再谈选型**，避免为"换而换"。
5. **零新增依赖是可能的**：本次界面体系改造未引入任何第三方库（M3 已在依赖树，Hot Reload 为官方插件 Apache-2.0），
   把风险面压到最低。

## 3. 经验（可复用的做法）

1. **先查证、后动手**（D43 范式）：用户提出"同步也该要求登录"后，先做**四条路径核查表**——结论是"请求层本就符合（不发请求），不符合的是交互文案与顶栏绕过门禁"。
   **把"要不要改"建立在证据上**，避免把已正确的部分返工一遍。
2. **C2 mini 闭环跑得通**：D40/D41 都是"决策档（含影响面扫描）→ 数据模型/迁移方案 → 返工 → 验收"，
   其中 D41 还给出了**降级口径**（`rollback.md §4.1.1`）与**迁移认领策略**（旧全局行一次性认领）。**大改动按增量做、不重做全局**这条路是对的。
3. **测试守卫会主动帮你**：`SettingsKeyNamespaceGuardTest` 在 D41 改键归属时立刻报错（要求登记账户级键 + 命名空间不冲突），
   逼出了"历史全局键只读例外"这一显式设计；`SnackbarPointerProbeTest` 把"M3 Snackbar 吞点击"锁成守护结论。
   **凡"有意偏离官方组件"的决定，都写一条守护测试**。
4. **把 UI 里的判定抽成纯函数才可测**：`TrayActionGate.lockedNotice(...)`（行情/同步共用）——
   `AppHost` 内的判定无法单测，抽出来就能锁两态。**"想测但测不到"通常等于"该抽一层"**。
5. **视觉回归自动化收益高**：4 页 × 2 主题 × 3 尺寸 = 24 张真实分辨率渲染（`runSkikoComposeUiTest(size=…)`，非裁剪），
   与**影片素材采集复用同一条链**（`VisualRegression.captureFilmAsset`）——一套渲染，三处用途（回归 / 视觉基准 / 宣传素材）。
6. **文档-代码同步靠"逐处回写清单"**：D41/D42/D43 都列了影响面表并逐项打勾（`data-model` / `api-contracts` / `interaction` / 用户指南 / AGENTS.md / 台账），
   改完再跑 `grep` 抽查残留。**文档脱节不是态度问题，是缺清单**。
7. **发布链要可复现**：本机产物（deb/便携版/AppImage）+ `SHA256SUMS` + 与 CI 自带校验和**逐位比对一致** + 打包产物**冒烟**（隔离数据目录启动）；
   宣传片给了 `render-0.2.0.sh` / `mix-0.2.0.sh` 一键脚本。**下一个人（或下一轮的我）能原样重跑**。
