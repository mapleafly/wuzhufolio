## 3. 经验（可复用的做法）

1. **平台约束要用真实缺陷换**：`AGENTS.md §7.3` 每一条（就地叠加层、打开即聚焦、弹层挂页面根、保存类状态一致）都源自一次真实事故；
   本次新增第 7 条（遮罩禁令 + 真实按键验收）同理——**约束条目 = 事故的复利**。
2. **验收手段决定缺陷发现率**：`performTextInput` 绕过真实键盘事件 → DEF-56 在 748 用例全绿的情况下依然漏到用户手上。
   **测试注入路径 ≠ 用户输入路径**，凡涉键盘/IME 必须补真实按键用例。
3. **「已通过模块」不等于「不用再看」**：M0–M13 全部通过，界面仍然被用户判为「笨拙」——**质量门衡量的是"有没有坏"，不是"好不好"**。
   设计层面的欠账需要单独的质量维度（本次以「D37/ADR-007 组件体系 + 人工目视对照区」补上）。
4. **换框架之前先确认"框架是否已在手里"**：调研 16 个候选后发现最优解是**已在依赖树里的官方 M3（稳定版 1.9.0，63 个组件族）**；
   真正缺的是「token 全量映射 + 组件收口」这两件工程活。**先做证据（jar/依赖解析/源码）再谈选型**，避免为"换而换"。
5. **零新增依赖是可能的**：本次界面体系改造未引入任何第三方库（M3 已在依赖树，Hot Reload 为官方插件 Apache-2.0），
   把风险面压到最低。
