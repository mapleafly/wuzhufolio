## 1. 产品定位与三条卖点

WuZhuFolio 是一款**以隐私和安全为核心、数据完全本地化的加密资产组合追踪工具**。它帮你在同一个界面里看清分散在多个平台的资产、资金进出与真实投资回报（ROI），并支持在同一台电脑上管理多个互相隔离的账户。

登录页写着它的一句话定位：**数据本地化 · 零遥测 · 开源 AGPL-3.0**。展开就是三条卖点：

1. **数据本地化（数据主权保障）**：所有数据 100% 本地存储，绝不上传至任何服务器。交易记录、API 密钥、资金流水只存在你自己的电脑上。
2. **零遥测**：不内置任何遥测、统计上报或第三方分析 SDK；不收集邮箱、不收集设备标识、不收集持仓（详见 §7.2）。
3. **开源 AGPL-3.0**：源码公开、经 GitHub Releases 分发，任何人都可以审计它到底做了什么（详见 §12）。

**它不做的事**：不替你在交易所下单交易；不做税务报告；不通过钱包地址跟踪链上资产；不做组合分享等社交功能；不提供行情 K 线、技术指标等专业图表。本产品是「跟踪与分析工具」，不是交易工具。

## 2. 系统要求

| 平台 | 支持版本 | 安装包形态 |
|------|----------|------------|
| Windows | Windows 10 / 11（x64） | `.msi` / `.exe` 安装版；便携版 `.zip` |
| macOS | ⛔ **不提供发行包**（需 Developer ID 签名 + Apple 公证，本项目不采购证书） | 可**从源码自行编译**（见 §3 ②，需 macOS + JDK 17） |
| Linux | x64 桌面发行版（Ubuntu 22.04 / 24.04 等） | `.deb` / `.rpm` / `.AppImage`；便携版 `.tar.gz` |

- **无需安装 Java**：安装包内已捆绑裁剪过的私有运行时，双击即可运行，不会用到（也不依赖）你机器上已有的 Java。
- **硬件**：双核 CPU、4 GB 内存即可；登录解密耗时控制在 2 秒以内。安装体积约 80–150 MB（内含私有运行时的代价）。
- **显示**：建议 1280×800 及以上；1024×768 也可正常使用，此时部分表格需要左右横向滚动才能看到最右侧的列。
- **网络**：可选。只有「刷新行情」与「同步交易」需要联网，其余功能离线可用（见 §10.5）。

## 3. 获取与安装

### 3.1 从哪里下载

官方唯一下载渠道：**GitHub Releases** — <https://github.com/mapleafly/wuzhufolio/releases>。发布页同时提供各产物的 **SHA256 校验清单**，下载后可自行核对文件完整性；请不要从第三方站点下载安装包。

### 3.2 四条安装路径

**① Windows 安装版（`.msi`，另有内容一致的 `.exe` 安装器）**

1. 双击 `.msi`（或 `.exe`）→ 系统弹出管理员确认（UAC）→ 点「是」。
2. 安装向导**没有目录选择页**：安装位置固定为 `C:\Program Files\WuZhuFolio`（纯英文路径）。
3. 安装完成后，从开始菜单或桌面图标启动。

> 这是「per-machine」安装（装给整台机器），安装与卸载都需要管理员确认。⚠️ 如果你装过更早的旧版本（旧版默认装在 `%LOCALAPPDATA%\WuZhuFolio`），请**先卸载旧版再装新版**——两者不是同一条升级路径。

**② macOS —— 不提供官方发行包，可从源码自行编译**

0.1.0 **不发布 macOS 安装包**：macOS 应用在商店外分发需要 Developer ID 代码签名与 Apple 公证（否则会被 Gatekeeper 拦截），本项目当前不采购签名证书。**需要 macOS 版的用户可以自己编译**（需要一台 macOS 机器）：

```bash
# 1) 安装 JDK 17（Temurin）
brew install --cask temurin@17

# 2) 获取源码并编译（首次会下载 Gradle 依赖）
git clone https://github.com/mapleafly/wuzhufolio.git
cd wuzhufolio
./gradlew :app:packageDmg        # 生成 .dmg → app/build/compose/binaries/main/dmg/
# 或者只生成可直接运行的 app-image：
./gradlew :app:createDistributable
```

自编译产物**未签名、未公证**：首次打开请**右键点图标 → 选「打开」**（或在「系统设置 → 隐私与安全性」里点「仍要打开」）放行，之后可正常双击启动。功能与 Windows / Linux 版一致，数据同样只存在本机 `~/.wuzhufolio`。

**③ Linux（`.deb` / `.rpm` / `.AppImage`）**

```bash
# Debian / Ubuntu
sudo dpkg -i wuzhufolio_0.1.0-1_amd64.deb      # 缺依赖时执行 sudo apt -f install
# 之后从应用菜单启动，或运行 /opt/wuzhufolio/bin/WuZhuFolio

# Fedora / RHEL 系
sudo rpm -i wuzhufolio-0.1.0-1.x86_64.rpm

# AppImage（免安装）
chmod +x wuzhufolio-0.1.0-x86_64.AppImage
./wuzhufolio-0.1.0-x86_64.AppImage
# 无 FUSE 的环境改用：APPIMAGE_EXTRACT_AND_RUN=1 ./wuzhufolio-0.1.0-x86_64.AppImage
```

**④ 三平台便携版（解压即用）**

- 文件名：`WuZhuFolio-portable-windows-x64.zip`、`WuZhuFolio-portable-linux-x64.tar.gz`、`WuZhuFolio-portable-macos-<架构>.zip`；解压到**纯英文目录** → 运行目录里的 WuZhuFolio 可执行文件。
- **不需要管理员权限**，不写注册表，不在解压目录里产生任何用户数据；你的数据同样保存在 `~/.wuzhufolio`（Windows：`%USERPROFILE%\.wuzhufolio`）。
- 「卸载」= 直接删除解压出来的那个目录。

### 3.3 两条强制提示（请务必先读）

> ⚠️ **提示一：安装或解压路径请使用纯英文（ASCII）路径**
>
> 打包器生成的启动器在「安装路径含系统代码页无法表示的字符」（例如中文用户名、中文目录名）时，无法加载随包的运行时，表现为启动时弹出 `Failed to launch JVM`，并且没有任何应用日志。这是打包工具上游的已知限制，**不是数据损坏，也与你机器上有没有装 Java、装的是哪个版本无关**。
>
> - Windows 安装版的默认路径 `C:\Program Files\WuZhuFolio` 已规避该问题；
> - **便携版的目录由你自己选，请务必用英文路径**（例如 `D:\WuZhuFolio`）；
> - 万一遇到该弹窗，处理办法见 §10.7。

> ⚠️ **提示二：备份文件（`.cpro`）的密码强度 = 你凭证保护强度的上限**
>
> 备份包用你**自己设置的备份文件密码**加密。该密码一旦忘记，备份里的数据（包含交易所 API 密钥）就无法找回——本产品不上传、不存储任何密码，官方也没有任何解密后门。
>
> 另外，备份密码过弱等于给 API 密钥配了一把弱锁，因此应用要求备份密码**至少 8 位且包含字母与数字**。请使用足够强的密码，并把 `.cpro` 文件放在安全的地方。

### 3.4 首次启动

启动后应用会自动创建数据目录（位置见 §7.1）。如果系统钥匙串不可用，启动时会弹出一次「安全提示」，属预期降级行为，说明见 §10.1。

## 4. 首次使用

### 4.1 创建账户

1. 首次启动且本机没有账户时，自动进入 **创建新账户** 页。
2. 填 **用户名**：不能为空，且在同一台电脑内不能与其他账户重名。它只是本机账户名，不会上传到任何地方。
3. 填 **密码**：至少 8 位且包含字母与数字；输入过程中会显示强度指示（**弱 / 中 / 强**）。
4. 再次输入 **确认密码**；两次不一致会提示「两次输入的密码不一致」。
5. 可选勾选 **记住我（会话令牌存入系统钥匙串）**：下次启动自动恢复会话（密码本身永不落盘）。多人共用一台电脑时建议不勾选。
6. 点 **创建账户**。

### 4.2 风险确认（必须勾选）

创建时会弹出「风险确认」窗口，正文是：

> 密码是数据的唯一钥匙，本产品不上传也不存储密码，忘记密码将无法恢复任何数据；请妥善保管密码并定期备份。

勾选 **我已了解上述风险**，再点 **确认创建**。不勾选无法完成创建——这是刻意的硬门控。

### 4.3 初始化向导：四种方式任选

创建成功后进入「欢迎使用 WuZhuFolio」向导，四张卡片：

| 方式 | 做什么 |
|------|--------|
| **手动添加交易** | 逐条录入买入 / 卖出记录，构建初始持仓 |
| **CSV 导入** | 导入交易所导出的 CSV 批量历史（可先下载标准模板） |
| **关联交易所 API**（推荐） | 填 Binance 只读密钥，保存后立即执行首次同步 |
| **从备份恢复** | 从 `.cpro` 备份文件恢复全部数据 |

也可以点 **稍后再说，直接进入仪表盘**，之后随时在应用内继续。

> **「从备份恢复」的前置**：必须先有目标账户，恢复的数据会归入该账户。向导出现时账户已经建好，所以直接进「设置 → 数据管理」选择 `.cpro` 文件即可。

### 4.4 「忘记密码」意味着什么

登录页点 **忘记密码**，会看到：

> 本产品无法找回密码。若记得某次备份使用的密码，可通过该备份恢复数据；否则数据不可恢复。

> ⚠️ **本地无后门**：数据在本机加密，没有云端账号、没有找回邮件，官方也无法解密你的数据。唯一的保障是「记得密码」+「有可用备份」。

## 5. 功能导览

主界面由以下几部分组成：

- **左侧边栏**：仪表盘 / 资产列表 / 交易管理 / 资金管理 / 行情 / 设置（共六页）。
  > ⚠️ **0.1.0 已知问题**：该版侧边栏最下方**多出一个「组件走查」页**（开发用的界面组件预览，不是产品功能）。
  > 它**不读取也不修改你的任何数据**（只演示按钮/弹窗等控件样式），点开后不会有任何数据变化；
  > 日常使用**请忽略该项**，将在下一版本移除。
- **左下角账户区**：头像 + 账户名 + 「切换账户 / 登出」。点它打开账户菜单：**切换账户**、**修改密码**、**登出**。切换账户必须输入目标账户密码。
- **顶栏**：当前页面标题、行情数据源徽章（如「数据源：CoinGecko · 上次成功 09:41」）、**刷新行情**、**立即同步**、☾ / ☀（明暗主题快捷切换）。
- **底部状态栏**：网络与同步状态、代理指示（「代理：系统代理」或「直连」）、行情源、上次价格时间、同步结果；距上次备份超过 30 天时会显示「建议备份」。

键盘操作：`Tab` / `Shift+Tab` 在控件间移动；在侧边栏项上按 `Enter` 后焦点直接进入页面内容；页面内未被控件消费的 `Esc` 或 `↑`/`↓` 会把焦点交回侧边栏。

### 5.1 仪表盘（登录后的默认页）

**这页做什么**：一眼看清总资产、收益与资产构成。

- 总览卡片：**总资产净值**、**24 小时盈亏**、**总投资回报率 ROI**、**投入本金（净）**、**可用现金余额**、**总收益**、**累计已实现盈亏**。
- 看懂这些数字：
  - 资产净值 = 全部币种持仓按现价折算基础法币后的合计；**持仓为负的币种不计入**；
  - 总收益 = 净值 + 累计撤资 − 累计增资；ROI = 总收益 ÷ 累计增资 × 100%；累计增资为 0 时 ROI 显示「--」并提示先记录增资；
  - 24 小时盈亏 = Σ(当前持仓数量 × 当前价) − Σ(当前持仓数量 × 24 小时前价格)，只反映价格变动；部分币种缺少 24 小时前价格时会剔除这些币种并标注「覆盖 N/M 个币种」，全部缺失时显示「--」；
  - 可用现金余额 = 稳定币白名单内币种持仓的合计（USDT 恒按 1:1 折算，白名单内其他稳定币按市价折算）。
- **资产分布**环形图：市值低于「小额币种阈值」的币种会合计归入「其他」；单击扇区会高亮并浮窗显示该币种的持有数量、总资产占比、持有量市值。
- 页面顶部可能出现提示行（没有提示就是一切正常）：
  - 「⚠ N 个币种持仓为负…其市值 … 未计入净值与可用现金」→ 见 §10.3；
  - 「⚠ N 个币种暂无行情，其市值未计入净值与 ROI」→ 点 **立即刷新行情** 重试；
  - 「⚠ N 个币种的历史持仓曾为负（账本缺少入金或早期记录），其中平均成本与已实现盈亏不可靠」。
- 右侧「安全与隐私」卡：本地存储、零遥测、分层密钥、只读权限、最近备份时间；想立刻更新价格就点 **立即刷新行情**（顶栏也有 **刷新行情**），不点也会按设置的频率自动刷新。

### 5.2 资产列表

**这页做什么**：看每个币种持有多少、成本多少、赚亏多少。

- 顶部总览卡与仪表盘同源；下方表格列：**币种 / 持有数量 / 平均成本 / 当前价 / 总市值 / 总浮动盈亏 / 累计已实现**。
- 默认按市值降序；**单击表头**按该列排序。
- **单击任意一行** → 打开「币种资产详情」（§5.3）。
- 行内可能出现的徽标：**持仓异常**（该币持仓为负）、**成本不可靠**（该币历史持仓曾为负，平均成本与已实现盈亏为重建期口径）、**估算中**（价格待联网回填）、**无行情**（行情源未收录该币，不计入总市值）。

### 5.3 币种资产详情

**这页做什么**：单个币种的完整账目。

- 顶部汇总：当前持有价值、占总资产比例、平均成本、总浮动盈亏、累计已实现盈亏。
- 中部「该币种交易记录」：按 **交易所**、**类型**（买入 / 卖出）、**时间**（全部时间 / 近 30 天 / 30–90 天 / 90 天以上）筛选，另有搜索框；卖出记录行显示该笔已实现盈亏。
- **以交易所余额校准持仓**：只有该币种的全部记录都来自同一个交易所的只读 API 同步时才显示。点它 → **生成校准预览**（依据交易所、本地持仓、交易所余额、差额、校准时市价）→ **确认校准**；差额视同系统生成的资金操作（正差额 = 增资语义、负差额 = 撤资语义），**不产生盈亏**，结果可在本页「校准历史」与「资金管理」列表查看（类型显示为「校准」）。若该币种存在多个数据来源，入口会隐藏并提示；行情完全不可用时不允执行校准。
- 左上角 **← 返回资产列表** 回到列表。

### 5.4 交易管理

**这页做什么**：录入与维护买入 / 卖出记录。

- 命令区：**＋ 添加交易**、**修改交易**、**删除交易**、**导入交易 (CSV)**；搜索框（币种 / 交易所）与「按类型筛选：」。
- 表格列：交易对 / 类型 / 价格 / 数量 / 手续费 / 总价 / 交易所 / 时间 / 已实现盈亏 / 操作。每行都有 **编辑**、**删除** 快捷入口。

**新增一笔交易**

1. 点 **＋ 添加交易**。
2. 填 交易所、交易对（输入 `BTC`、`ETH` 会按币种目录自动补全；目录未收录的币种可手输并标「无行情」）、类型（买入 / 卖出）、价格、数量。
3. 手续费可手填，也可点 **自动计算手续费（交易所 > 全局费率）**，按设置的费率算出并填入；手续费币种默认「计价币种」，也可选「基础币种」或「自定义币种」（第三币种，如用 BNB 抵扣）。
4. **总价（实时）** 随价格 × 数量自动计算。
5. 交易时间按本地时区输入（内部统一按 UTC 保存与换算）。
6. 点 **保存**，列表立即刷新，持仓与成本自动重算。

**修改 / 删除**

- 选中一行点 **修改交易**；选中多行点 **删除交易**，会弹确认框「将删除 N 条交易记录并重算持仓成本与盈亏，是否继续？」，确认后执行且**不可撤销**。

**看不到已实现盈亏？** 卖出记录行的「已实现盈亏」显示「--」，表示该笔卖出时没有可用的成本基数——通常是更早的买入没有导入（交易所只读 API 只返回最近 500 条成交），或该币种持仓为负（异常区段）。用 CSV 补录更早的历史即可恢复。

**CSV 导入**

1. 点 **导入交易 (CSV)** → 可用 **下载标准模板** 拿到列格式，或直接选交易所导出的 CSV。
2. **选择文件** → **解析并预览**，查看「影响摘要（解析预览）」：新增 N 条 · 疑似重复 N 条 · 未解析 N 条 · 格式错误 N 条，以及涉及币种与导入后持仓变化概览。
3. 遇到歧义 ticker 时，在「歧义 ticker 消歧」区域点选正确候选（名称 / 市值）；选择结果会被记住，后续相同资产自动复用。
4. 点 **确认导入**。导入完成后持仓与成本重算。
   - 交易所 CSV 的日期时间按 UTC 解析；交易对以法币计价时（如 BTC/USD）按 1:1 归一化处理（USD → USDT）。
   - 建议先记录增资或补录历史，否则可能出现「持仓异常」（§10.3）。

### 5.5 资金管理

**这页做什么**：记录资产怎么进、怎么出，以及校准产生的差额。

- 顶部两张卡：**可用现金余额**（现金类币种 = 稳定币白名单）、**投入本金（净）**（= 累计增资 − 累计撤资）。
- 命令区：**＋ 记录增资**、**－ 记录撤资**、编辑、删除；搜索框（币种 / 来源 / 备注）与「按日期筛选：」（全部时间 / 近 30 天 / 近 90 天 / 更早）。
- 列表是混合列表，类型为 **增资 / 撤资 / 校准**；列：类型 / 币种 / 数量 / 折算金额 / 日期 / 来源 去向 / 备注。
- **记录增资**：填 币种（限稳定币或其他加密货币；输入法币代码会提示「法币不入账：请改为记录兑换后实际到账的稳定币」）、数量、日期时间、来源（可选）、备注（可选）。表单内实时显示「折算基础法币（记录时行情价）」；离线时显示「待定价」，联网后自动补算。
- **记录撤资**：同样表单，填「去向（撤资）」；数量超过该币种持仓会被阻止并提示「XX 持仓不足，无法撤资」。
- **删除**：弹确认框「将删除 N 条资金记录并重算投入本金与 ROI，是否继续？」，确认后重算，**不可撤销**。
- 增资 / 撤资本身**不产生盈亏**，只改变对应币种持仓数量与投入本金；**校准** 类型的记录不可编辑、只能删除，它来自币种详情页的持仓校准（§5.3）。

### 5.6 行情

**这页做什么**：看自选币种的现价；只有只读行情，不含交易与图表。

- 默认显示稳定币白名单（现金类币种）。在 **搜索币种（coins 目录）** 框输入如 `BTC`、`usdt`、`ethereum` 检索，点候选的 **添加** 加入自选；自选会持久保存（重启后仍在），上限 **50** 个，点行的 **移除** 可删除。
- 表格列：**币种 / 现价（基础法币）/ 数据源 / 更新**。数据源可能显示 `COINGECKO`、`COINMARKETCAP`（兜底）或「无行情」（暂无该币价格，现价显示「--」）。
- 顶部有 **立即刷新行情** 与数据源指示；页面可见期间按「行情刷新频率」自动轮询，离开页面即停。
- 想配置数据源 Key 或调整频率：设置 → 行情与同步。

### 5.7 设置

设置页分九个分组：

- **通用**：基础法币（计价与折算基准，默认 USD）、主题（明 / 暗）、**界面语言**（中文 / English，即时生效）、盈亏颜色方案（绿涨红跌（默认）/ 红涨绿跌 / 色盲友好（蓝涨橙跌）；数值始终显示 +/- 符号，颜色只作辅助）、默认精度、登录页用户名枚举（关闭后登录页用户名改为纯手动输入）、稳定币白名单（默认 USDT，可添加扩展项；白名单币种合计计入「可用现金余额」）、小额币种阈值（低于阈值的币种在环形图归入「其他」，0 = 不启用）。
- **网络**：系统代理（默认自动检测并使用操作系统代理；关闭则全部直连，状态栏显示当前连接方式）。
- **托盘与后台**：关闭窗口最小化到托盘、开机自动启动（默认关闭）、同步完成/失败通知、备份提醒（距上次备份超过 30 天提醒导出备份）。
- **行情与同步**：行情刷新频率（5 / 15 / 30 分钟，默认 5 分钟；托盘驻留期间按同步间隔降频）、API 同步间隔（交易数据，15 / 30 / 60 分钟，默认 30 分钟）、**行情数据源（CoinGecko API Key）**（不填 = 使用无 Key 公共 API，开箱即用；填自己的 Key 后切换专属额度）、**行情兜底（CoinMarketCap API Key）**（可选；主源失败时兜底）。
- **日志与诊断**：**查看日志**（日志已脱敏，账户名与金额部分遮蔽）、**导出日志**（导出前会提示检查敏感信息）、**生成诊断报告**（应用/OS 版本、schema 版本、最近日志片段、调用计数；不含密钥与完整响应体）。
- **手续费**：全局默认费率（买入 / 卖出分别设置）+ 交易所费率（覆盖全局）。自动计算手续费时按「交易所 > 全局」匹配。
- **API 管理**：已保存的密钥列表（别名 / 交易所 / 隐藏的 Key / 最后同步 / 状态），**＋ 添加 API（Binance 只读）**、**立即同步**，以及「最近同步记录」。详见 §6。
- **数据管理**：备份、恢复、明文导出（§8）。
- **关于**：版本、开发者信息、隐私政策、行情数据源说明、无遥测声明。

### 5.8 托盘与后台

- 关闭主窗口默认**最小化到系统托盘**（可在设置里改为关窗即退出）；托盘菜单：**打开主界面** / **立即同步** / **退出**。
- 托盘驻留期间会按「API 同步间隔」自动同步交易数据，并按同一间隔降频刷新行情；同步完成或失败会发送桌面通知（可关闭）。
- **开机自启是设备级设置**，与登录状态无关：先登出再关机，开机后应用照样启动并驻留托盘（但会停在登录页，需要输入密码）。
- Linux 桌面若没有托盘宿主（GNOME 需安装 AppIndicator 扩展），应用会**降级为「关窗即退出」**，不会把窗口藏起来找不回来。

## 6. 两类 API 的区别（别搞混）

| | 行情数据 API | 交易所只读 API |
|---|---|---|
| 用途 | 拉取币价、写价格快照、计算市值与盈亏 | 拉取你账户的成交记录，导入本地账本 |
| 提供方 | CoinGecko（主源，可不填 Key）/ CoinMarketCap（兜底，需自己的 Key） | Binance（当前版本） |
| 需要的权限 | 公开行情数据 | **只读**（读取账户与成交） |
| 配置位置 | 设置 → 行情与同步 | 设置 → API 管理 |
| 是否必需 | 否（不填 Key 也能用公共 API） | 否（纯手动录入 / CSV 也可以记账） |

两类 API **互相独立**：各自的定时任务、各自的频率、各自的日志。行情刷新失败不影响交易同步，反之亦然。

> ⚠️ **绝不要给提现或交易权限**：在交易所创建 API Key 时只勾选「读取」。带提现或交易权限的密钥一旦泄露，可以直接造成资产损失。

- **密钥怎么存**：交易所密钥以字段级加密（AES-256-GCM）保存在本机；添加 / 编辑时会提示「该 API 将关联当前登录账户」，保存后请**清理系统剪贴板**（剪贴板历史云同步是真实的泄露面）。行情数据源 Key 同样加密后只存本机，且**不进备份包**。
- **备份里的密钥**：交易所只读密钥会随 `.cpro` 备份一起打包（导出时用你的备份密码重新加密），所以备份文件要按敏感文件保管（§8.1）。
- 交易所只读 API 只返回**最近 500 条成交**；更早的历史请用 CSV 导入补录。
- 保存密钥后应用会**立即执行首次同步**；若密钥已保存但首次同步没成功，会提示「密钥已保存；首次同步未成功（原因）。可点『立即同步』重试」——此时密钥是保存成功的，直接重试即可。
- 同步是**增量追加**：按「交易所 + 订单号」去重，只导入本地没有的新成交，**不会覆盖或改写你手动录入的记录**。注意：同一笔真实交易若「先手写、后同步」会各存一行，导致重复计入持仓与盈亏；处理办法是删掉手写那一行后重新同步，或先同步再补录差异。

## 7. 数据与隐私

### 7.1 数据存在哪里

- **数据目录**：Linux / macOS 为 `~/.wuzhufolio`；Windows 为 `%USERPROFILE%\.wuzhufolio`。
- 目录内容：加密数据库 `wuzhufolio.db`；密钥材料（系统钥匙串可用时存钥匙串，不可用时为本地密钥文件）；`logs/` 日志；`backups/` 覆盖前的临时备份。
- **文件权限**：数据目录与日志目录仅当前用户可访问；密钥文件与数据库文件仅当前用户可读写。
- **整库加密**：数据库使用 SQLCipher 整库加密（AES-256），没有正确的密钥与密码无法打开。

### 7.2 隐私声明

- **我们收集什么：什么都不收集。** 不收集邮箱，不收集设备标识，不收集持仓，也不发送任何使用统计或崩溃上报。
- **零遥测**：应用不内置任何统计、分析或第三方分析 SDK。没有「匿名使用数据」开关，因为这条链路根本不存在。
- **不自动检查更新**：应用不会在后台访问版本服务器或更新接口；想知道有没有新版本，请自行查看 GitHub Releases。
- **日志与诊断报告只在本机**：导出前会提示你检查敏感信息；日志中禁止出现 API 密钥明文 / 哈希与完整 API 响应体，账户名与金额默认部分遮蔽。
- **帮助链接**：你主动点击的链接（交易所密钥创建教程、行情源注册页、隐私政策、源码仓库等）会交给系统浏览器打开——那是你主动发起的浏览器访问，应用自身不会访问这些域名。

### 7.3 出站连接白名单

应用运行期只可能连接以下**三个主机**（均为 HTTPS）：

| 主机 | 作用 |
|------|------|
| `api.coingecko.com` | 行情主源（币价、币种目录、历史价格回填） |
| `pro-api.coinmarketcap.com` | 行情兜底（仅在你配置了 CoinMarketCap Key 且主源失败时） |
| `api.binance.com` | 交易所只读 API（交易数据同步） |

除这三个之外没有第四个业务域名。开启系统代理只改变这些请求经由的通道，不会新增访问目标。

**这些请求里带了什么**：只带**币种标识 / 交易对与时间窗口**这类必要参数——例如「查询 bitcoin、ethereum 的美元价格」「查询 BTCUSDT 在某个时间段的成交」。
**绝不包含**你的持仓数量、资产金额、账户名、备注或任何交易明细；应用也**不会**把你的数据上传到任何服务器。行情刷新与交易同步是两条彼此独立的链路（见 §6）。

### 7.4 数据完全属于你

- **换电脑**：用 `.cpro` 备份迁移（§8.3）。
- **想带走原始数据**：用「数据管理」里的明文 CSV 导出（不含任何 API 密钥，§8.4）。
- **想彻底删除**：见 §11。

## 8. 备份与恢复

### 8.1 备份（`.cpro`）

`.cpro` 文件由两部分组成：**明文头部**（格式版本、应用版本、导出时间、各表记录条数、数据时间范围——用于恢复前给你看摘要）+ **AES-256-GCM 加密的 JSON 载荷**（交易、资金流水、校准记录、手续费规则、交易所 API 密钥、账户级设置、相关价格快照）。备份**不包含任何账户信息**（用户名、密码哈希等）。

操作步骤：

1. 设置 → **数据管理** → 点 **备份数据**。
2. 设置 **备份文件密码** 与 **确认备份文件密码**：至少 8 位且包含字母与数字。应用**不会回填或存储**你的账户密码，请为备份设置一个独立密码并牢记。
3. 阅读提示「备份文件包含 API 密钥等敏感数据，请妥善保管。」。
4. 点 **选择保存位置并生成** → 选好路径后生成文件；成功后提示「备份完成：<路径>」，同时「上次备份」时间刷新。

> ⚠️ **备份密码决定备份包的强度上限**：忘记它，备份里的数据（含 API 密钥）就无法恢复，没有找回入口。
>
> 建议把 `.cpro` 存放在与电脑分开的安全位置并定期更新；距上次备份超过 30 天时状态栏会提醒你。

### 8.2 恢复

设置 → **数据管理** → 点 **恢复数据**：

1. **选择 `.cpro` 文件** — 界面显示备份摘要（格式版本、应用版本、导出时间、数据时间范围、记录条数）供你确认。
2. 输入 **备份文件密码** → **验证密码**。密码错误或文件损坏会提示「密码错误或文件损坏，请核对备份文件密码后重试。」（有意不区分这两种情况）。
3. 选择导入方式：
   - **增量合并（默认）**：按「记录 uuid → 交易所+订单号 → 快照幂等」合并，**不删除**现有记录；密钥按「交易所 + 别名」、费率按交易所、账户级设置按设置项合并，备份优先覆盖。界面会预览「将新增：N 条；已存在跳过：N 条；缺失币种跳过：N 条」。
   - **全量覆盖**：清空当前账户的业务数据后导入（全局行情缓存保留）；需要勾选「我已知晓全量覆盖将替换当前账户的全部业务数据」，并且覆盖前会自动生成临时备份。
4. 点 **开始恢复**。完成后显示「恢复完成」：已导入、重复跳过、缺失币种跳过、覆盖前临时备份路径，以及本次导入新产生 **持仓异常** / 账户既存持仓异常的清单。

> ⚠️ **全量覆盖不可逆**：它会替换当前账户的全部业务数据。恢复前请先按 §8.1 导出一份当前数据的 `.cpro`；界面虽然会自动生成临时备份，但那份备份也保存在本机。

### 8.3 跨设备迁移 / 换电脑

1. 旧设备：按 §8.1 导出一份 `.cpro`。
2. 新设备：安装后**先创建账户**（走初始化向导，选「从备份恢复」，或先「稍后再说」再进 设置 → 数据管理）。
3. 选择 `.cpro` 文件并输入**备份文件密码**即可。恢复只依赖这个文件密码，与原账户密码、原设备钥匙串无关。
4. 恢复完成后应用会重算持仓与各项指标并刷新页面。

### 8.4 明文导出（CSV）

设置 → 数据管理 → 「明文导出（CSV，不含 API 密钥）」：**导出交易记录**、**导出资金流水**、**导出持仓汇总**。

CSV 是**明文**文件，适合自己存档或交给其他工具处理；交易 CSV 与导入模板同列，可以直接回导。共享或上传前请自行评估隐私影响。

## 9. 加密与安全说明

- **分层密钥（DEK / KEK）**：每个账户有独立的数据密钥（DEK，AES-256-GCM）；DEK 由账户密码派生的账户密钥（KEK，Argon2id）包裹后存储。验证密码 → 解开 KEK → 解开 DEK → 打开数据。没有密码就没有密钥，也就无法解密。
- **密码与登录凭据永不落盘**：只保存不可逆的密码哈希用于登录校验；「记住我」只把会话令牌放进系统钥匙串（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service），密码本身不保存。
- **钥匙串不可用时降级**：数据库主密钥改存本地密钥文件（仅当前用户可读写），并在启动时弹一次「安全提示」（§10.1）。
- **文件权限**：数据目录仅当前用户可访问，密钥与数据库文件仅当前用户可读写（Linux / macOS 上分别为 0700 与 0600；Windows 上依赖账户 ACL）。
- **修改密码**：需要先验证原密码；改密只用新密码重新包裹 KEK，数据不会整体重新加密；历史备份仍按导出时设置的备份密码解密；改密后原「记住我」会话令牌**立即失效**，需要重新登录并可重新勾选。
- **切换账户**：必须重新输入目标账户密码（严格模式），无密码无法解密；登出即清除会话令牌。
- **日志脱敏**：日志包含时间戳、操作类型与结果；账户名与金额默认部分遮蔽，禁止记录密钥明文 / 哈希与完整 API 响应体。日志与同步记录按上限轮转（各保留最近 1 万条或 90 天，先到为准）。本机之外没有任何副本：不联网备份、不同步到云端——这也是为什么备份必须由你自己做。

## 10. 常见问题（FAQ）

### 10.1 启动时提示「安全提示：系统钥匙串不可用」

含义：系统钥匙串（Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service）不可用，数据库主密钥已**降级存入本地密钥文件**（仅当前用户可读写）。应用可以正常使用，但此模式的保护弱于系统钥匙串。

怎么恢复：

- Windows：检查凭据管理器是否被账户策略或安全软件拦截；
- Linux：安装 `gnome-keyring` 与 `libsecret-1-0`，并在**桌面会话内**启动应用（WSL、无桌面会话或未运行钥匙串服务的环境会一直走降级，属预期）。

> 无论哪种模式，请把数据目录中的密钥文件与数据库一起纳入备份与保管范围。

### 10.2 启动提示「无法解锁本地数据库」

含义：数据库无法用当前主密钥解密——**密钥与数据库不匹配**（换了机器、密钥文件被替换，或数据目录被整体替换）。

怎么办：

1. **不要删除数据目录**，先退出应用；
2. 回想是否更换过密钥文件、搬动过数据目录，或把别的数据库文件拷了进来；
3. 如果这份库是从别处拷来的、没有配套密钥，唯一途径是用该账户的 `.cpro` 备份恢复（§8.3）；
4. 如果提示的是「本地密钥文件异常」（该文件应为 64 位十六进制），先确认文件完整；确实损坏且没有备份时，移走该文件重启会生成新密钥——但旧库将无法解锁，同样只能从备份恢复。

### 10.3 为什么某个币没有算进总资产

两种最常见的情况：

1. **该币暂无行情（缺价）**：仪表盘提示「⚠ N 个币种暂无行情，其市值未计入净值与 ROI」。应用会自动尝试补价，也可以点 **立即刷新行情** 重试；长时间没有价格说明行情源未收录该币。
2. **该币持仓为负（持仓异常）**：只可能来自导入路径（CSV 导入 / API 同步不做余额校验）。负持仓币种的市值**不计入净值与可用现金**，资产列表该行显示 **持仓异常** 徽标，仪表盘会显式提示被排除的金额（不会静默忽略，也不会隐式扣减）。
   恢复办法（任一）：补录对应的增资、补导入更早的历史数据，或在币种详情页执行 **以交易所余额校准持仓**；异常消除后市值自动重新计入，无需手工干预。

另外，**24 小时盈亏**在部分币种缺少 24 小时前价格时会剔除这些币种计算，并标注「覆盖 N/M 个币种」；全部缺失时显示「--」。

### 10.4 行情刷新失败 / 提示限流（429）

- 界面会说明原因（如「行情接口限流（429），已自动退避」「CoinGecko 共享限流触发，已自动退避；建议注册免费个人 Key 获取专属额度」），并**保留上次价格与时间戳**，不会清空已有数据。
- 未配置个人 Key 时走 CoinGecko 公共 API，按 IP 共享限流，公司 / 校园等共享出口更容易触发 429。注册免费的 CoinGecko 个人 Key，填入「设置 → 行情与同步 → 行情数据源（CoinGecko API Key）」，即可切换为专属额度（约 30 次/分钟、1 万次/月），**切换即时生效，无需重启**。
- 配置了 CoinGecko Key 后，月度额度用到 80% 会自动降一档刷新频率并在状态栏提示。
- 配置了 CoinMarketCap Key 时，主源失败（网络 / 超时 / 429 / 额度耗尽 / 币种未收录）会自动兜底，价格旁标注「数据源：CoinMarketCap」，主源恢复后自动回落；未配置则保持上次价格并显示上次成功时间戳。手动重试：点顶栏 **刷新行情**。

### 10.5 离线能用吗？

**能。** 所有数据与计算都在本机：查看持仓、交易、资金流水，录入记录，导出备份都不需要网络。只有两件事需要联网：**刷新行情**（取价格）与**同步交易**（交易所只读 API）。

离线期间的差异：

- 价格保持上次成功获取的值，并显示上次成功时间戳；
- 离线保存需要折算的记录会标记「待定价」，暂按最近可得价格估算并标注「估算中」，联网后自动回填真实价格并重算；行情完全不可用时不允许执行持仓校准，等有价格后再校准。

### 10.6 备份文件的密码忘了怎么办？

> ⚠️ **无法找回。** 备份包由你设置的备份文件密码加密，应用不保存该密码，也没有任何后门或在线找回途径。

- 记得**该备份文件**的密码：直接用它恢复（与当前账户密码无关，改过账户密码也不影响历史备份）。
- 忘了备份密码但记得账户密码：该备份打不开，只能改用其他 `.cpro` 备份恢复。
- 两者都忘了：本地数据无法解密，数据不可恢复。

这也是为什么建议**定期导出备份，并牢记备份密码**。

### 10.7 安装 / 解压到中文路径后启动失败（弹 `Failed to launch JVM`）

原因：启动器无法在含系统代码页不支持字符的路径下加载随包运行时（打包工具上游限制），**与是否安装 Java、装的是哪个版本无关**。

处理：

1. 改用**纯英文（ASCII）路径**：Windows 安装版已在默认路径 `C:\Program Files\WuZhuFolio` 规避；**便携版请解压到如 `D:\WuZhuFolio`**；也可以直接使用安装版。
2. 若弹窗伴随其他异常，先核对安装包的 SHA256 是否与发布页一致，并确认安全软件没有隔离安装目录里的文件。
3. Linux / macOS 的便携版同样建议解压到纯英文路径。

### 10.9 Windows 首次运行提示「Windows 已保护你的电脑 · 未知发布者」

本版安装包**未做代码签名**（本项目的既定选择：不采购签名证书），因此 Windows SmartScreen 会对新下载的程序给出提醒。放行步骤：

1. 在弹出的蓝色窗口中点「**更多信息**」；
2. 点右下角的「**仍要运行**」；
3. 安装过程中若再次被拦，同样选「更多信息 → 仍要运行」。

这不是病毒告警，而是「发布者身份未知」的通用提示。想进一步确认文件没被篡改，可用发布页的 `SHA256SUMS` 核对：

```powershell
certutil -hashfile WuZhuFolio-0.1.0.msi SHA256   # 与 SHA256SUMS 里的值比对
```

### 10.8 卸载后数据在哪？怎么彻底删除？

卸载程序只移除应用，**不会删除数据目录**（这是刻意设计，避免误删账本）：

- Windows 在 `%USERPROFILE%\.wuzhufolio`；macOS / Linux 在 `~/.wuzhufolio`。

彻底清除 = 先按 §11 卸载应用，再手动删除上述数据目录。

> ⚠️ 删除数据目录后，如果没有 `.cpro` 备份，数据将**永久消失、无法恢复**。删除前请确认：不再需要这份数据，并且你保存的备份文件（在你选择的保存位置，不会随卸载删除）也不再需要。

## 11. 卸载

- **Windows（安装版）**：设置 → 应用 → 已安装的应用 → WuZhuFolio → 卸载（或控制面板「程序和功能」）；卸载需要管理员确认。数据目录保留，按 §10.8 手动删除才彻底清除。
- **Windows（便携版）**：直接删除解压出来的目录即可；删除前建议先在「设置 → 托盘与后台」关闭「开机自动启动」。
- **macOS**：把 WuZhuFolio 从「应用程序」拖到废纸篓。
- **Linux**：deb 用 `sudo dpkg -r wuzhufolio`，rpm 用 `sudo rpm -e wuzhufolio`；AppImage 与便携版直接删除对应文件或目录。
- 安装版若开启过「开机自动启动」，建议**先在设置里关闭再卸载**，避免系统里残留一条指向已删除程序的启动项。
