# ADR-004 交易所同步适配（Binance 只读 + 可扩展适配器，Kotlin）

- **状态**：**人工拍板采纳**（2026-08-31，含 §3.1 symbol 枚举与权重预算）
- **日期**：2026-08-31（本轮适配 Kotlin + Compose Desktop）
- **决策类型**：架构级
- **需求回溯**：PRD 故事 4.1、PRD §7.2 模块 4、PRD §10 api_keys 表注（MVP 收敛 Binance）、PRD 全局说明「币种标识与主数据规则」、共享规范 §1/§6

---

## 背景

交易数据同步通过交易所只读 API 拉取新成交写入本地账本，与行情数据刷新相互独立。MVP 收敛 **Binance**（api_key + secret_key，只读；api_keys 预留 passphrase/extra，PRD §10 注）。同步增量式：按「交易所 + 订单号」去重、仅导入本地不存在的新交易、不覆盖本地持仓；API 仅返回最近 500 条成交，更早需 CSV 补录。本 ADR 固化 Kotlin 适配器抽象与同步语义。

## 决策

### 1. 统一抽象 `ExchangeAdapter`（Kotlin 接口）

```kotlin
interface ExchangeAdapter {
  val exchangeName: String
  suspend fun validateCredentials(): Result<Unit>
  suspend fun fetchBalances(): List<Balance>
  suspend fun fetchTrades(since: Long?, cursor: String?): TradePage
  suspend fun fetchPairs(): List<PairInfo>
}
```

每个 adapter 声明凭证模型、去重键、限流语义；HTTP 用 Ktor client，经系统代理。

### 2. MVP 实现 `BinanceAdapter`（真实 API，Spot）

Base：`https://api.binance.com`（REST，签名端点）。凭证 api_key + secret_key（HMAC SHA256 签名）。

| 方法 | 端点 | 说明 |
|------|------|------|
| `validateCredentials()` | `GET /api/v3/account` | 签名请求验证密钥（PRD §9.10） |
| `fetchBalances()` | `GET /api/v3/account` | 资产余额（校准数据源） |
| `fetchTrades(symbols)` | `GET /api/v3/myTrades` | **逐 symbol**（必传）增量，`limit≤500` + `fromId`/时间分页；symbol 集合与权重预算见 §3.1 |
| `fetchPairs()` | `GET /api/v3/exchangeInfo` | pair 注册表（baseAsset/quoteAsset，公开） |

认证：请求头 `X-MBX-APIKEY` + 查询参数 `timestamp`（毫秒）+ `recvWindow`（默认 5000）→ `signature=HMAC-SHA256(queryString, secret)`。
错误映射：-2015/-2014 → 密钥失效（B2 文案）；-1003/429 → 限流退避；-1021 → 时间戳偏差重试；-1022 → 签名错误（提示密钥错误）。

### 3. 同步语义（PRD 故事 4.1）

- 增量去重键 `(exchange, exchange_order_id)`；仅写本地不存在的新交易；**不覆盖本地持仓余额**。
- 币种解析：pair 经 exchangeInfo 注册表切分 → base/quote 资产经 `exchange_coin_map` 映射 coin_id，消歧四级（共享规范 §6），冻结写入记录（base_coin_id/quote_coin_id）。
- 触发：应用启动 + 定时（默认 30 分钟，可调 15/30/60）+ 手动；托盘驻留按同一间隔。保存密钥（验证通过）后立即首次同步（PRD 流程图 3）。
- 结果写 `sync_logs`（new_trades_count、脱敏 message，禁密钥/完整响应体，PRD §6）。

### 3.1 同步范围收敛（symbol 枚举策略，2026-08-31 评审 F2 修订）

Binance 现货**无账户级成交端点**：`myTrades` 必传 `symbol`（单次权重 10）；现货交易对约 2,000+，全量枚举一次同步即数万次调用，必然触发 -1003/429 乃至 418 封禁。候选 symbol 集合按以下来源收敛：

1. **余额推导**：`fetchBalances()` 返回的非零资产 × exchangeInfo 中这些资产可组成的 TRADING 状态 pair；
2. **历史已同步 pair**：本地 transactions 表已存在的 (exchange, pair) 去重集合；
3. **手动指定**：用户在 API 管理中补充的交易对（可选，MVP 可不暴露）。

逐 symbol 增量拉取（有 fromId 用 fromId，否则按时间窗分页），**单次同步权重预算 ≤1200（约 120 次 myTrades 调用/分钟窗口）**；超出部分排队到下一调度周期续传，并在 sync_logs 注明「部分同步，下轮续传」。首次同步（无 fromId）按同一候选集合与时间窗分页，受同一预算约束。

### 4. 扩展性

- 后续交易所（Coinbase Ed25519/JWT 等）逐个评审后新增 adapter，复用 api_keys 的 passphrase/extra（PRD §10 注）；去重键统一 (exchange_name + 订单号)，api_keys 去重键 (exchange_name + name)。
- exchange_coin_map 与 pair 注册表缓存为全局公共数据，不随账户备份导出（PRD §10 注）。

## 选项

| 选项 | 优点 | 缺点 |
|------|------|------|
| **adapter 抽象 + Binance 单实现（选定）** | 与 PRD 收敛清单一致；可插拔；凭证差异隔离 | 需定义稳定契约 |
| 硬编码 Binance 调用 | 最快 | 无扩展性，违反 PRD「后续逐个评审接入」 |
| 同时接入多家 | 覆盖更广 | 违反 MVP 收敛，范围蔓延 |

## 理由

1. 逐条对齐 PRD 故事 4.1 与 §7.2 模块 4；MVP 范围不蔓延。
2. 适配器抽象隔离凭证模型差异与增量去重/币种解析。
3. 同步与行情代码层严格隔离（不同接口、不同调度、不同日志）。

## 风险

| 风险 | 缓解 |
|------|------|
| Binance 权重限流/封禁 | 429/418 退避；失败写 sync_logs + UI 提示（N2/B2）；同步串行 |
| myTrades 仅 500 条历史缺失 | PRD 已明示 CSV 补录；UI 提示 |
| 密钥失效 | 保存时测试请求验证；失败标 status=FAILED（B2 文案） |
| 交易所资产未收录（无行情） | 共享规范 §6 标「无行情」，不计入总资产 |

## 备注

- 持仓校准复用 `fetchBalances`，但校准语义由领域层 `ReconciliationService` 负责（architecture.md），不在 adapter 内。
