# ADR-001 桌面端技术栈（Kotlin + Compose Desktop）

- **状态**：**人工拍板采纳**（2026-08-31 人工指令「桌面端采用 kotlin + compose desktop 技术栈；若有基于此的脚手架也可采用」）
- **日期**：2026-08-31（本轮按人工指令修订）
- **决策类型**：架构级
- **需求回溯**：PRD §12（运行环境/OS 矩阵/签名公证/无检查更新）、PRD §1/§3（隐私第一/4GB 低配目标）、PRD §6（响应 2s 内、异步后台任务、无障碍基线）、AGENTS.md §4 P2（桌面端需定架构）

---

## 背景

桌面端此前无既定技术栈。人工于 2026-08-31 拍板：**采用 Kotlin + Compose Desktop**，如有基于此的脚手架亦可采用。本 ADR 据此落地完整技术栈与脚手架来源，并适配 PRD 的隐私/安全/低配/三平台分发约束。

P1 产出的 HTML 原型（`wuzhufolio-light.html`）与 design tokens 在此栈下**不再是运行时基座**，而是 **UI 视觉与交互基准**（P4 用 Compose 组件逐项还原，截图走查对比）；逻辑契约（重放引擎、异常态、精度、黄金用例）不变。

## 决策

**桌面端采用 Kotlin（JVM）+ Jetpack Compose for Desktop（Compose Multiplatform）**：

| 层次 | 技术绑定 |
|------|----------|
| 语言 | Kotlin（JVM target 17） |
| UI | Compose Multiplatform（Compose for Desktop）+ Material 3 基座 + 自定义主题映射 `design-tokens.md`（Canvas 画环形图，LazyColumn 数据表） |
| 构建 | Gradle（Kotlin DSL）+ version catalog；Compose Gradle 插件（`org.jetbrains.compose`） |
| 状态/架构 | androidx ViewModel + kotlinx.coroutines + StateFlow；分层：UI → 用例/服务 → 领域 → 数据（见 architecture.md） |
| DI | Koin（轻量，Compose 友好） |
| 持久化 | SQLite + SQLCipher（JDBC），Exposed ORM 或薄 DAO（见 ADR-002） |
| 加密 | JDK JCE AES-256-GCM + Argon2id（argon2-jvm 或 BouncyCastle，见 ADR-002） |
| OS 钥匙串 | javakeyring（JNA：Windows 凭据管理器 / macOS Keychain / Linux Secret Service，见 ADR-002） |
| HTTP + 系统代理 | Ktor client（**OkHttp 引擎**，原生支持 JVM `ProxySelector` 系统代理自动检测）+ kotlinx.serialization（ADR-003 §1，评审 N4） |
| 托盘/通知/自启 | **Compose Desktop 自带 Tray/Notification API（首选）**：`androidx.compose.ui.window.Tray` composable + `TrayState.send(Notification(...))`，Kotlin 声明式（AWT SystemTray 仅为其底层实现，不直接使用）；dorkbox SystemTray/Notify 作 **Linux AppIndicator 兼容备选**；自启与 AWT 无关，走平台注册（注册表/LaunchAgents/XDG autostart） |
| 测试 | kotlin.test/JUnit5 单测；Compose UI 测试（ui-test-junit4）；MockWebServer/MockEngine 做行情与交易所 mock |
| 分发 | jpackage（Compose 插件 package* 任务）：**捆绑 jlink 裁剪私有 JRE 的原生安装包**（exe/msi/dmg/deb），用户机器无需系统 Java——「本地 exe 脱离系统 Java 环境」即此既定模型（ADR-006 §1.1）；签名/公证见 ADR-006 |

**脚手架来源（人工允许采纳）**：以官方 **`JetBrains/compose-multiplatform-desktop-template`**（GitHub）或 **Kotlin Multiplatform 向导（kmp.jetbrains.com）** 生成的 Compose Desktop 工程为 P3 骨架基座，再按本项目分层重构（不保留模板的演示代码，只取其 Gradle/插件/runtime 配置骨架）。

## 选项

| 选项 | 优点 | 缺点 |
|------|------|------|
| **Kotlin + Compose Desktop（人工拍板，采纳）** | 单一 Kotlin 语言全栈；Compose 声明式 UI + Canvas 可精确还原原型视觉；JVM 生态（JDBC/SQLCipher/JCE/协程）成熟；jpackage 原生三平台打包 | 读屏（NVDA/JAWS）支持弱于 Web（见风险）；需 JRE 打包（体积 ~80–150 MB）；托盘/通知需第三方库 |
| Tauri 2 + Rust + Web 前端（原建议） | 二进制小、内存低、Web a11y 好 | 人工已改选；Rust 学习成本高、与原型双层技术栈 |
| Electron | 生态成熟、Web a11y 最好 | 体积/内存大，与低配 4GB 定位冲突（原已否决） |
| Flutter Desktop / Qt | 跨端/原生 | 需重写 UI、脱离 Kotlin 方向（原已否决） |

## 理由

1. **人工拍板**：技术方向由人决策，本 ADR 记录并落地。
2. **单语言全栈**：UI、领域、数据、加密、打包全程 Kotlin，降低心智与工具链成本。
3. **视觉可还原**：Compose 声明式 UI + Canvas + 自定义主题可将 `design-tokens.md` 的 CSS 变量与原型布局 1:1 映射为 Compose 主题对象，P4 以截图对比验证。
4. **JVM 生态支撑硬约束**：JDBC + SQLCipher（整库加密）、JCE AES-256-GCM、Argon2id、javakeyring（钥匙串）均在 JVM 有可用实现（见 ADR-002 的风险与 P3 验证项）。
5. **三平台分发**：Compose Gradle 插件内建 jpackage（dmg/msi/deb/rpm），配合公证/签名可落地 PRD §12（AppImage/Flatpak 为追加步骤，见 ADR-006 风险）。

## 风险

| 风险 | 缓解 |
|------|------|
| 读屏（NVDA/JAWS）支持弱于 Web | Compose 语义 API（`Modifier.semantics`）+ 全键盘导航 + 文本标签；完整读屏走查在 P4 实测，若为硬阻断则升级提醒人工（PRD §6/T12 仍为目标） |
| JVM SQLCipher 驱动非官方 | 采用社区维护 `Willena/sqlite-jdbc-crypt`（跨平台），P3 验证并锁版；备选自绑 JNI（见 ADR-002 风险） |
| 打包体积（含 JRE）较大 | 接受体积换稳定；jlink 裁剪 JRE 减小体积（P7） |
| 托盘/通知/自启跨平台差异（Linux Wayland 默认无托盘协议，需 AppIndicator 扩展——平台限制，与打包/AWT 无关） | Compose Tray API 首选 + dorkbox AppIndicator 兼容备选 + 平台自启注册模块，P3 三平台冒烟 |
| Compose 还原原型的偏差 | design tokens 单源映射 + 截图走查（P4） |

## 备注

- 移动端技术栈不在此决策范围（AGENTS.md §4：移动端归下一版本）；若未来移动端启用，Compose Multiplatform 可让 UI 与部分逻辑跨端复用（Ktor/kotlinx.serialization/领域层均可共享），本栈为此预留了空间。
- 本 ADR 覆盖原 `api-contracts.md` §3「内部 IPC」——Compose 桌面端无跨进程 IPC，改为**进程内 Kotlin 服务/用例接口**（见 architecture.md §2.2 与 api-contracts.md §3）。
