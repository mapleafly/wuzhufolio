# ADR-002 存储引擎与加密方案（SQLCipher + 分层密钥 DEK/KEK，Kotlin/JVM）

- **状态**：**人工拍板采纳**（2026-08-31：驱动选型 Willena/sqlite-jdbc-crypt，P3 三平台验证并锁版；失败回退「自维护 JNI 绑定官方 sqlcipher 库」——回退路径已随拍板一并确认）
- **日期**：2026-08-31（本轮适配 Kotlin + Compose Desktop）
- **决策类型**：架构级
- **需求回溯**：PRD §10 注（存储与加密选型/并发写模型）、PRD 故事 5.1、PRD §1.1 硬约束 3、共享规范 §7（密钥架构与存储选型）

---

## 背景

产品硬约束要求：分层密钥（DEK/KEK）、AES-256-GCM、密码与登录凭据永不落盘、日志脱敏（PRD §1.1）。PRD 故事 5.1 定下方向：SQLite 单库多账户、整库加密（**如** SQLCipher，数据库密钥随机生成、由 OS 安全存储保护）、凭证字段额外按账户 DEK 字段级加密、全局公共表不按账户 DEK 加密。本 ADR 在 Kotlin/JVM 栈下落地具体引擎、依赖与参数（Argon2id 初值 + 校准要求，PRD §12：4GB 双核登录解密 ≤2s）。

## 决策

### 1. 存储引擎：SQLite + SQLCipher（JDBC）

- 单库多账户：一个 SQLite 文件承载全部账户；账户业务表按 `account_id` 隔离（PRD §10 注）。
- 整库加密：SQLCipher 4.x；JDBC 驱动采用社区维护的 **`Willena/sqlite-jdbc-crypt`**（基于 xerial sqlite-jdbc + SQLCipher，含 Windows/macOS/Linux 原生库）。**密钥经连接属性注入**（xerial 系驱动要求 key 在连接建立时设置或作为首条语句；驱动初始化触碰 DB 后再执行 `PRAGMA key` 会失败，评审 N4）。**P3 验证三平台可用性并锁版**；若该 fork 维护不力，备选「自维护 JNI 绑定官方 sqlcipher 库」（成本高但可控，需人工确认）。
- 数据库密钥：随机 256-bit，不派生自任何账户密码；首次建库生成并写入 OS 钥匙串。
- JDBC 连接参数：`journal_mode=WAL`、`busy_timeout=5000`、`foreign_keys=ON`（经 `PRAGMA` 或连接 URL 参数）。**WAL 在 SQLCipher 下的生效性列入 T1.1 三平台锁版验证清单**（加密页与 WAL 交互存在版本差异，评审 N4）。
- 访问层：**Exposed（JetBrains ORM）** 管理 schema/迁移/查询（备选：薄 DAO + 原生 JDBC）；迁移用 Exposed SchemaUtils + 手工迁移脚本（PRD §10「数据库版本管理」）。

### 2. 分层密钥（DEK/KEK）

- 每账户独立 `DEK`：256-bit 随机，AES-256-GCM，仅用于凭证字段级加密。
- `KEK`：账户密码经 KDF 派生的 256-bit。
- `wrapped_dek` = AES-256-GCM(明文=DEK, key=KEK, nonce=随机 96-bit, AAD=account_id+"wrapped_dek")，存储 `v1`+base64(nonce‖ciphertext‖tag)。
- KDF：**Argon2id**（初值 m=64 MiB, t=3, p=1, salt=16 字节, 输出=32 字节）；备选 PBKDF2-HMAC-SHA256 ≥600,000 次（共享规范 §7 允许）。实现：`de.mkammerer:argon2-jvm`（JNA 绑参考实现，最快）或 BouncyCastle `Argon2BytesGenerator`（纯 JVM）。**P3 在 4GB 双核目标机基准校准 ≤2s**；不达标降为 m=19 MiB/t=2/p=1（OWASP 最小值）并记录实测。
- 字段级加密：api_keys 的 api_key/secret_key/passphrase/extra 逐列 AES-256-GCM（JDK `javax.crypto`，GCM 无填充，96-bit 随机 nonce），AAD=account_id+"|"+api_key_id+"|"+column；密文 base64(version‖nonce‖ciphertext‖tag)。仅凭证列加密，不做筛选/排序/索引（PRD §10 注）。
- 密钥材料擦除：使用后清零 `ByteArray`（`Arrays.fill(0)`），密码不落盘（PRD 故事 5.1-4）。

### 2.1 应用级秘密（行情平台 Key）：设备密钥加密（2026-08-31 人工拍板方案甲，评审 F1）

- 行情平台 Key（CoinGecko / CoinMarketCap）是**应用级秘密**，不是账户资产：用与数据库密钥同级的「**设备密钥**」加密（随机 256-bit，存 OS 钥匙串，与 DB 密钥并列管理），密文存 settings 表**全局行**（account_id NULL，key=market.coingecko_key / market.cmc_key）。
- **不使用账户 DEK**：保持「字段级加密仅限 api_keys 四列」的加密边界不变（共享规范 §7），避免跨账户/新设备恢复后密文随源账户 DEK 失效。
- **不进 .cpro 备份**：备份不含全局设置（ADR-005 §3）；恢复后用户在设置中重新配置行情 Key（成本极低，备份文件敏感面不扩大）。
- 设备密钥与 DB 密钥同生命周期、同降级策略（钥匙串不可用时见本 ADR 风险表）。

### 3. 登录/改密/切换语义

- 登录：**单次** Argon2id 派生 KEK → 解包 wrapped_dek（**GCM tag 校验即完成密码认证**：密码错误必然解包失败）→ DEK 驻内存。`password_hash` 不落第二趟 KDF，存 KEK 派生校验值（如 SHA-256(KEK ‖ "verify")）用于快速判错——登录解密 ≤2s 预算不因双趟 KDF 翻倍（PRD §12，评审 N2）。
- 改密：验原密码 → 新密码派生新 KEK → 重包 DEK（数据不变）→ 作废该账户「记住我」会话令牌（PRD 故事 5.1-6）。
- 切换账户：需目标账户密码（严格模式），解锁新账户 DEK（PRD 故事 1.3）。
- 「记住我」会话令牌语义（2026-08-31 严苛度评审整改，原表述欠定义）：令牌 = 随机 256-bit，与密码**无任何推导关系**；钥匙串存 (token, wrapped_dek_session)，其中 wrapped_dek_session = AES-256-GCM(明文=DEK, key=token, AAD=account_id+"session")；启动自动恢复 = 读 token → 解包得 DEK（全程不触密码）；登出/改密/切换账户即删除钥匙串条目并作废令牌；令牌泄露影响面 = 当台设备当前账户，撤销即失效（PRD 故事 1.1/1.2）。

### 4. 并发写模型

- 单写队列：所有写操作（前台编辑、CSV/API 导入、后台同步、全量重放）经单一 `Mutex` 串行执行（PRD §10 注）。
- WAL + busy_timeout；后台同步期间前台编辑入队等待并显示「同步中」；MVP 不引入乐观锁（共享规范 §7）。

## 选项

| 选项 | 优点 | 缺点 |
|------|------|------|
| **SQLCipher 整库 + 字段级 DEK（选定）** | 与 PRD/共享规范逐字对齐；整库防文件窃取 + 凭证二次加密，支撑 `.cpro` 导出解密/重加密语义 | JVM 驱动为社区维护，需 P3 验证 |
| 仅字段级 DEK 加密（不整库） | 实现简单 | 业务表/快照明文落盘，违反 PRD 故事 5.1-1 |
| 仅整库加密（无字段级） | 单一加密层 | 无法满足 `.cpro` 字段级解密→重加密语义与全局公共表隔离 |
| SQLite SEE / 自研加密 | SEE 需付费、自研不可靠 | 不采纳 |

### Kotlin/Compose Desktop 亲和存储栈评审（2026-08-31 人工问询增补）

| 候选栈 | Kotlin/Compose 亲和度 | 结论 |
|--------|----------------------|------|
| Room KMP（androidx.room 2.7+，支持 Desktop JVM） | Kotlin 一等公民、编译期 SQL 校验 | **否决**：KMP 模式无 SQLCipher 支持（加密 OpenHelperFactory 仅 Android 端 sqlcipher-android），无法满足整库加密硬约束 |
| Realm Kotlin（KMP，内置 AES-256 整库加密） | Kotlin 原生、加密开箱即用 | **否决**：对象库非关系型，违反共享规范 §7「SQLite 单库多账户」既定约束；11 表关系模型 + 重放引擎的 ad-hoc 关系查询不适配 |
| SQLDelight（Square） | Kotlin 一等公民、编译期 SQL 校验、协程/Flow 原生 | **不采纳**：JVM 下仍走同一 Willena SQLCipher JDBC 驱动（加密可用性风险与现方案完全相同，不降低最大风险）；动态多条件筛选/排序（交易/资金列表主场景）表达力弱于 Exposed DSL；编译期校验收益可由单测 + 黄金用例覆盖替代 |
| **SQLite + SQLCipher(Willena JDBC) + Exposed（维持）** | JetBrains 维护、DSL 动态查询灵活、`newSuspendedTransaction` 协程集成 | **维持**：本评审未发现更亲和且满足整库加密硬约束的替代栈，按现有方案执行；Kotlin 亲和度由 DAO 封装 + 协程集成保证 |

## 理由

1. 逐条对齐 PRD 故事 5.1 与共享规范 §7。
2. 整库密钥随机 + 入钥匙串：文件单独被窃取无法解密；改密只重包 DEK，不重加密数据。
3. 字段级 DEK 是 `.cpro` 跨账户/跨设备恢复语义的前提（见 ADR-005）。
4. Argon2id + 单写队列保证登录性能与并发正确性。

## 风险

| 风险 | 缓解 |
|------|------|
| JVM SQLCipher 驱动维护状态不明 | P3 验证 `Willena/sqlite-jdbc-crypt` 三平台 + 锁版；失败回退自绑 JNI（需人工确认），并更新本 ADR |
| Argon2id 低配机超 2s | P3 基准夹具校准，备降 OWASP 最小值并记录实测 |
| SQLCipher 损坏无法读取 | PRD 统一异常处理 B1：引导从 `.cpro` 恢复；P6 损坏恢复测试 |
| 钥匙串不可用（Linux 无 Secret Service） | 数据库密钥与设备密钥同一降级策略：提示用户手动保护密钥文件；P3 三平台验证 |
| 字段级加密列不可索引 | 凭证列本无需检索（PRD §10 注） |

## 备注

- 全局公共表（coins、exchange_coin_map、price_snapshots）仅受整库加密保护、不按账户 DEK 字段级加密（PRD §10 注）。
- 依赖坐标与版本在 P3 锁进 version catalog；加密/钥匙串库最终选择以 P3 实测为准。
- DB 密钥以 **raw key 模式**注入（`PRAGMA key = "x'<64 hex>'"` 或等价连接属性），跳过 SQLCipher 自带 PBKDF2——密钥本身已是随机 256-bit，无需二次派生。
- **威胁模型边界（2026-08-31 严苛度评审）**：本方案防御——设备丢失/文件窃取（整库加密 + 随机密钥入钥匙串）、共享机器跨账户窥视（DEK 分层 + 字段级）、备份外泄（独立备份密码 + Argon2id/GCM）；**不防御**——已登录 OS 会话内恶意软件读内存/钥匙串（OS 级威胁，超出应用层能力，与主流桌面密码管理器口径一致）。
- **严苛度结论（2026-08-31 评审）**：与本软件（本地单用户财务数据 + 只读密钥）定位匹配——不过严（无 HSM/安全飞地/反调试等过度设计，Argon2id 参数有 ≤2s 校准降级预案）、不过宽（整库 + 字段级 + 钥匙串 + 密钥擦除分层齐全）；唯一欠定义宽松点「记住我令牌语义」已按 §3 整改。
### 实现注记（2026-09-02，P4-M1 落地实证——即「P3 验证」字样的实际执行记录）

- 驱动：io.github.willena:sqlite-jdbc:3.53.4.0 锁版实证（org.sqlite.mc 构建，SQL_CIPHER = SQLCipher 4 兼容）：SQLiteMCSqlCipherConfig.getDefault() + withRawUnsaltedKey(32B) → build() → toProperties()，raw-key 经连接属性注入（每新连接自动携带）；错钥在连接期即抛 SQLITE_NOTADB。三平台矩阵验证由 P4 CI 执行（SqlCipherDatabaseTest）。
- KDF 实现：从 ADR 允许的两选项（argon2-jvm JNA / BouncyCastle 纯 JVM）定案 **BouncyCastle Argon2BytesGenerator**——免三平台原生库分发风险；参照机实测与参数冻结（m=64MiB/t=3/p=1）见 docs/dev/modules/M1.md（4GB 双核目标机复核列入 M2 门）。
- 钥匙串：javakeyring 后端「无条目 vs 不可用」经探针写-读-删往返区分（不做异常消息嗅探）；不可用 → 0600 密钥文件降级 + UI 提示（风险表「提示用户手动保护密钥文件」落地，T1.1 验收）。
- DB 密钥生命周期：WzDatabase 构造完成后调用方擦除源数组（密钥已编入连接属性、进程期随连接使用）；close() 释放连接。
- 全部实现细节 / 验收证据 / 遗留见 docs/dev/modules/M1.md。
