**评审日期:** 2026-08-25
**评审人:** 产品评审（AI 辅助）
**评审方法:** 与桌面端 PRD 同一套评审框架（需求合理性 / 使用逻辑 / 易用性 / 安全性 / 数据模型 / 成功指标 / 文档一致性），并增加「移动端特有」与「与桌面端联动」两个维度。桌面端评审结论见 docs/prd/桌面端prd评审报告.md。

## 一、评审结论摘要

**总体判断：移动化方向正确（离线优先、下拉刷新、侧滑操作、WorkManager、Keystore 等都是加分项），但文档质量明显低于桌面端，且桌面端的核心逻辑硬伤在移动端全部原样继承，另有移动端特有的手势冲突、生物识别用途冲突、安全参数过弱等新问题。当前版本不能作为开发基线，需要 1～2 轮修订。**

亮点（比桌面端做得更好的部分）：

- **离线优先与数据韧性**（L397-398）：缓存旧数据 + 写操作本地排队 + 恢复后重试，是移动端最该有的一节。
- **移动端交互规范**：下拉刷新/上拉加载（L75）、侧滑删除带撤销动画（L744）、单手操作布局（L722）、48dp 点击区域与 56dp 输入框（L856-857）、底部抽屉替代弹窗（L389），符合 Material Design。
- **移动端能耗意识**：“仅 WiFi”“仅充电时同步”（L81、L257、L286）、WorkManager（L104）、低电量模式降级（L870）。
- **安全方向有进步**：引入生物识别（故事 1.2）、Android Keystore（L303、L1106）、密钥隐藏与一键清除（L835-836）。
- **性能指标量化**：冷启动 ≤2s、60fps、内存 ≤50MB、后台同步 ≥30 分钟（L882-886）。
- **细节用心**：自动保存草稿（L879）、双主题跟随系统（L402）、空态与缺省值（L72-73）。

硬伤（🔴）：

1. **继承桌面端的 8 个逻辑硬伤全部原样存在**：ROI 公式、现金余额模型、24 小时盈亏快照、API 双源去重、备份语义、免密切换 vs 密码强关联、转账无规格、手续费币种无入口（详见 3.1）。
2. **生物识别用途自相矛盾**：故事 1.2 说“仅用于解锁，敏感操作仍需密码”（L194），9.10 却要求“添加 API 密钥时指纹/面部识别验证”（L834）。
3. **手势体系互相打架**：左右滑切账户（L46、L722）vs 左滑删除/右滑编辑（L744-745）vs Android 10 手势导航返回边缘，切账户这种高风险操作极易误触。
4. **分页、刷新频率、系统版本三处数字互相矛盾**（L75/L884/L1086；L254/L451/L886；L80/L885）。
5. **安全参数落后**：PBKDF2 仅 100,000 次迭代（L1028-1029）、密码哈希“SHA-256+salt”无迭代（L943、L1020）、备份文件结构疑似明文放密钥（L1040-1046）、用“校验和”当防篡改（L302）。

## 三、问题清单

> 严重度：🔴 必须解决｜🟡 应当解决｜🟢 建议优化

### 3.1 继承自桌面端的逻辑硬伤（在移动端同样成立，附移动端行号）

**🔴 I1. ROI 公式在撤资场景下数学错误（L42、L347；投入本金定义 L38-40）**
与桌面端 R1 完全相同：投入本金 = 增资 − 撤资，盈利提现后分母为负，ROI 显示 −100% 而实际是盈利。移动端 9.3 还给负 ROI 加了“❗️警示图标 + 查看详细分析”（L731-733），等于把一个算错的数字用更醒目的方式展示给用户，误导更严重。**建议与桌面端同步改为资金加权口径。**

**🔴 I2. “可用现金余额”模型不闭合（L32、L34、L226、L244、L325、L334）**
法币现金与币币交易（BTC/USDT）之间无任何联动规则，增资/撤资只改现金、交易只改持仓，两条账对不上；USDT 与法币现金重复计价风险同桌面端 R2。

**🔴 I3. 24 小时盈亏无数据支撑（L245、L449、L455）**
移动端连桌面端的公式都删了，只剩“显示过去24小时的资产绝对值变化和百分比变化”。没有价格快照表、没有“24小时前总资产”的计算定义，新用户首日除零问题同桌面端 R3。

**🔴 I4. API 同步与手动/CSV 数据无合并去重规则（L629；transactions 表 L963-976 无订单号字段）**
流程图同样只有“与本地数据比对，写入新交易”，无去重键、无双源策略；Binance myTrades 500 条限制在移动端同样适用。同桌面端 R4。

**🔴 I5. 免密切换账户 vs “无密码无法解密”矛盾（L206 vs L301）**
故事 1.4 与 5.1 的冲突原样继承。移动端虽有 Keystore（L303）的正确方向，但两处需求并未调和：Keystore 保管的是什么密钥、切账户时如何解密，没有架构说明。同桌面端 S1。

**🔴 I6. 备份语义冲突（L309“当前账户的所有数据” vs L501“整个本地数据库”）**
同桌面端 R9，且移动端恢复还涉及“新设备/重装应用”场景（L308），跨账户语义不清影响更大。

**🔴 I7. “转账”枚举有、规格无（L964 表里有 TRANSFER vs L213-214、L792 表单只有买入/卖出）**
移动端数据表比桌面端“进步”地加了 TRANSFER，但全篇无转账的表单、字段、成本规则、验收标准——枚举与功能规格脱节，开发无从下手。**建议：MVP 明确 Out of Scope 并删除枚举，或补全规格，二选一。**

**🔴 I8. 手续费币种字段有、入口无（L355、L968 vs 9.7 表单 L788-801 无币种选择器）**
同桌面端 R6。

**🟡 I9. 平均成本法细则缺失（L26、L954 portfolio 表直接存 average_cost/total_cost 派生字段）**
移动端把派生成本字段落表，意味着“编辑/删除历史交易如何重算 average_cost”必须有明确规则，否则库存成本会静默漂移。比桌面端更需要先定计算规范。

**🟡 I10. 已实现盈亏缺失（全文无）**：同桌面端 R8。
**🟡 I11. 忘记密码零交代（全文无）**：同桌面端 R10，移动端设备丢失/换机场景更多，更需要显式告知“密码即数据钥匙”。
**🟡 I12. 修改密码连锁影响未定义（L706 只有“可选，如修改密码”一句）**：数据加密与密码派生（L1023-1031）挂钩，改密如何重加密、旧备份如何解密，无规则。同桌面端 R11。
**🟡 I13. 时区规则缺失（全文无 UTC）**：I18N 说日期格式适配地区（L435-437），但存储时区、导入 Binance CSV（UTC）如何解析未定义。同桌面端 U6。
**🟡 I14. 法币汇率无数据源（L813 显示“1 BTC = $30,000 USD”却不定义汇率来源）**：同桌面端 R2/R12 延伸。

### 3.2 移动端特有的需求合理性问题

**🔴 M1. 生物识别用途自相矛盾（L194 vs L834）**
故事 1.2 明确“生物识别仅用于解锁，敏感操作（备份/恢复）仍需密码”；9.10 却要求“添加 API 密钥时要求指纹/面部识别验证”。添加 API 密钥是典型的敏感操作，两处直接冲突，且 1.2 的限制让 9.10 的设计失去依据。
**建议：** 统一策略——生物识别只能做“已登录会话的二次确认”，不能替代密码成为 API 密钥加密密钥的来源；若确实想让生物识别参与密钥保护，需使用 Android BiometricPrompt + Keystore 的「生物识别门控密钥」方案，并把该架构写进 5.1。

**🔴 M2. 手势体系冲突且切账户手势风险高（L46、L722 vs L744-746）**
- 全局“左右滑动切换账户”（9.3）与列表“左滑删除/右滑编辑”（L744-745）在交互层直接竞争同一手势；
- Android 10+ 系统手势导航的左右边缘返回也会与全屏左右滑冲突；
- 切账户是高风险操作（显示的数据域整体变化），绑在无确认的全局滑动上极易误触。
**建议：** 取消“左右滑切账户”，改用顶部账户切换器（9.14 已有“导航栏快速切换按钮”L875，二者重复）；列表滑动操作保留左滑删除+右滑编辑，并给出与系统边缘返回的冲突处理（如边缘留白或长按进入编辑）。

**🟡 M3. 语音输入/语音朗读与隐私定位冲突（L740、L778、L818）**
语音输入交易信息、朗读“当前价格为30,000美元”，在公共场合会把用户财务数据说出来——与产品“隐私第一”的定位相悖；且朗读功能与系统 TalkBack 重复。
**建议：** MVP 砍掉语音朗读；语音输入降级为“实验性可选功能”或移到后续版本。

**🟡 M4. “编辑资产分类”凭空出现（L731 长按饼图弹出“编辑资产分类”）**
“资产分类”功能全篇无任何定义（无字段、无故事、无验收标准），却在核心页面交互中出现。**建议：** 删除，或补全资产分类的需求规格。

**🟡 M5. Widget/快捷入口只定义不落地（L48 名词解释有“快捷入口：Widget 或悬浮按钮”，L876 有“主屏幕快捷方式直接跳转”）**
第 5、7、9 章均无 Widget 的功能规格（显示什么数据、刷新机制、隐私风险——Widget 会在锁屏显示资产金额！）。隐私产品做 Widget 必须先回答“锁屏是否显示金额”。
**建议：** MVP 明确不做 Widget 或给出完整规格（含锁屏隐私选项）。

**🟡 M6. 导航结构缺失（L56-58 名词解释定义了 Bottom Navigation Bar 和 FAB，但全篇从未定义导航栏有几个 Tab、各是什么；9.2 还残留“侧边栏”入口 L702）**
底部导航是移动端信息架构的骨架，却没有规格；FAB 定义了名词但无处使用。
**建议：** 补一节“信息架构”：底部导航 Tab 清单（如 仪表盘/资产/交易/资金/设置）、每个 Tab 的层级、FAB 用在哪（如交易页“添加交易”）。

**🟡 M7. “大额资金操作两次金额确认”的“大额”阈值未定义（L811）**
**建议：** 给出默认阈值（如 ≥$5,000）并可配置。

**🟡 M8. “金额锁定：输入金额后自动禁用返回键”（L812）是反模式**
Android 规范禁止劫持系统返回键；禁用返回会让用户在录错时无法退出，反而更焦虑。**建议：** 改为“提交中防重复点击 + 退出时提示未保存草稿”（L879 已有草稿机制，正好衔接）。

### 3.3 安全设计问题（移动端特有）

**🔴 M9. PBKDF2 迭代次数过弱（L1028-1029：100,000 次）**
2025-2026 年 OWASP 建议 PBKDF2-HMAC-SHA256 ≥600,000 次；100,000 次对财务数据明显不足。移动端 CPU 较弱是现实，但可以用 Argon2id（更抗 GPU）或提高迭代次数 + Keystore 包裹的方案平衡。
**建议：** 密码派生改用 Argon2id（或 PBKDF2 ≥600k），数据密钥由 Keystore 包裹随机 DEK，密码只包裹 DEK 的 KEK。

**🔴 M10. 登录密码哈希“SHA-256 + salt”无迭代次数（L943、L1020），且被标成“加密”**
SHA-256 是快速哈希，不做 10 万次以上迭代等于裸奔；表格“加密”列把哈希当加密，概念错误。
**建议：** 密码验证哈希与数据 KEK 分开：验证用 Argon2id/bcrypt，派生用独立 KDF；修正表格措辞。

**🔴 M11. 备份文件结构疑似明文放密钥 + 校验和不防篡改（L1040-1046、L302）**
结构“[文件头][加密密钥 32 字节][数据块][校验和 8 字节]”——若 32 字节密钥明文存放，加密形同虚设（需明确是“被密码包裹的密钥”）；“校验和”只能查损坏不能防篡改，与故事 5.1“防篡改机制”的要求不匹配。
**建议：** 明确为 AES-256-GCM（自带认证加密），密钥用 KDF（含迭代参数、salt 写入文件头）派生，删除独立校验和或用 HMAC；文件头携带格式版本与 KDF 参数。

**🟡 M12. 密码错误 3 次禁用生物识别 30 秒，逻辑可疑（L693）**
密码连续错与生物识别安全性无关；正常设计是“生物识别失败 N 次后降级要求密码”。**建议：** 改为生物识别失败 5 次锁定生物识别、要求密码解锁；密码暴力防护另设（如指数退避）。

**🟡 M13. “卸载后残留数据无法被其他应用读取”表述（L304）**
Android 卸载会清除应用私有目录，此句应改为“卸载即删除全部数据，如需保留请先备份”，避免“残留数据”歧义。

**🟢 M14. “一键删除所有 API 密钥”（L836）好功能，但应要求密码二次确认。**
**🟢 M15. 日志同样缺脱敏要求（第 6 章日志小节），同桌面端 S3。**

### 3.4 使用逻辑问题

**🔴 M16. 分页大小三处矛盾（L75 每页 50 条 vs L884 每页不超过 20 条 vs L1086 每页 20 条）**
**建议：** 统一为每页 20 条（移动端合理值），全局说明与性能节同步。

**🔴 M17. 刷新机制三处矛盾（L254 价格刷新可设 1/5 分钟 vs L451 仪表盘每 5 分钟 vs L886 后台同步 ≥30 分钟）**
“1 分钟刷新”与“后台 ≥30 分钟”必须区分前台/后台语境；仪表盘硬编码 5 分钟与设置可调 1 分钟冲突。
**建议：** 明确两级策略：前台按用户设置（1/5/30 分钟）刷新行情；退到后台由 WorkManager 按 ≥30 分钟同步；仪表盘不再硬编码。

**🔴 M18. 系统版本自相矛盾（L80 支持 Android 10+ vs L885 内存 50MB 标注“Android Lollipop+”）**
Lollipop 是 Android 5.0，与最低支持版本冲突。**建议：** 统一 Android 10+（L885 改为“Android 10+”）。

**🟡 M19. 9.5 币种详情“弹出页面 + 关闭按钮”（L752-754）与故事 3.4“跳转到详情页”（L268）冲突**
移动端应为整页导航 + 返回键，弹窗只用于表单类。同桌面端 U3，移动端应更彻底地改。

**🟡 M20. 9.6“分三步输入”（L775-776）与 9.7 单一表单（L788-801）矛盾**
**建议：** 保留单表单 + 实时计算（9.7 已够好），删除分步输入的描述，或明确“三步”仅指键盘焦点流转。

**🟡 M21. 左滑删除交易记录写错章节（L744 在“9.4 资产列表页面”下，但交易记录不在资产列表）**
应移到交易管理页/币种详情页的交易记录列表；资产列表的滑动操作要单独定义（或无）。

**🟡 M22. 自动纠错“您输入的价格高于当前市价”（L772）对小币种/冷门交易对无价可查**
需定义“无行情时跳过此提示”。同桌面端“symbol 映射”问题。

**🟡 M23. 存储权限按旧模型描述（L84-88、L65 权限异常）**
Android 10+ 分区存储下，备份导出经 SAF（系统文件选择器）与私有目录操作都不需要 READ/WRITE_EXTERNAL_STORAGE；CSV 导入同样走 SAF。**建议：** 按 SAF 重写权限章节，删除“引导开启存储权限”的旧逻辑（或仅保留 Android 10 以下的兼容说明）。

**🟡 M24. CSV 导入在手机上的取文件路径未定义（L228-233 只说“上传 CSV 文件”）**
**建议：** 明确通过 SAF/文件管理器选择，支持从下载目录与云端文件（如 Google Drive 选择器）。

### 3.5 数据模型问题

**🔴 M25. 表格质量差：拼写错误与类型混搭**
- flow_tim 拼写错误（L981，应为 flow_time）；
- 类型混用：fee_currency 写 String（L968）、created_at 写 Timestamp（L975、L989）、source 带反引号 TEXT（L976）——SQLite 里这些都是 TEXT/INTEGER，照抄桌面端错误；
- 桌面端“主键类型不一致”问题在移动端反而解决了一部分（全用 INTEGER 主键，好），但与桌面端 UUID 体系分歧（见 M26）。
**建议：** 统一 SQLite 类型（TEXT/INTEGER/REAL），清理拼写与格式。

**🟡 M26. 与桌面端数据模型分歧，导致 .cpro 备份互导不可行**
- settings 表：桌面端 key-value（桌面端 L775-781），移动端改为固定列（L1006-1011）；
- transactions：桌面端 UUID，移动端 INTEGER；
- accounts：移动端多出 last_active（L947）；
- 两文档对 .cpro 结构定义不一致（移动端 L1040-1046 定义了带密钥块的结构，桌面端未定义）。
两个产品共享“WuZhuFolio”品牌与 .cpro 扩展名，备份文件能否互相导入没有一句话说明。
**建议：** 在移动端文档中明确“V1.0 与桌面端备份格式互不兼容（或兼容）”，并把 .cpro 格式规范抽为共享文档。

**🟡 M27. small_asset_threshold 默认 0.01 无单位（L1009）**
是 1% 还是 $0.01？桌面端同字段也无单位。**建议：** 明确为“占总资产百分比，默认 1%”。

**🟡 M28. “对 note 字段压缩存储”（L1083）对加密数据无效**
AES 密文不可压缩，压缩应发生在加密前，且 note 类短文本收益≈0。**建议：** 删除该条，或改为“大文本字段在加密前压缩”。

**🟡 M29. 迁移表预写未来版本 1.1/1.2/1.3（L1061-1066）与本文档 V1.0 状态矛盾**
可作为示例但应标注“示例，非承诺版本计划”。

**🟢 M30. 缺表同桌面端 D3**：无价格快照表（24h 盈亏需要）、无手续费费率规则表、无去重订单号字段、无生物识别/会话状态表。

### 3.6 成功指标问题

- **🟡 M31. WAU>30% / MAU>40%（L187-189 指标表）**：WAU/MAU=75% 对“查一下就走”的移动工具依然过高，建议 WAU 15-20% 或改口径。

- **🟡 M33. 满意度>80% 收集口径模糊（L194）**。
- **🟢 M34. 移动端建议补指标**：后台同步成功率、备份完成率、冷启动达标率（文档已给 2s 标准，应配套监控）。
