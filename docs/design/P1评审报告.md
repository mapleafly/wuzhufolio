## 四、问题清单（按严重度）

### 🔴 阻断（不满足 P1 DoD，放行前必须修复或人工明示豁免）

**F1 · 原型未覆盖登录链路 4 个页面**
- 现状：原型只含主壳（侧边栏五页+模态）；ia.md 2.1/2.2/2.3/2.18 的登录页、账户创建（含**风险确认勾选**）、初始化向导（四方式）、忘记密码页均无 HTML 原型。STATUS.md 验收描述也仅引导「侧边栏五页+模态」。
- 依据：AGENTS.md P1 DoD「**原型图输出为 HTML、覆盖全部核心页面**、可点击可交互」；PRD 流程图 1（新用户初始化）是第一条核心流程；故事 1.1 的风险确认勾选是 PRD 验收硬条款。
- 影响：P4 将以原型为 UI 视觉基准（AGENTS.md P1 衔接），登录链路无基准；「密码是数据唯一钥匙」的安全叙事是本产品信任建立的第一触点，恰是设计最需要打磨的页面。
- 建议：深化轮补齐 4 页（登录/创建含风险确认弹层/初始化向导/忘记密码），至少静态可点击；或人工明示「主壳优先、登录链路后补」并记入 direction-approved.md。

### 🟡 重要（建议随深化轮修复）

**F2 · 代理状态指示未落入设计**
- PRD 4.2 验收 3：「界面状态栏需有图标或文字，清晰地指示当前网络是通过代理连接的」；PRD 3.2 将「代理网络支持」列为 **P0 用户需求**。ia.md §1.1 状态栏元素清单（网络/同步图标、数据源、上次更新、备份提醒）与 interaction.md 全文均无「代理连接中」状态；原型状态栏亦无。
- 建议：ia.md 状态栏行补「代理指示（直连/代理）」；interaction.md 增加对应呈现（文案+图标）。

**F3 · 日志/诊断入口缺失**
- PRD 6「日志管理与可追溯性」：用户可访问的日志文件、方便导出日志（导出前提示检查敏感信息）、诊断报告（复用脱敏规则，内容受限清单）。ia.md 2.12 设置页清单与原型均无「日志/诊断」入口。
- 影响：P6 安全自查（日志脱敏核验）与用户排障路径失去落点。
- 建议：ia.md 设置页补「日志与诊断」分组（查看/导出日志、生成诊断报告），脱敏要求在交互细节中注明。

**F4 · 对比度未达 WCAG AA（token 层，P4 的直接源头）**
- 实测（V13）：浅色 `--ink3 #8A938C` 对底 **2.88:1**（用于表头 11px、hint、时间戳、图例百分比）；浅色 `--warn #A97B1E` 对底 **3.45:1**（用于「待定价/估算中」标记、校准 pill，10.5–11px）；深色 `--ink3 #66726B` **3.51:1**。均低于 4.5:1；ink3 甚至低于大字 3:1。
- design-tokens §2.4 仅验证了 ink/ink2，§6 却声明「文本对比度满足 WCAG AA」——声明范围与实际用法不符。gain 4.72 / loss 4.70 属压线通过（建议同步加深留余量）。
- 建议：修 token——加深 ink3（两主题各至 ≥4.5:1）或明文限定 ink3 仅用于非信息性装饰文本；warn 加深或放大加粗。**此项必须在 P4 取用 token 前完成。**

**F5 · 原型无障碍基线缺失（与自身文档承诺不符）**
- 实测（V14）：tabindex 属性 0 个、aria/role 属性 0 个、样式表无任何 `:focus` 规则；21 处 `div onclick`（侧边导航、开关、菜单、表格行）；Tab 键只能触到顶栏三个 button 后即跳回 body。interaction.md 3.9 与 design-tokens §6 承诺「全键盘导航+读屏兼容」。
- 影响：原型是 P4 的视觉基准，若开发照抄 DOM 模式（div+onclick），无障碍基线将带病进入实现。
- 建议：深化轮补 button 语义/role/tabindex/:focus-visible；或至少在 design-tokens 明示「原型仅为视觉基准，DOM 语义与焦点样式按 interaction.md 3.9 在 P4 实现」。

**F6 · 变体差异化不足，方向选择的信息基础不完整**
- 实测：两版 HTML diff 仅 4 行（data-theme、title、THEME 变量）——「变体」实为同一文件的主题切换；两套配色 token 真实存在且任一文件内均可切换（这点已验证）。
- 但 direction-approved.md §2 声称变体差异含「**等宽数字强化**」，实际两版字体栈完全相同，该差异不存在；design-tokens §1 所说「差异在配色/**字体气质**/密度节奏」中后两项未实现。
- 影响：人工「选方向」实际只是选默认主题；若选「混合（主版配色+变体等宽强化）」需在深化时真正实现差异化。
- 建议：人工选择时知悉此情并记录于 direction-approved.md；深化轮按所选方向落实真实差异。

### 🟢 轻微（记录在案，随深化收尾处理）

- **F7 字号口径矛盾**：design-tokens §3「正文 14px 底线」vs 原型正文/导航 13.5px、表格 12.5px、hint 11px。两者取一（建议改 tokens 为「正文 13–14px、表格 ≥12.5px」并注明原型现状）。
