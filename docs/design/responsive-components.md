# 桌面端响应式与组件体系统一方案（responsive-components.md）

> **背景**：P6 人工门第七轮（2026-09-15，真实桌面 GUI 全流程）暴露出**同一类问题在多个页面反复出现**——
> 窄窗/高 DPI 下表格列被压窄（换行、竖排、截断）、卡片大数字换行变形、弹窗多出一条「不到一行」的滚动条。
> 人工明确要求：「能否有总体的应对分辨率变化的方案，而不是小修小补？是否有合用的表格/卡片组件？」
> 本文即该总体方案：**断点 → 组件 → 页面**三层，一处定义、全站复用。
> **落地状态**：DEF-31…DEF-38 已按本方案实施（见 `docs/test/defects.md`）；变更分级建议 **C1**（新增组件与响应式规范，跨模块替换），待人工拍板。

---

## 1. 分辨率与断点（唯一来源）

桌面端窗口可自由缩放，且 **Windows 显示缩放（125%/150%/200%）会显著缩小「有效 dp 宽度」**
（例：2560×1600 @200% ≈ 1280×800 的可用空间，这正是人工在 4K 屏上仍看到窄窗症状的原因）。

- **断点按「内容区有效宽度 dp」判定**（内容区 = 窗口宽度 − 侧边栏 220dp），实现见
  `ui/theme/Breakpoints.kt`：`WzWindowClass.COMPACT < 1200dp ≤ MEDIUM < 1760dp ≤ WIDE`，
  由 `MainShell` 用 `ProvideWzWindowClass` 提供，页面经 `LocalWzWindowClass` 读取（**不允许各页面自行判断**）。

| 档位 | 有效宽度 | 典型场景 | 表格 | 卡片 | 弹窗 |
|------|----------|----------|------|------|------|
| **COMPACT** | < 1200dp | 1024×768；2560×1600 @200% | 列取最小宽 + **整表横向滚动** | 指标数字自动缩字号（下限 0.68×） | 内容上限 = 窗口高 × 0.66 |
| **MEDIUM** | 1200–1760dp | 1280×800、1920×1080 @100% | 按最小宽比例铺满，**无横向滚动** | 正常字号 | 同上 |
| **WIDE** | ≥ 1760dp | 2560×1600 @100% | 同上（留白更充裕） | 正常字号 | 同上 |

> 口径：**信息完整 > 留白美观**。宁可横向滚动，也不换行/截断财务数值；宁可自动缩小字号，也不让数字换行。

## 2. 表格：`ui/components/AdaptiveTable.kt`（统一表格组件）

| 规则 | 说明 |
|------|------|
| **列声明** | `TableColumn(minWidth, flex = minWidth.value)`：最小宽 + 弹性 |
| **列宽分配** | 可用宽 ≥ Σ最小宽 → **按最小宽比例分配**（等价于保证「每列 ≥ 其最小宽」）；否则整表横向滚动，列 = 最小宽 |
| **文本** | 一律 `SingleLineText`（单行 + 省略号 + **截断时悬停显示全值**）；**禁止换行**（换行会撑高行、破坏表格节奏） |
| **徽标** | `Badge` 单行；与主文本**内联**（同一行），不另起一行 |
| **单元线** | 横线：`AdaptiveTable(divider = true)`（默认开，行底 1px `line` 色）；**纵线**：`verticalDivider = true`（默认开，画在列边界、最后一列右边界不画，表头行亦画；DEF-40） |
| **操作列** | 作为一等列（`TableWidths.ACTIONS = 120dp`），保证按钮成对、文字不竖排 |
| **滚动条槽** | 页面给列表区**右侧预留 12dp**（`padding(end = 12.dp)`），纵向滚动条画在留白里——**不得压住最右列** |
| **横向滚动条** | 组件自动在表格底部呈现（仅滚动模式） |

已接入：资产列表、交易管理、资金管理。**新增数据表一律用该组件**，不得再用裸 `Row + weight`。

## 3. 卡片：`ui/components/WzCard.kt`

| 组件 | 用途 | 规则 |
|------|------|------|
| `WzCard` | 统一卡片容器 | surface 底 + 1px 边 + 10dp 圆角 + 16/14dp 内边距（`compact` 时 12/10dp） |
| `WzCardLabel` | 卡片标签 | 11sp、`ink2`、单行 |
| `WzMetric` | **关键指标数字** | **单行 + 自动缩字号**（1.0→0.9→0.82→0.74→0.68），仍放不下才省略号；**绝不换行**；字号取 `metricPrimary`（27sp，一级）/ `metricSecondary`（21sp，次级）——两级比值 ≈1.29（DEF-39，对齐原型） |
| `SingleLineText` | 列表/图例单行文本 | 单行 + 省略号 + 截断时悬停全值 |
| `rowDivider` | 列表单元线 | 1px `line` |

已接入：仪表盘/资产页统计卡（`StatCard` 内部改用 `WzCard` + `WzMetric`）、环形图图例（`SingleLineText`）、行情自选列表（单元线）。

## 4. 弹窗：尺寸与滚动策略

- **内容上限** = `modalContentMaxHeight()` = 窗口高 × 0.66（下限 320dp），替代原先写死的 420/470/380dp；
- **表单紧凑化**：字段间距 10→8dp、按钮区 16→12dp（交易/增资表单）；
- 目标：**1024×768 下打开交易/增资表单无需滚动即可看到「保存」**；窗口过小时才出现内部滚动（内容不被裁切）；
- 弹层仍遵守 `AGENTS.md §7.3`：同窗口就地叠加、由页面根承载（`PageOverlayHost`）、打开即聚焦首输入框。

## 5. 列表可读性（人工反馈 8）

- 表格类列表：由 `AdaptiveTable(divider = true)` 统一提供单元线；
- 非表格列表（行情自选、API 密钥、同步记录、币种详情成交）：行间插入 `rowDivider()`；
- 单元线用最低强调的 `line` 色，**不加重分隔**（保持 design-tokens §4.1「克制使用边框」）。

## 6. 防回归（自动化）

| 断言 | 用例 |
|------|------|
| 窄窗下徽标完整显示、数值单元格单行、行高稳定 | `PortfolioPagesUiTest::assets table keeps badges and numeric cells intact at narrow width` |
| 手续费单行；横向滚到最右后删除按钮**完整可见**且宽度达标 | `TransactionsPageUiTest::transactionTableKeepsFeeSingleLineAndActionsFullyVisible` |
| 交易弹窗在紧凑窗口无需滚动即可看到「保存」 | `TransactionsPageUiTest::transactionModalFitsWithoutScrolling` |
| 焦点/键盘/弹层契约不回归 | `ShellFocusFlowUiTest`、`SettingsPageUiTest`、`KeyboardA11yUiTest` |

> 说明：Compose UI 测试默认窗口即 1024×768（COMPACT 档），因此上述用例本身就是**窄窗回归**；
> 1280×800 / 2560×1600 与高 DPI 场景按 `docs/test/manual-test-guide.md §14` 人工复验。

## 7. 未纳入本次（登记 P8）

- **列优先级隐藏**：COMPACT 档下自动隐藏低优先级列（如交易所/已实现盈亏）而非横向滚动——属**交互口径变化**
  （信息默认不可见），需人工拍板后另立 Δ；当前口径为「全部列保留 + 横向滚动」。
- **表格排序/列宽拖拽/列显隐菜单**：数据表交互增强，登记 P8。
- **`LazyColumn` 化**：超长列表（>1 万行）的虚拟化替换（当前为 `Column + verticalScroll`），登记 P8 观察项。
- **字号体系随断点整体缩放**：目前只对**指标数字**做自动缩字号；正文/表格字号固定（避免小屏文字过小）。
