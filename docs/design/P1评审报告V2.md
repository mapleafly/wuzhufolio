## 七、附 · 暗色主题一致性专项验证（2026-08-31 追加，回应人工提问）

**问题**：只深化主版、变体归档后，暗色主题是否会与主版不一致？

**实测结论（Playwright，将 light.html 切至 data-theme=dark 后逐组件读取 computed style）**：

1. **结构性自适应：通过**。深化新增的全部组件均以 CSS 变量取色，暗色下自动套用暗色 token：CG Key Modal 背景 #1D2421（暗 surface）、边框 #2E3733（暗 line）、标题文字 #E8EAE6（暗 ink）；交易对候选下拉（pair-sug）、手续费自定义币种下拉、资金币种单选下拉同样全部为暗色 token。结论：**「暗色主题」作为主版文件内置主题，会自动跟随后续一切深化，不存在功能性漂移**。
2. **发现一处真实不一致（记 N5，预存在、本轮坐实）**：环形图扇区配色为 JS 渲染时按当时主题挑选（light/dark 两套 palette 数组），**切换主题后不重渲染**--切至暗色后扇区仍为浅色板颜色（#1F5A48 系），不会切换为黄铜板（#D0A85C 系）。实测：toggle 主题后 path fill 不变；仅当在暗色状态下重新 renderPage() 才会使用暗色板。修复约一行代码（主题切换时重渲染，或改为 CSS 变量驱动配色），建议并入 F1 深化轮。
3. **dark.html 文件已冻结在深化前状态**：无 Key 配置弹窗、币种仍为文本框、无交易对补全--交互与功能基准已失效，仅剩配色参考价值（与 STATUS 验收口径「归档仅作配色参考」一致）。

**建议（供人工终审一并拍板）**：确立「**单一真源 + 双主题**」原则--以 wuzhufolio-light.html 为唯一原型真源，暗色主题为其内置主题随深化自动维护；dark.html 在放行前标注「已归档 · 请勿作为基准引用」或直接删除；F4 对比度修正须**两套主题分别验证**（暗色 ink3 3.51:1 同样不达标）。
